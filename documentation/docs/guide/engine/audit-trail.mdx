# Audit Trail

OIBus records an audit log entry every time a configuration entity is created, updated, or deleted, so you
can see who changed what, and when.

## What Gets Audited {#what-gets-audited}

Each audit log entry records:

| Field                | Description                                                                                                            |
| -------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| **Entity type / ID** | The kind of entity that changed, and its identifier.                                                                   |
| **Action**           | `Create`, `Update`, or `Delete`.                                                                                       |
| **User**             | The user who performed the change.                                                                                     |
| **Date**             | When the change was recorded.                                                                                          |
| **Before / After**   | A JSON snapshot of the entity before and after the change — before is empty for `Create`, after is empty for `Delete`. |

The following entity types are audited: South connector, South item, South item group, North connector,
North transformer, History query, History query item, History query transformer, Scan mode, IP filter,
Certificate, User, Transformer, and OIAnalytics registration.

Engine settings are audited per section, matching what is edited on the Engine page: **general settings**,
**web server**, **proxy server**, and **logging and audit**. Each entry only contains the settings of its section,
and saving a section without any change does not record anything.

Secrets (passwords, tokens, private keys…) are never recorded in the audit trail. When a secret is modified — or
set on creation — its value is replaced by `<changed>` in the **After** snapshot, so you can still see that it
changed.

## Viewing the Audit Trail {#viewing-the-audit-trail}

### The Audit Page {#the-audit-page}

Open the account menu (top right) and select **Audit** to see every audit log entry across the whole
OIBus instance. Filter by **Entity type**, **Action**, and a **Start**/**End** date range (the last week by
default), then click the 🔍 icon on any row to open its full history.

The **Entity** column shows the entity name. When the entity still exists, the name links to the page where it
can be found: the connector or history query page for connectors, history queries and their items, groups,
configuration workflows and transformers; the Engine page for scan modes, IP filters, certificates, transformers
and engine settings. Deleted entities are greyed out and show their last known name.

The **User** column shows the name of the user who performed the change, or **OIAnalytics** when the change was
pushed from OIAnalytics.

### From an Entity's Own List {#from-an-entitys-own-list}

Most configuration list pages — South, North, History Queries, Scan modes, IP filters, Certificates, and
Transformers — also have an audit icon on each row, opening that entity's own history directly without
going through the global Audit page. The South, North and History query pages also have an audit icon next to
their edit button, as well as on each row of their item and transformer lists. On the Engine page, each settings
section has its own audit icon next to its edit button.

## Reading a History Entry {#reading-a-history-entry}

The history view lists every change recorded for the entity, most recent first. Expand a row to see what
changed, in one of three modes (switch between them with the dropdown at the top):

| Mode                    | Description                                                                                 |
| ----------------------- | ------------------------------------------------------------------------------------------- |
| **JSON diff** (default) | A unified diff of the two JSON snapshots.                                                   |
| **Table**               | One row per field, with its value **Before** and **After**. Changed fields are highlighted. |
| **JSON side by side**   | The two JSON snapshots shown side by side.                                                  |

## Retention {#retention}

Audit log entries are kept for a configurable number of days before being automatically pruned — see
**Audit log retention** under [Logging Parameters](./engine-settings.mdx#logging-parameters).
