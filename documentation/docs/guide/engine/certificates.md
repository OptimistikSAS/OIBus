# Certificates

OIBus keeps a certificate store (**Engine > Certificates**) used to authenticate OIBus against external systems. One such scenario is
utilizing a designated certificate for establishing [OIAnalytics](../north-connectors/oianalytics.md) connections via **Azure Active
Directory with certificates**.

A certificate entry can either be **generated by OIBus** (self-signed) or **imported** from an external Certificate Authority.

## Generating a self-signed certificate

Use the **+** button and fill in the subject fields (common name, country, state/province, locality, organization), the key size and the
number of days before expiry. OIBus generates an RSA key pair, signs the certificate itself and stores the private key encrypted.

The displayed expiry is the certificate's actual `notAfter` date.

## Importing a certificate signed by your own CA

Use the **upload** button to import an existing certificate instead of generating one. You must supply:

- **Certificate file** (required) — the leaf certificate, PEM (`.pem`, `.crt`, `.cer`) or DER (`.der`, `.cer`) encoded.
- **Private key file** (required) — the matching private key, PKCS#1 (`-----BEGIN RSA PRIVATE KEY-----`) or PKCS#8
  (`-----BEGIN PRIVATE KEY-----`), PEM or DER encoded. Encrypted keys are accepted — supply the passphrase in the
  **Private key passphrase** field.
- **CA chain file** (optional) — the intermediate and root CA certificates. Because a DER file can only hold a single certificate, a
  multi-certificate chain must be supplied as a concatenated PEM bundle.

OIBus verifies that the private key matches the certificate's public key and rejects the import otherwise. The expiry is read from the
certificate itself. Only RSA keys are supported.

The CA chain is stored as provided; OIBus does not verify that it actually chains up to the leaf certificate.

:::info
PKCS#12 / `.pfx` bundles are not supported. Extract the certificate and key first:

```bash
openssl pkcs12 -in bundle.pfx -clcerts -nokeys -out certificate.pem
openssl pkcs12 -in bundle.pfx -nocerts -nodes -out private-key.pem
```
:::

## Downloading a certificate

The **download** button on a certificate row opens a dialog offering:

- **Format** — **PEM** (`.pem`) or **DER** (`.cer`). DER is what OPC UA servers such as Kepware expect, so it can be handed over directly
  without an `openssl` conversion round-trip.
- **Include the CA chain** — appends the stored chain to the exported file. Only available with PEM, since a DER file holds exactly one
  certificate.
- **Include the private key** — see below.

## Downloading the private key

The private key can be downloaded only in encrypted form. Tick **Include the private key** and enter a passphrase (at least 8 characters,
repeated for confirmation). OIBus produces a PKCS#8 encrypted PEM file (`-----BEGIN ENCRYPTED PRIVATE KEY-----`, PBES2 with
PBKDF2-HMAC-SHA256 and AES-256-CBC), downloaded alongside the certificate as a separate file.

The passphrase is never stored by OIBus — if you lose it the downloaded file is unusable. Every private key export is recorded in the OIBus
logs together with the user who requested it.

You can inspect or convert the downloaded key with:

```bash
openssl pkcs8 -in private-key.pem -passin pass:yourpassphrase -noout
```
