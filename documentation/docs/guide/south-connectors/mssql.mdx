# Microsoft SQL Server™

Connect to and query Microsoft SQL Server™ (MSSQL) databases with OIBus.

This connector is commonly used to extract process and historian data from industrial platforms that store their data in SQL Server, such as **AVEVA™ Historian** (formerly Wonderware® InSQL) or **Inductive Automation Ignition®**.

:::info Compatibility Notes

- Supports SQL Server 2012 and later
- Requires TCP/IP protocol to be enabled on SQL Server

:::

## Specific Settings {#specific-settings}

| Setting                  | Description                                                                                             | Example Value    |
| ------------------------ | ------------------------------------------------------------------------------------------------------- | ---------------- |
| Host                     | IP address or hostname of the SQL Server instance.                                                      | `192.168.1.10`   |
| Port                     | SQL Server port number. Default: `1433`.                                                                | `1433`           |
| Connection timeout       | Maximum time in milliseconds to establish connection. Default: `5000`.                                  | `5000`           |
| Database                 | Name of the database to connect to.                                                                     | `production`     |
| Use encryption           | Enable data encryption between OIBus and the database.                                                  | Enabled/Disabled |
| Trust server certificate | Accept self-signed or expired certificates. Use with caution.                                           | Enabled/Disabled |
| Username                 | Authentication username.                                                                                | `sa`             |
| Password                 | Authentication password.                                                                                | `••••••••`       |
| Domain                   | Active Directory domain for domain authentication (optional).                                           | `CORP`           |
| Idle connection timeout  | Time in milliseconds an unused connection of the pool stays open before being closed. Default: `30000`. | `30000`          |
| Max parallel queries     | Maximum number of items or groups queried at the same time, from `1` (sequential) to `8`. Default: `1`. | `2`              |

:::note Parallel queries
OIBus keeps a pool of up to this number of connections to the database, opened when the queries need them and closed after the idle connection timeout: each one adds to the load of the source. Keep the value below the number of connections the SQL Server login can use.
:::

### Security Best Practices {#security-best-practices}

- **User Permissions**: Always use a read-only database user
- **Certificate Validation**: Only trust server certificates in development/test environments
- **Encryption**: Enable for sensitive data, untrusted networks, or compliance requirements

### Performance Considerations {#performance-considerations}

**Query Optimization**:

- Use indexed columns in WHERE clauses
- Limit result sets (avoid `SELECT *`)
- Prefer parameterized queries

**Resource Management**:

- Encryption adds CPU overhead
- Increase timeouts for long-running queries
- Implement pagination for large result sets
- Reuse connections where possible

## Exploring Tables {#exploring-tables}

Click **Explore** to browse the database's tables (with their column count and, where the database gives it, an
approximate row count) and the columns of each table, with their type and, where available, nullability, primary key
and default value. Check tables or columns and click
**Add in an item** to start an item whose query reads the checked columns (several tables are joined), tracked on a
date/time column picked automatically — see [SQL Tables in an Item](./common-settings.md#sql-tables-as-items) — or
**Metadata sync** to push the records of a table to OIAnalytics.

An [items synchronisation](./common-settings.md#items-synchronisation) on this connector runs a metadata query and
pushes its rows to OIAnalytics; it never creates items.

:::note MSSQL item request timeout
Each MSSQL item has its own **Request timeout** field (milliseconds), setting the maximum execution time for that
item's query. **Connection timeout** only bounds how long OIBus waits to establish a connection, and the queries run
outside an item (connection test, explore, discovery) time out after 15 seconds.
:::

:::note MSSQL datetime field types
The following **Type** values are available for the tracking instant's datetime field in Microsoft SQL Server:

| Type            | Description                                            |
| --------------- | ------------------------------------------------------ |
| String          | String representation parsed with a custom format      |
| Date            | SQL `DATE` column (date only, no time)                 |
| DateTime        | SQL `DATETIME` column                                  |
| DateTime2       | SQL `DATETIME2` column (higher precision)              |
| DateTime Offset | SQL `DATETIMEOFFSET` column (includes timezone offset) |
| Small DateTime  | SQL `SMALLDATETIME` column (minute precision)          |
| ISO String      | ISO 8601 string (e.g. `2024-01-15T10:30:00.000Z`)      |
| UNIX epoch (s)  | Unix timestamp in seconds                              |
| UNIX epoch (ms) | Unix timestamp in milliseconds                         |

:::
