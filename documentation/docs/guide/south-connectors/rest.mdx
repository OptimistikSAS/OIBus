# REST

Query data from any HTTP/HTTPS REST API using configurable methods, query parameters, headers, and request bodies.

## Connection Settings

### Main Configuration

| Setting                             | Description                                                                 | Example Value            |
| ----------------------------------- | --------------------------------------------------------------------------- | ------------------------ |
| **Host**                            | Base URL of the REST API server. Must start with `http://` or `https://`.   | `http://server.com:8080` |
| **Accept unauthorized certificate** | Allow HTTPS connections with self-signed or invalid certificates.           | Enabled/Disabled         |
| **Timeout**                         | Duration in seconds before a connection failure is reported. Default: `30`. | `30`                     |

### Authentication

| Setting               | Description                                                       | Example Value                             |
| --------------------- | ----------------------------------------------------------------- | ----------------------------------------- |
| Authentication method | Authentication type for the connection.                           | `None`, `Basic`, `Bearer`, `API Key`      |
| Username              | Username for Basic authentication.                                | `api_user`                                |
| Password              | Password for Basic authentication.                                | `••••••••`                                |
| Token                 | Bearer token sent in the `Authorization` header.                  | `eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...` |
| API Key               | Name of the header or query parameter for API Key authentication. | `X-Api-Key`                               |
| API Value             | Secret value sent with the request (stored encrypted).            | `••••••••`                                |
| Add to                | Where the API key/value pair is injected.                         | `header`, `query-params`                  |

### Proxy Configuration

| Setting            | Description                                      | Example Value                   |
| ------------------ | ------------------------------------------------ | ------------------------------- |
| **Use proxy**      | Route requests through a proxy server.           | Enabled/Disabled                |
| **Proxy URL**      | Full URL of the proxy server.                    | `http://proxy.example.com:8080` |
| **Proxy username** | Username for proxy authentication (if required). | `proxy_user`                    |
| **Proxy password** | Password for proxy authentication (if required). | `••••••••`                      |

### Connection Test

OIBus can test the connection to the server before any item query is executed. This is useful to verify credentials and reachability.

| Setting           | Description                                                          | Example Value |
| ----------------- | -------------------------------------------------------------------- | ------------- |
| **Method**        | HTTP method used for the test request. Default: `GET`.               | `GET`         |
| **Test Endpoint** | Path appended to the host. Default: `/`.                             | `/health`     |
| **Body**          | Optional JSON body for `POST` or `PUT` test requests.                | `{}`          |
| **Success code**  | HTTP status code indicating a successful connection. Default: `200`. | `200`         |

:::info
The test body is only sent when the method is `POST` or `PUT`.
:::

## Group Settings

Items can be organised into groups. Each group defines a shared collection schedule and default throttling
settings. Items in the same group are still fetched **one at a time** in sequence — the group simply
provides common defaults that individual items can override.

| Setting        | Description                                                                                                                                       | Example Value             |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------- |
| **Name**       | Unique label for the group within this connector.                                                                                                 | `Group A`                 |
| **Scan mode**  | Schedule used to collect all items in the group.                                                                                                  | `Every 1 min`             |
| **Throttling** | Default throttling values (Max read interval, Read delay, Start time offset, End time offset, Recovery strategy) inherited by items in the group. | `3600, 200, 0, 0, oldest` |

## Item Settings

Each item targets a specific API endpoint and defines how to request and interpret the response. Items
inherit their scan mode and throttling defaults from their group, but each setting can be overridden per
item by disabling **Sync with group**.

### Request Configuration

| Setting         | Description                                                                  | Example Value  |
| --------------- | ---------------------------------------------------------------------------- | -------------- |
| **Method**      | HTTP method for the data request. Default: `GET`.                            | `GET`          |
| **Endpoint**    | Path appended to the host.                                                   | `/api/data`    |
| **Return type** | How the response is processed — as a structured body or a raw file download. | `body`, `file` |

### Query Parameters

Add key/value pairs appended to the request URL as query string parameters. Use the `@StartTime` / `@EndTime`
or `@PeriodStart` / `@PeriodEnd` variables (see [Time Variables](#time-variables)) to inject a time window
directly into a parameter value.

| Setting            | Description                                                                                                 | Example Value |
| ------------------ | ------------------------------------------------------------------------------------------------------------ | -------------- |
| **Key**            | Name of the query parameter.                                                                                 | `from`         |
| **Value**          | Value of the parameter; may contain `@StartTime`, `@EndTime`, `@PeriodStart`, or `@PeriodEnd` placeholders. | `@PeriodStart` |
| **Date format**    | Shown when the value contains any of the time variables — configures how the instant is formatted.         | `iso-string`   |
| **Sliding window** | Shown when the value contains `@PeriodStart` or `@PeriodEnd` — the window size used to compute them.       | `1 hr`         |

#### Date/Time Format for Query Parameters

When a parameter value includes `@StartTime`, `@EndTime`, `@PeriodStart`, or `@PeriodEnd`, a date format
configuration section appears:

| Setting      | Description                                       | Example Value                                         |
| ------------ | ------------------------------------------------- | ----------------------------------------------------- |
| **Type**     | Representation of the datetime value.             | `iso-string`, `unix-epoch`, `unix-epoch-ms`, `string` |
| **Timezone** | Timezone for formatting (only for `string` type). | `UTC`, `Europe/Paris`                                 |
| **Format**   | Custom format pattern (only for `string` type).   | `yyyy-MM-dd HH:mm:ss`                                 |

#### Sliding Window for Query Parameters

When a parameter value includes `@PeriodStart` or `@PeriodEnd`, a sliding window configuration section appears:

| Setting  | Description               | Example Value                 |
| -------- | -------------------------- | ------------------------------ |
| **Size** | Numeric size of the window. | `1`                            |
| **Unit** | Unit for the size value.   | `ms`, `s`, `min`, `hr`, `day`  |

### Headers

Add custom HTTP headers to the request. Like query parameters, header values support the same time variables
and, when using `@PeriodStart` / `@PeriodEnd`, the same sliding window configuration.

| Setting   | Description                                                                                        | Example Value     |
| --------- | --------------------------------------------------------------------------------------------------- | ----------------- |
| **Key**   | Header name.                                                                                        | `X-Custom-Header` |
| **Value** | Header value; may contain `@StartTime`, `@EndTime`, `@PeriodStart`, or `@PeriodEnd` placeholders.   | `Bearer my_token` |

:::info Content-Type
When a body is configured and no `Content-Type` header is explicitly defined, OIBus automatically adds
`Content-Type: application/json`.
:::

### Request Body

A JSON body can be sent for `POST`, `PUT`, `PATCH`, and `DELETE` requests. The body supports the same
`@StartTime` / `@EndTime` and `@PeriodStart` / `@PeriodEnd` placeholders to inject a time window into the payload.

| Setting            | Description                                                                                                  | Example Value              |
| ------------------- | ------------------------------------------------------------------------------------------------------------ | --------------------------- |
| **Content**         | JSON body of the request; may contain `@StartTime`, `@EndTime`, `@PeriodStart`, or `@PeriodEnd` placeholders. | `{"from": "@PeriodStart"}` |
| **Date format**     | Shown when the body contains any of the time variables — configures how the instant is formatted.           | `iso-string`                |
| **Sliding window**  | Shown when the body contains `@PeriodStart` or `@PeriodEnd` — the window size used to compute them.         | `1 hr`                      |

The date/time format and sliding window configuration for the body follow the same settings as
[query parameters](#datetime-format-for-query-parameters).

### Response Handling

The `Return type` setting controls how OIBus interprets the server's response.

| Setting     | Description                                                                                                                                                                                            | Example Value  |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------- |
| Return type | `body`: response is read as text; OIBus auto-detects JSON or XML from the `Content-Type` header. `file`: response body is saved as a binary file using the `Content-Disposition` filename if provided. | `body`, `file` |

:::info Filename in file mode
When the server does not provide a `Content-Disposition` header, the file is saved with an auto-generated name
based on the connector name, item name, and a random identifier.
:::

### Tracking the Maximum Instant

When the return type is `body` and the response is JSON, OIBus can automatically track the most recent timestamp
found in the response. This advances the `@StartTime` of the next query to avoid re-fetching already seen data.

| Setting           | Description                                                                                 | Example Value         |
| ----------------- | ------------------------------------------------------------------------------------------- | --------------------- |
| **Track instant** | Enable extraction of the maximum timestamp from the JSON response.                          | Enabled/Disabled      |
| **JSONPath**      | Expression used to locate timestamp values inside the JSON response.                        | `$.data[*].timestamp` |
| **Date format**   | How OIBus should interpret the extracted timestamp values (type, timezone, format, locale). | `iso-string`          |

#### Tracking Instant Date/Time Format

| Setting      | Description                                                 | Example Value                                         |
| ------------ | ----------------------------------------------------------- | ----------------------------------------------------- |
| **Type**     | Representation of the datetime in the JSON field.           | `iso-string`, `unix-epoch`, `unix-epoch-ms`, `string` |
| **Timezone** | Timezone for parsing (only for `string` type).              | `UTC`, `Europe/Paris`                                 |
| **Format**   | Custom format pattern for parsing (only for `string` type). | `yyyy-MM-dd HH:mm:ss`                                 |
| **Locale**   | Locale for month/day name parsing (only for `string` type). | `en-En`                                               |

:::info JSONPath
OIBus uses the [JSONPath Plus](https://github.com/JSONPath-Plus/JSONPath) library. When multiple values match the
JSONPath expression, the maximum timestamp among all of them is used as the new `@StartTime`.
:::

## Time Variables

The following variables can be used in query parameter values, header values, and request bodies. They fall
into two independent modes — use whichever matches the target API, they are not meant to be combined.

### Query Interval (`@StartTime` / `@EndTime`)

| Setting      | Description                                                                               | Example Value              |
| ------------ | ----------------------------------------------------------------------------------------- | -------------------------- |
| `@StartTime` | Start of the current query interval. Updated to the tracked max instant after each query. | `2024-01-15T10:00:00.000Z` |
| `@EndTime`   | End of the current query interval (capped to the current time or the sub-interval end).   | `2024-01-15T11:00:00.000Z` |

`@StartTime` picks up where the previous query left off — either the last tracked max instant (see
[Tracking the Maximum Instant](#tracking-the-maximum-instant)) or the last completed query time. This is
the right choice for APIs that support arbitrary historical ranges, since OIBus can catch up on a backlog
after downtime by re-querying the missed intervals.

:::info Query Splitting
When a large time range is requested, OIBus splits it into smaller sub-intervals based on the **Max read interval**
throttling setting. Each sub-interval gets its own `@StartTime` / `@EndTime` pair.
:::

### Sliding Window (`@PeriodStart` / `@PeriodEnd`)

| Setting        | Description                                                                        | Example Value              |
| -------------- | ----------------------------------------------------------------------------------- | -------------------------- |
| `@PeriodStart` | Start of the sliding window: the current time minus the configured window size.    | `2024-01-15T10:00:00.000Z` |
| `@PeriodEnd`   | End of the sliding window: the current time when the request is sent.              | `2024-01-15T11:00:00.000Z` |

Unlike `@StartTime` / `@EndTime`, `@PeriodStart` / `@PeriodEnd` are always computed from the current time,
regardless of when the previous query ran. This suits APIs that only expose a rolling window of recent data
(e.g. "give me the last 5 minutes"), rather than arbitrary historical ranges.

The window size is configured per field, next to the placeholder that uses it — see **Sliding window** in
[Query Parameters](#query-parameters), [Headers](#headers), or [Request Body](#request-body).

:::warning No backfill
Because `@PeriodStart` / `@PeriodEnd` always anchor to "now", this mode does not catch up on missed data.
If OIBus is stopped or the connection is unavailable for longer than the window size, the gap is lost — the
next successful query only covers the current window. Use `@StartTime` / `@EndTime` instead if backfilling
after downtime matters for this item.
:::
