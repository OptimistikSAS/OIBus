# OSIsoft PI System™

Read the recorded values of a PI Data Archive.

OIBus talks to PI through a small Windows helper process that ships with OIBus. When a connection opens, the helper
loads the **AF SDK** of the PI AF Client installed on the OIBus machine. OIBus does not include any AVEVA software, so
the connector works once that machine has been prepared as described below.

## Prerequisites {#prerequisites}

Whatever the setup, the OIBus machine needs:

- **Windows x64**. The connector is not available on Linux or macOS.
- **.NET Framework 4.8**. It is part of Windows 10 (1903 and later), Windows 11 and Windows Server 2022 and later.
  Install it on Windows Server 2016 and 2019.
- A **PI System Access (PSA) licence**. AVEVA requires one for any non-AVEVA program that reads PI data, OIBus
  included.

The other requirements depend on where OIBus runs: on the PI Data Archive server itself (**local access**), or on
another machine (**remote access**). OIBus always connects with the Windows account that runs its service, through
Windows integrated security, so there is no username or password field.

| Requirement                                          | Local access (OIBus on the PI server)                                                                                                                                                                                                                         | Remote access (OIBus on another machine)                                                                                                                                                                                             |
| ---------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| [Install PI AF Client](#install-pi-af-client)        | Usually already there: the PI Server setup installs it. Check that **PI System Explorer** is present.                                                                                                                                                         | Install it on the OIBus machine. Having it on the PI server is not enough.                                                                                                                                                           |
| [Register the PI Data Archive](#known-servers-table) | The local server is normally already in the known servers table and set as the default. You can leave the **PI Data Archive** setting empty.                                                                                                                  | Add the remote PI Data Archive by its name. The OIBus machine must be able to resolve that name (DNS or `hosts` file).                                                                                                               |
| Network access (TCP 5450)                            | Nothing to open.                                                                                                                                                                                                                                              | Open TCP port **5450** from the OIBus machine to the PI Data Archive, in every firewall between them, including the Windows firewall on the PI server.                                                                               |
| [Service account](#user-configuration)               | **Local System** works and is seen as `NT AUTHORITY\SYSTEM`. A dedicated local or domain account is still better, so that it can be given read-only rights.                                                                                                   | The account must be known to the PI server: a domain account, the machine account `DOMAIN\MACHINE$` when the service runs as Local System, or a local user with the same name and password on both machines when there is no domain. |
| [PI access (mapping or trust)](#pi-access)           | Map the service account (or `NT AUTHORITY\SYSTEM`) to a read-only PI identity. Default PI installs often map `BUILTIN\Administrators` to `piadmins`, which also matches Local System. This gives OIBus admin rights, so prefer an explicit read-only mapping. | Map the remote account (as above) to a read-only PI identity. A trust, if used, must match the IP address of the OIBus machine.                                                                                                      |

## Setting Up the OIBus Machine {#pi-af-client-configuration}

### 1. Install PI AF Client {#install-pi-af-client}

Install PI AF Client from the AVEVA customer portal. It places the AF SDK (`OSIsoft.AFSDK`) in the Global Assembly
Cache, where OIBus finds it. If it is not in the Global Assembly Cache, OIBus looks in
`%PIHOME%\AF\PublicAssemblies\4.0`.

### 2. Register the PI Data Archive {#known-servers-table}

Add the PI Data Archive to the known servers table of PI AF Client. For example, in PI System Explorer go to
**File** → **Connections** → **Add Data Archive**. If the connector's **PI Data Archive** setting will be left empty,
make this server the default one.

The connector's **PI Data Archive** setting must match the name shown in this table.

### 3. Choose the OIBus Service Account {#user-configuration}

The installer creates the OIBus Windows service under the **Local System** account, and the PI Data Archive sees
whichever account runs the service. Pick one of these options:

- **Keep Local System.** The OIBus machine then connects with its computer account (`DOMAIN\MACHINE$`), so the PI
  mapping must target that account. This works only when both machines are in the same domain.
- **Use a dedicated domain account (recommended).** Create a domain user such as `DOMAIN\svc-oibus`. Open
  **services.msc**, open the OIBus service, go to the **Log On** tab, choose **This account** and enter the user. Then
  restart the service. The account needs full control of the OIBus data folder.
- **No domain.** Create a local user with the same name and password on both machines, and run the OIBus service with
  it.

### 4. Grant Access on the PI Data Archive {#pi-access}

On the PI Data Archive, give the service account a PI identity that has read access to the points. A **mapping** is the
recommended way to do this. A **trust** is a legacy mechanism and should only be used when a mapping is not possible.

#### Mapping (recommended) {#mapping-configuration}

1. Open **PI System Management Tools** and connect to the PI Data Archive.
2. Go to **Security** → **Mappings & Trusts**, **Mappings** tab.
3. Create a mapping:
   - **Windows Account**: the OIBus service account (or `DOMAIN\MACHINE$` for Local System)
   - **PI Identity**: an identity that has read access to the points and their data, for example `PIWorld` or a
     dedicated one

![PI add mapping](@site/static/img/guide/south/osisoft-pi/3-add-mapping.png)

![PI list mapping](@site/static/img/guide/south/osisoft-pi/4-mapping-list.png)

#### Trust (legacy) {#trust-configuration}

1. In **PI System Management Tools**, go to **Security** → **Mappings & Trusts**, **Trusts** tab.
2. Create a trust that matches the OIBus machine: its IP address and net mask, and its domain or account if applicable.
3. Select the **PI Identity** to connect with.

![PI add trust](@site/static/img/guide/south/osisoft-pi/1-add-trust.png)

![PI list trust](@site/static/img/guide/south/osisoft-pi/2-trust-list.png)

### 5. Test the Connection {#test-connection}

Create the connector in OIBus and click **Test connection**. A successful test shows the server name and version, which
confirms that the AF SDK loads and that the account can sign in. Then test an item to check that the account can read
its points. See [Troubleshooting](#troubleshooting) when a test fails.

## Connection Settings {#connection-settings}

| Setting         | Description                                                                                                                       | Example Value |
| --------------- | --------------------------------------------------------------------------------------------------------------------------------- | ------------- |
| PI Data Archive | Name of the PI Data Archive in the [known servers table](#known-servers-table). Empty: the default PI Data Archive of that table. | `MYPISERVER`  |
| Retry interval  | Time in milliseconds to wait before retrying the connection. Default: `10000`.                                                    | `10000`       |

:::note Connection
OIBus connects when the connector starts, and retries every **Retry interval** until it succeeds. If the connection to
the PI Data Archive is lost, the read in progress fails and the next read connects again.
:::

## Group Settings {#group-settings}

Items are organised into **groups**. Each group has its own schedule and the default throttling parameters for
reading historical data.

| Setting       | Description                                             | Example Value |
| ------------- | ------------------------------------------------------- | ------------- |
| **Name**      | Unique label for the group within this connector.       | `Group A`     |
| **Scan mode** | Collection schedule applied to every item in the group. | `Every 1 min` |

<ThrottlingSettings />

:::tip Overriding throttling per item
To override the group throttling defaults for one item, turn off the **Sync with group** toggle in the item edit form.
:::

## Item Settings {#item-configuration}

| Setting      | Description                                                                                                                                                                                                                                                                                                          | Example Value                    |
| ------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------- |
| Type         | `PI point` reads one point by name. `PI query` reads every point matched by a query.                                                                                                                                                                                                                                 | `PI point`                       |
| PI point     | Exact point name, without the server name. Not case-sensitive. Used when Type is `PI point`.                                                                                                                                                                                                                         | `SINUSOID`                       |
| PI query     | Query that selects several points (see [PI Point Query Syntax](https://docs.aveva.com/bundle/af-sdk/page/html/pipoint-query-syntax-overview.htm)). A query with no attribute name, such as `sinus*`, searches the point names. Default: `*` (all points).                                                            | `tag:=SINUS* AND pointsource:=R` |
| Value filter | Optional condition in [performance equation syntax](https://docs.aveva.com/bundle/af-sdk/page/html/M_OSIsoft_AF_PI_PIPoint_RecordedValues.htm). The PI Data Archive evaluates it and sends only the values that pass, which saves transfer. The condition can name the point it filters. Empty: every value is sent. | `'SINUSOID' > 50`                |

:::caution PI query `*`
The default query `*` reads every point of the PI Data Archive. Narrow it before enabling the item.
:::

:::note How items are read

- `PI point` items of a group are read in bulk: one call per distinct value filter, or a single call if none of them
  has a filter.
- Each `PI query` item gets its own call, and its value filter applies to every point the query matches.
- If a point is not found or a query fails, OIBus logs a warning and still reads the other items.

:::

## Collected Values {#values}

OIBus reads the recorded (archived, compressed) values between the start and the end of each interval, both included.
The next interval starts just after the last value read.

Each record contains:

- `pointId`: the item name for a `PI point` item, or the PI point name for each point matched by a `PI query` item
- `timestamp`: an ISO 8601 UTC string
- `value`: a number for numeric points, the state name for digital states (system states included, such as
  `I/O Timeout`), or a string otherwise

## Troubleshooting {#troubleshooting}

| Symptom                                       | What to check                                                                                                                                                                     |
| --------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| The AF SDK cannot be loaded                   | Check that PI AF Client is installed on the OIBus machine (not only on the PI server), and that .NET Framework 4.8 is present.                                                    |
| Server not found                              | Check that the **PI Data Archive** setting matches a name in the known servers table, or that a default server is set there when the setting is empty.                            |
| Connection refused or timeout                 | Check that TCP port 5450 is open between the OIBus machine and the PI Data Archive (firewall).                                                                                    |
| Access denied, or no mapping or trust matches | Check which account runs the OIBus service, and that a mapping targets exactly that account (`DOMAIN\MACHINE$` for Local System). Restart the service after changing its account. |
| Point not found                               | Check the point name, and that the PI identity is allowed to read it (point security and data security).                                                                          |

To see why a connection was rejected, look at the PI Data Archive messages in **PI System Management Tools** →
**Operation** → **Message Logs**.
