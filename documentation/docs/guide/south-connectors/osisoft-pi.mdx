# OSIsoft PI System™

Read the recorded values of a PI Data Archive. OIBus talks to it through the PI AF Client installed on the OIBus
machine, with a small Windows helper process shipped with it: no OIBus Agent is needed.

:::caution System Requirements

- OIBus **must** run on Windows x64 to use this connector.
- **PI AF Client** **must** be installed on the OIBus machine. It installs the AF SDK that OIBus loads, and holds the
  known servers table: the PI Data Archives OIBus can connect to, and the default one. OIBus does not ship any AVEVA
  software: install PI AF Client from AVEVA, under your own agreement with AVEVA.
- The Windows account running OIBus **must** have read access on the PI Data Archive, through a
  [mapping or a trust](#pi-af-client-configuration).
- AVEVA requires a **PI System Access (PSA)** licence for any non-AVEVA program that reads PI data, OIBus included.

:::

## Connection Settings {#connection-settings}

| Setting         | Description                                                                                                               | Example Value |
| --------------- | ------------------------------------------------------------------------------------------------------------------------- | ------------- |
| PI Data Archive | Name of the PI Data Archive in the known servers table of PI AF Client. Empty: the default PI Data Archive of that table. | `MYPISERVER`  |
| Retry interval  | Time in milliseconds to wait before retrying the connection. Default: `10000`.                                            | `10000`       |

:::note Connection
OIBus connects when the connector starts, and retries every **Retry interval** until it succeeds. When the connection
to the PI Data Archive is lost, the running read fails and the next one connects again.
:::

## Group Settings {#group-settings}

Items are organised into **groups**. Each group defines a shared schedule and the default throttling
parameters for historical data retrieval.

| Setting       | Description                                             | Example Value |
| ------------- | ------------------------------------------------------- | ------------- |
| **Name**      | Unique label for the group within this connector.       | `Group A`     |
| **Scan mode** | Collection schedule applied to every item in the group. | `Every 1 min` |

<ThrottlingSettings />

:::tip Overriding throttling per item
Each item can override the group throttling defaults by disabling the **Sync with group** toggle in the item
edit form.
:::

## Item Configuration {#item-configuration}

### Point Access Methods {#point-access-methods}

| Setting  | Description                                                                                                                                                                                                                                            | Example Value                    |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------- |
| Type     | Access method: `PI point` (single point by name) or `PI query` (multiple points by query expression)                                                                                                                                                   | `PI point` or `PI query`         |
| PI point | Exact point name (without server name, not case-sensitive). Used when Type is `PI point`.                                                                                                                                                              | `SINUSOID`                       |
| PI query | Query selecting several points (see [PI Point Query Syntax](https://docs.aveva.com/bundle/af-sdk/page/html/pipoint-query-syntax-overview.htm)). A query without attribute name, such as `sinus*`, searches the point names. Default: `*` (all points). | `tag:=SINUS* AND pointsource:=R` |

:::info Reference Names

- For `PI point`: Item name serves as reference in JSON payloads
- For `PI query`: PI name is used as reference
  :::

:::info Values
OIBus reads the recorded values between the start and the end of each interval, both included. Each record has the
point (`pointId`), the timestamp (ISO 8601 UTC string) and the value: a number for numeric points, the state name for
digital states (system states included, such as `I/O Timeout`), a string otherwise. The next interval starts just after
the last value read. A point not found or a query that fails is logged as a warning, and the other items are still read.
:::

## PI AF Client Configuration {#pi-af-client-configuration}

### Known Servers Table {#known-servers-table}

Add the PI Data Archive to the known servers table of PI AF Client on the OIBus machine (for instance with PI System
Explorer, **File** → **Connections**), and set it as the default server if the connector's **PI Data Archive** setting
is left empty.

### User Configuration {#user-configuration}

OIBus connects with the Windows account running it (its service account), never with a login prompt:

1. Create a domain user account (accessible from both machines)

- If domain doesn't exist, create identical local users with same password

2. Run the OIBus service with this user

### Trust Configuration {#trust-configuration}

1. Open PI System Management Tools
2. Navigate to `Mapping & Trusts` → `Trusts` tab
3. Create new trust with:

- OIBus machine IP and Net Mask
- Domain (if applicable)
- PI Identity to connect with

### Mapping Configuration {#mapping-configuration}

1. In PI System Management Tools
2. Navigate to `Mapping & Trusts` → `Mappings` tab
3. Create new mapping with:

- OIBus service user
- PI Identity from trust configuration

:::tip Log Access
View system logs in PI System Management Tools:
`Operation` → `Messages Logs`
:::
