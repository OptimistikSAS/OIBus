# OIBus 安全

## 凭据存储 {#credential-storage}

### 登录密码 {#login-passwords}

用户密码在存储到 `oibus.db` 之前会使用 **Argon2** 进行哈希处理。明文密码
永远不会被持久化——只会存储哈希值。Argon2 是一种内存密集型哈希函数，旨在抵御暴力破解
和 GPU 加速攻击。

### 连接器机密信息 {#connector-secrets}

在南向和北向连接器中配置的密码、令牌和 API 密钥在静态存储时会使用
**AES-256-CBC** 进行加密：

- 在 OIBus 初始化期间，使用密码学安全的随机数生成器生成一个 256 位密钥
  和一个 128 位初始化向量（IV）。
- 密钥和 IV 以 base64 字符串的形式存储在 **`crypto.db`** 中——这是一个与
  主配置数据库分离的独立 SQLite 数据库。
- 加密后的机密信息存储在 **`oibus.db`** 中，只有在两个数据库都
  存在的情况下才能解密。

:::danger 保护 crypto.db
如果 `crypto.db` 被删除或丢失，OIBus 将无法再解密任何连接器机密信息。所有机密信息都必须
在重启 OIBus 后重新输入。请以对待私钥文件同等的谨慎程度对待 `crypto.db`。
:::

### 数据库布局 {#database-layout}

OIBus 使用五个 SQLite 数据库：

| 数据库         | 内容                                                                                                                   |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------- |
| **`oibus.db`**   | 所有配置：连接器、条目、扫描模式、IP 过滤器、用户（哈希后的密码）、加密后的机密信息。                 |
| **`crypto.db`**  | 用于加密/解密连接器机密信息的 AES-256-CBC 密钥和 IV。                                                          |
| **`logs.db`**    | 运行时日志条目，存储在 `logs/` 子文件夹下。                                                                   |
| **`metrics.db`** | 南向/北向/历史查询的运行时指标，在每次扫描和每次北向发送时更新，存储在 `logs/` 子文件夹下。 |
| **`cache.db`**   | 南向连接器缓存（等待传输到北向连接器的数值），存储在 `cache/` 子文件夹下。              |

要获得一份完整的、可恢复的快照，必须同时备份 `oibus.db` 和 `crypto.db`。

## Web 界面身份验证 {#web-interface-authentication}

OIBus Web 界面支持两种身份验证方式：

### JWT（主要方式） {#jwt-primary}

登录成功后，OIBus 会签发一个**使用 RS256（RSA-SHA256）签名的 JWT**。该令牌：

- 默认**有效期为 7 天**，可在引擎设置中配置为 1 小时到 30 天之间。
- 使用 OIBus 持有的 RSA 私钥签名。
- 在每次 API 请求中使用对应的公钥进行验证。
- 包含用户的登录名及其密码的哈希值——如果
  密码发生变更，该令牌会自动失效。

### 基本身份验证（API / CLI） {#basic-auth-api--cli}

除公共状态端点（`/api/status`、`/api/engine/status`）之外，所有 API 端点都接受 HTTP 基本身份验证，前者
无需任何身份验证。它被基于 curl 的自动化脚本使用
（参见[自动化安装](../installation/disk-image.mdx)）以及不支持 JWT 的工具使用。

:::tip
对于脚本化访问，建议使用专用的 API 方式，并始终在 OIBus 主机本身上
（`localhost`）运行脚本，以避免凭据以未加密的方式通过网络传输。
:::

## IP 过滤 {#ip-filtering}

OIBus 在 HTTP 请求级别强制执行基于 IP 的访问控制。来自未列出地址的请求
在尝试任何身份验证之前就会收到 HTTP 401 响应。

主要行为：

| 行为               | 详情                                                                                                        |
| ----------------------- | ------------------------------------------------------------------------------------------------------------- |
| **本地主机绕过**    | `127.0.0.1`、`::1` 以及其他回环地址始终被允许，无论过滤列表如何设置。           |
| **通配符**            | 条目 `*` 允许所有远程地址。                                                                  |
| **IPv4 / IPv6**         | 两种格式均受支持。IPv4 映射的 IPv6 地址（如 `::ffff:192.168.1.1`）会被透明处理。 |
| **模式匹配**    | 条目支持将 `*` 作为通配符（内部会编译为正则表达式），从而支持类似子网的规则。 |
| **用于测试的禁用方式** | 向 `oibus-launcher` 传递 `--ignore-ip-filters`，即可在不修改配置的情况下绕过所有 IP 检查。   |

配置详情请参见 [IP 过滤器](../engine/ip-filters.mdx)。

## OIAnalytics 机密信息交换 {#oianalytics-secret-exchange}

当通过 OIAnalytics 输入或更新机密信息时，它们会**在浏览器中**被加密后再
传输，使用的是 OIBus 的 RSA 公钥（RSA-OAEP，4096 位）。这意味着：

- OIAnalytics 永远不会看到或存储明文机密信息。
- 只有持有匹配私钥的 OIBus 才能对其进行解密。
- 当 OIBus 将其配置发送给 OIAnalytics 时，所有机密信息字段都会在
  传输之前被剥离。

RSA 密钥对在 OIAnalytics 注册期间生成，可以通过
**重新生成加密密钥**远程命令进行轮换。轮换后，任何先前通过
OIAnalytics 输入的机密信息都必须重新输入，因为旧的密文将无法再被解密。

此外，OIBus 在启动时会生成自己的 4096 位 RSA 证书/密钥对（`private.pem` /
`public.pem` / `cert.pem`）——正是它对上文所述的 JWT 进行签名，也用于自签名
用于 OPC UA 连接所出示的证书。这与用于
OIAnalytics 机密信息交换的密钥对是不同的一对密钥。

## 网络安全 {#network-security}

OIBus 原生**不**支持 HTTPS。Web 界面运行在普通 HTTP 上（默认端口 2223）。

对于需要远程访问界面的生产环境：

1. 将 OIBus 部署在终止 TLS 的**反向代理**（nginx、Apache、Caddy）之后。
2. 配置代理将请求转发到 `http://localhost:2223`。
3. 使用 [IP 过滤器](../engine/ip-filters.mdx)防止从主机外部直接访问 2223 端口。
4. 对于外部访问，优先使用 **VPN**，而不是将反向代理暴露到公共互联网。

## 数据源访问 {#data-source-access}

对 OIBus 连接的每个系统都应用最小权限原则：

- 为 OIBus 创建**专用账户**——不要复用与其他工具共享的服务账户。
- 对仅查询数据的南向连接器授予**只读权限**。
- 将该账户限制在其所需的特定数据库、标签或主题范围内——不要授予更宽泛的权限。
- 在协议支持的情况下，优先使用**基于密钥或令牌的身份验证**，而不是密码。
- 定期轮换凭据，并在 OIBus 连接器设置中进行更新。

## 软件完整性 {#software-integrity}

- **开源**：完整源代码在
  [GitHub](https://github.com/OptimistikSAS/OIBus) 上公开可用。所有提交在合并前都会经过团队审查。
- **官方构建**：发布的二进制文件由 GitHub Actions 从已打标签的源代码构建而成。构建
  流水线可通过代码仓库的 Actions 工作流进行审计。
- **依赖监控**：[Dependabot](https://github.com/OptimistikSAS/OIBus/security/dependabot)
  持续扫描依赖项中的已知漏洞，并针对更新开启拉取请求。
- **自定义编译**：开源许可证和公开的代码库允许你从源代码编译
  OIBus，并在部署到敏感环境之前独立审计它。
- **软件物料清单**：每个稳定版本都会附带一份 CycloneDX SBOM（`oibus-sbom.json`），
  列出所有组件及其版本，可用于漏洞扫描或许可证合规
  检查。详情参见[软件物料清单](./oibus-sbom.md)。
