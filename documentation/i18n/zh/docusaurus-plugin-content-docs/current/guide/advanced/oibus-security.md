# OIBus 安全

## 凭据存储 {#credential-storage}

### 登录密码 {#login-passwords}

用户密码在存储到 `oibus.db` 之前会使用 **Argon2id**（64 MiB 内存、3 次迭代、4 个通道、16 字节随机盐）进行哈希处理。明文密码
永远不会被持久化——只会存储哈希值。Argon2 是一种内存密集型哈希函数，旨在抵御暴力破解
和 GPU 加速攻击。当较新版本的 OIBus 使用更强的参数对密码进行哈希时，用户下次登录时会使用新参数重新哈希其密码。

### 密码策略 {#password-policy}

根据 [NIST SP 800-63B](https://pages.nist.gov/800-63-4/sp800-63b.html)，密码长度必须为 **8 到 128 个字符**，字符类型不限。
OIBus 不强制任何组合规则（大写字母、数字、特殊字符等）：较长的密码短语既更容易记住，也更难被猜到。

修改密码需要提供执行修改的用户的当前密码：修改自己的密码时是其本人的密码，通过 API 修改其他用户的密码时同样是其本人的密码。

### 默认账户 {#default-account}

OIBus 首次启动时会创建一个密码为 **pass** 的 **admin** 账户，除非安装时设置了其他凭据（安装脚本的 `-u` 和 `-p` 选项，
或 `ADMIN_USERNAME` 和 `ADMIN_PASSWORD` 环境变量）。launcher 的 `--reset-password` 选项也会将 **admin** 账户的密码恢复为该默认密码。

只要账户仍使用默认密码，OIBus 就只允许其修改密码：Web 界面会在登录后立即打开密码修改窗口，API 会以 HTTP 403 响应拒绝其他任何请求。
升级 OIBus 时仍使用默认密码的账户同样适用此规则。

### 连接器机密信息 {#connector-secrets}

在南向和北向连接器中配置的密码、令牌和 API 密钥——以及 OIAnalytics 注册的令牌和密钥、
转发代理和 Loki 的密码，以及证书的私钥——在静态存储时会使用 **AES-256-GCM** 进行加密：

- 在 OIBus 初始化期间，使用密码学安全的随机数生成器生成一个 256 位密钥，并以 base64
  字符串的形式存储在 **`crypto.db`** 中——这是一个与主配置数据库分离的独立 SQLite 数据库。
  加密密钥通过 HKDF-SHA256 从该密钥派生。
- 每个机密信息都使用其自身的 96 位随机 nonce 进行加密，因此两个相同的机密信息永远不会
  得到相同的加密值；每个加密值还带有认证标签，因此被篡改的值会被拒绝，而不会被解密。
- 加密后的机密信息存储在 **`oibus.db`** 中，只有在两个数据库都
  存在的情况下才能解密。

:::danger 保护 crypto.db
如果 `crypto.db` 被删除或丢失，OIBus 将无法再解密任何连接器机密信息。所有机密信息都必须
在重启 OIBus 后重新输入。请以对待私钥文件同等的谨慎程度对待 `crypto.db`。
:::

### 数据库布局 {#database-layout}

OIBus 使用五个 SQLite 数据库：

| 数据库           | 内容                                                                                        |
| ---------------- | ------------------------------------------------------------------------------------------- |
| **`oibus.db`**   | 所有配置：连接器、项目、扫描模式、IP 过滤器、用户（哈希后的密码）、加密后的机密信息。       |
| **`crypto.db`**  | 用于派生加密/解密机密信息的 AES-256-GCM 密钥的密钥。                                        |
| **`logs.db`**    | 运行时日志条目，存储在 `logs/` 子文件夹下。                                                 |
| **`metrics.db`** | 南向/北向/历史查询的运行时指标，在每次扫描和每次北向发送时更新，存储在 `logs/` 子文件夹下。 |
| **`cache.db`**   | 南向连接器缓存（等待传输到北向连接器的数值），存储在 `cache/` 子文件夹下。                  |

要获得一份完整的、可恢复的快照，必须同时备份 `oibus.db` 和 `crypto.db`。

### 文件权限 {#file-permissions}

数据文件夹包含配置（密码哈希、加密后的机密信息）、机密信息的密钥以及 OIBus 的私钥。其访问权限在创建时被限制为
运行 OIBus 的账户，之后由管理员负责，管理员可以修改这些权限（例如允许备份代理读取）：

- 安装程序创建新的数据文件夹时，仅允许该账户访问：在 Linux 上为模式 `700`；在 Windows 上为一个访问控制列表，
  仅授予 OIBus 服务（`SYSTEM`）和管理员完全控制权限，并移除从父文件夹继承的权限。已存在的数据文件夹保持不变。
- 在 Linux 和 macOS 上，OIBus 创建的 `oibus.db` 和 `crypto.db` 仅允许其用户访问（模式 `600`）。升级到 OIBus 4.0 时，
  会对之前创建的这些文件执行一次同样的限制。

在 Windows 上，可在管理员命令提示符中以同样的方式限制已存在的数据文件夹：

```bat
icacls "C:\OIBusData" /inheritance:r /grant:r "*S-1-5-18:(OI)(CI)F" "*S-1-5-32-544:(OI)(CI)F"
```

此后，以交互方式运行 OIBus（`go.bat`）需要使用管理员命令提示符。

## Web 界面身份验证 {#web-interface-authentication}

OIBus Web 界面支持两种身份验证方式：

### JWT（主要方式） {#jwt-primary}

登录成功后，OIBus 会签发一个**使用 HS256（HMAC-SHA256）签名的 JWT**。该令牌：

- 默认**有效期为 7 天**，可在引擎设置中配置为 1 小时到 30 天之间。
- 使用 OIBus 生成并存储在 `crypto.db` 中的 256 位随机密钥签名，该密钥不作他用。
- 在每次 API 请求中使用同一密钥进行验证：以其他方式或其他算法签名的令牌会被拒绝。
- 包含用户的登录名及其密码哈希的指纹（绝不包含哈希本身）——如果
  密码发生变更，该令牌会自动失效。

### 基本身份验证（API / CLI） {#basic-auth-api--cli}

除公共状态端点（`/api/status`、`/api/engine/status`）之外，所有 API 端点都接受 HTTP 基本身份验证，前者
无需任何身份验证。它被基于 curl 的自动化脚本使用
（参见[自动化安装](../installation/disk-image.mdx)）以及不支持 JWT 的工具使用。

:::tip
对于脚本化访问，建议使用专用的 API 方式，并始终在 OIBus 主机本身上
（`localhost`）运行脚本，以避免凭据以未加密的方式通过网络传输。
:::

### 身份验证失败限制 {#failed-authentication-limits}

验证密码会刻意消耗时间和内存，因此 OIBus 会限制通过登录页面或基本身份验证进行的失败身份验证：

- 一个 IP 地址在 **15 分钟内最多失败 10 次**；
- 一个登录名在 **15 分钟内最多失败 100 次**（来自任意地址）。

超出限制后，该地址或登录名的身份验证会被以 HTTP 429 响应（带有 `Retry-After` 头）拒绝，且不会验证密码，直到距其首次失败已过去 15 分钟。
成功的身份验证不计入：使用正确凭据的 API 客户端永远不会被限速，除非其地址或登录名已被阻止。对登录名设置更高的限制，
可以阻止分散在多个地址上的猜测攻击，同时不会让少数几个地址就能锁定某个账户。
主机自身的地址（回环地址）仅按登录名限制，因为运行在主机上的反向代理的所有客户端都来自这些地址。

无论登录名是否存在，失败的身份验证耗时相同、响应也相同：不会泄露哪些登录名存在。

## IP 过滤 {#ip-filtering}

OIBus 在 HTTP 请求级别强制执行基于 IP 的访问控制。来自未列出地址的请求
在尝试任何身份验证之前就会收到 HTTP 401 响应。

主要行为：

| 行为                   | 详情                                                                                       |
| ---------------------- | ------------------------------------------------------------------------------------------ |
| **本地主机绕过**       | `127.0.0.1`、`::1` 以及其他回环地址始终被允许，无论过滤列表如何设置。                      |
| **通配符**             | 条目 `*` 允许所有远程地址。                                                                |
| **IPv4 / IPv6**        | 两种格式均受支持。IPv4 映射的 IPv6 地址（如 `::ffff:192.168.1.1`）会被透明处理。           |
| **模式匹配**           | 条目支持将 `*` 作为通配符（内部会编译为正则表达式），从而支持类似子网的规则。              |
| **用于测试的禁用方式** | 向 `oibus-launcher` 传递 `--ignore-ip-filters`，即可在不修改配置的情况下绕过所有 IP 检查。 |

配置详情请参见 [IP 过滤器](../engine/ip-filters.mdx)。

## OIAnalytics 机密信息交换 {#oianalytics-secret-exchange}

当通过 OIAnalytics 输入或更新机密信息时，它们会**在浏览器中**被加密后再
传输，使用的是 OIBus 的 RSA 公钥（RSA-OAEP，4096 位）。这意味着：

- OIAnalytics 永远不会看到或存储明文机密信息。
- 只有持有匹配私钥的 OIBus 才能对其进行解密。
- 当 OIBus 将其配置发送给 OIAnalytics 时，所有机密信息字段都会在
  传输之前被剥离。

RSA 密钥对在 OIAnalytics 注册期间生成，OIBus 每 90 天会随其令牌一起自行更换该密钥对
（参见[身份验证令牌](../installation/oianalytics.mdx#authentication-tokens)）。
OIBus 会保留之前的私钥，以便仍能解密在更换前不久通过 OIAnalytics 输入的机密信息。

OIBus 向 OPC UA® 服务器出示的证书，在每个 OPC UA 连接器中从[证书存储](../engine/certificates.md)中选择，
其私钥与其他机密信息一样经过加密（参见[通信证书](../south-connectors/opcua.mdx#communication-certificate)）。
它与用于 OIAnalytics 机密信息交换的密钥对不同，也与签名 JWT 的密钥不同。

## 网络安全 {#network-security}

新安装的 OIBus 通过 [HTTPS](../engine/engine-settings.mdx#https) 提供 Web 界面（默认端口 2223），并使用其在首次启动时生成的自签名证书。
请将其替换为由浏览器信任的 CA 签发的证书，以避免浏览器警告；对于从 4.0 之前版本升级、仍通过 HTTP 提供服务的 OIBus，在启用 HTTPS 之前，请勿让其可通过网络访问。

对于需要远程访问界面的生产环境：

1. 使用 [IP 过滤器](../engine/ip-filters.mdx)限制可访问 2223 端口的来源。
2. 如果改为在**反向代理**（nginx、Apache、Caddy）中终止 TLS，请将其请求转发到 OIBus，并防止从主机外部直接访问 2223 端口。
3. 对于外部访问，优先使用 **VPN**，而不是将 OIBus 或反向代理暴露到公共互联网。

## 服务器身份 {#server-identity}

在发送任何凭据之前，OPC UA®（**安全模式**为 `Sign` 或 `Sign and encrypt`）和 SFTP 的南向与北向连接器，以及使用它们的
历史查询，会检查所连接服务器的身份：OPC UA 服务器的证书、SFTP 服务器的主机密钥。连接器只会连接到提供其所信任身份
（以 SHA-256 指纹标识）的服务器。这样可以防止其他机器冒充该服务器来获取凭据或数据。

- **信任身份**：测试连接，或保存、启动尚未信任其服务器身份的连接器时，会显示其服务器提供的身份：指纹，以及证书的
  主题、颁发者、有效期和名称。在信任之前，请将该指纹与服务器显示的指纹（其证书，或在 SFTP 服务器上运行
  `ssh-keygen -l -f <主机密钥文件>` 的输出）进行比对。在身份被信任之前，连接测试会在此检查后停止，不会向服务器发送
  任何凭据。
- **不信任即保存**：连接器可以在不信任其服务器身份的情况下保存或启动：此时它会等待其服务器被信任。从其他连接器或历史查询
  复制而来的连接器或历史查询不会信任原对象所信任的身份：请信任其自身服务器的身份。
- **被拒绝的身份**：当服务器提供连接器不信任的身份，或与已信任身份不同的身份（其证书或主机密钥已更新，或有其他服务器
  冒充它）时，连接器会拒绝连接并停止重试。连接器或历史查询的页面会显示所提供的身份：**查看并信任**会信任该身份并
  重启连接器。
- **TLS 连接器**：REST、OIAnalytics 和 MQTT 连接器、启用 SSL 的 PostgreSQL 连接器，以及 OIBus 在 OIAnalytics 的注册，
  使用**标准**验证（公共证书颁发机构）或根据[证书存储](../engine/certificates.md#importing-a-trusted-certificate)中的**受信任的证书**（证书颁发机构，或服务器本身的证书）
  验证其服务器的证书。信任服务器提供的身份会将其证书添加到存储并选中。OIAnalytics 的身份在注册页面中审核和信任。
- **可追溯性**：连接器页面会显示谁在何时信任了其服务器的身份。信任身份的操作会被记录在日志中，且在
  [导出和导入](../engine/config-export-import.mdx)配置时会保留已信任的身份。
- **OIAnalytics**：OIAnalytics 测试连接时会显示服务器的身份，且只有在拥有
  [**数据流**和**连接数据源**权限](../installation/oianalytics.mdx#command-permissions)时才能信任该身份。

## 数据源访问 {#data-source-access}

对 OIBus 连接的每个系统都应用最小权限原则：

- 为 OIBus 创建**专用账户**——不要复用与其他工具共享的服务账户。
- 对仅查询数据的南向连接器授予**只读权限**。
- 将该账户限制在其所需的特定数据库、标签或主题范围内——不要授予更宽泛的权限。
- 在协议支持的情况下，优先使用**基于密钥或令牌的身份验证**，而不是密码。
- 定期轮换凭据，并在 OIBus 连接器设置中进行更新。

## 软件完整性 {#software-integrity}

- **开源**：完整源代码在
  [GitHub](https://github.com/OptimistikSAS/OIBus) 上公开可用。所有提交在合并前都会经过团队审查。
- **官方构建**：发布的二进制文件由 GitHub Actions 从已打标签的源代码构建而成。构建
  流水线可通过代码仓库的 Actions 工作流进行审计。
- **依赖监控**：[Dependabot](https://github.com/OptimistikSAS/OIBus/security/dependabot)
  持续扫描依赖项中的已知漏洞，并针对更新开启拉取请求。
- **自定义编译**：开源许可证和公开的代码库允许你从源代码编译
  OIBus，并在部署到敏感环境之前独立审计它。
- **软件物料清单**：每个稳定版本都会附带一份 CycloneDX SBOM（`oibus-sbom.json`），
  列出所有组件及其版本，可用于漏洞扫描或许可证合规
  检查。详情参见[软件物料清单](./oibus-sbom.md)。
