# REST API

**REST API North 连接器**使 OIBus 能够**将数据发送到任意 HTTP REST 端点**，非常适合与接受 JSON 负载
或文件上传的自定义 API、webhook 及云服务集成。

OIBus 可以传输：

- **时间值负载**：序列化为 JSON 请求体，或通过 FormData 发送的 JSON 文件。
- **文件**：原样转发（压缩或未压缩）via FormData。

**示例用例**：

- **自定义 API 集成**：将 OIBus 数据直接推送到内部或第三方 REST API。
- **Webhook 传递**：通过事件驱动的 HTTP 调用触发外部系统。
- **云端数据摄取**：将数据转发到暴露 HTTP 摄取端点的云平台。

## 特定设置 {#specific-settings}

### 连接配置 {#connection-configuration}

| 设置                             | 说明                                                                                  | 示例值             |
| ----------------------------------- | -------------------------------------------------------------------------------------------- | ------------------------- |
| **主机**                            | REST API 服务器的基础 URL。必须以 `http://` 或 `https://` 开头。                    | `https://api.example.com` |
| **接受未经授权的证书** | 接受自签名或其他不受信任的 TLS 证书。                                                  | 启用/禁用          |
| **方法**                          | 发送数据时使用的 HTTP 方法。                                                          | `POST`、`PUT`、`PATCH`    |
| **端点**                        | 附加到主机后面以构成完整请求 URL 的路径。                                                      | `/api/data`               |
| **请求超时**                 | 等待响应的最长时间（秒），超过此时间则认为请求失败。    | `30`                      |
| **负载发送方式**                 | 负载的发送方式：作为原始**请求体（Body）**，或作为**文件（FormData）**多部分附件。 | `Body`                    |
| **预期成功状态码**           | 表示传输成功的 HTTP 状态码。                                                   | `200`                     |

:::tip 负载发送方式

- **Body（请求体）**：负载（JSON 或文件内容）直接作为请求体发送。OIBus 会根据文件扩展名
  （`.json`、`.xml`、`.txt`、`.csv`）自动设置 `Content-Type` 请求头。
- **File (FormData)（文件）**：负载作为文件附加到 `multipart/form-data` 请求中。当 API 要求
  文件上传而非原始请求体时使用此方式。
  :::

### 身份验证 {#authentication}

| 设置          | 说明                                                                                                                                    | 示例值                                                  |
| ---------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------- |
| **类型**         | 身份验证方式。                                                                                                                         | `None`、`Basic (username/password)`、`Bearer token`、`API key` |
| **用户名**     | 用户名。Basic 身份验证时必填。                                                                                                   | `api_user`                                                     |
| **密码**     | 用于 Basic 身份验证的密码（编辑时留空以保留现有密码）。                                              | `••••••••`                                                     |
| **Bearer token** | 通过 `Authorization: Bearer` 请求头发送的令牌，用于 Bearer token 身份验证（编辑时留空以保留现有令牌）。 | `••••••••`                                                     |
| **API key**      | API 密钥参数的名称。API key 身份验证时必填。                                                                            | `X-API-Key`                                                    |
| **API value**    | API 密钥的值，用于 API key 身份验证（编辑时留空以保留现有值）。                                  | `••••••••`                                                     |
| **添加位置**       | API 密钥的附加位置：`Header`（请求头）或 `Query parameters`（查询参数）。API key 时必填。                                                                             | `Header`                                                       |

### 代理配置 {#proxy-configuration}

如果您的网络基础设施要求请求通过代理服务器才能到达目标 REST API，请启用**使用代理**选项并在下方配置代理详情。

| 设置            | 说明                                      | 示例值                   |
| ------------------ | ------------------------------------------------ | -------------------------------- |
| **使用代理**      | 通过代理服务器路由请求。           | 启用/禁用                |
| **代理 URL**      | 代理服务器的 URL。                         | `http://proxy.example.com:8080` |
| **代理用户名** | 代理身份验证用户名（如有需要）。 | `proxy_user`                    |
| **代理密码** | 代理身份验证密码（如有需要）。 | `••••••••`                      |

### 查询参数 {#query-parameters}

添加附加到每个请求 URL 上的静态查询参数。每个条目都有一个**键（Key）**和一个**值（Value）**。

| 字段     | 说明            | 示例值 |
| --------- | ---------------------- | ------------- |
| **Key**   | 查询参数名称。  | `source`      |
| **Value** | 查询参数值。 | `oibus`       |

### 请求头 {#headers}

添加随每个请求发送的自定义 HTTP 请求头。每个条目都有一个键名和一个值。

| 字段                    | 说明        | 示例值     |
| ------------------------ | ------------------ | ----------------- |
| **HTTP header key name** | HTTP 请求头名称。  | `X-Custom-Header` |
| **HTTP header value**    | HTTP 请求头值。 | `my-value`        |

:::info 身份验证请求头
**请求头**部分设置的请求头会与身份验证配置生成的请求头合并。如果同一个请求头名称在两处都有定义，
身份验证请求头（例如 `Authorization`）将优先生效。
:::

## 连接测试 {#connection-test}

使用**连接测试**部分在 OIBus 开始发送真实数据之前验证连通性。

| 设置                   | 说明                                                                          | 示例值 |
| ------------------------- | ------------------------------------------------------------------------------------ | ------------- |
| **方法**                | 测试请求使用的 HTTP 方法。                                                               | `GET`         |
| **测试端点**         | 测试请求使用的路径（附加到已配置的**主机**后面）。                | `/health`     |
| **请求体**                  | 随测试请求发送的 JSON 请求体。仅当方法为 `POST` 或 `PUT` 时可用。 | `{}`          |
| **预期成功状态码** | 表示测试响应成功的 HTTP 状态码。                          | `200`         |

测试使用与实际配置相同的主机、身份验证和代理设置。它**不会**复用已配置的查询参数或请求头——
这些设置仅在发送实际数据时使用。
