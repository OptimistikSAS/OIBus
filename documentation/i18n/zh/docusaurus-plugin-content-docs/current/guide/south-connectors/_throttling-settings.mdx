### 限流设置 {#throttling-settings}

限流控制着 OIBus 如何调节历史数据请求的节奏。这些设置出现在每个**分组**（对于支持分组的连接器）
或每个**项目**（对于单项目连接器）上。分组中的项目可以通过禁用**与分组同步**开关来覆盖分组的默认值。

| 设置               | 描述                                                                                                                                                                                                                                                                                                                                                                                          | 示例值           |
| --------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------- |
| **最大读取间隔** | 每个子查询的最大持续时间（秒）。较大的时间范围会自动拆分为不超过该值的多个分块。                                                                                                                                                                                                                                                                      | `3600`                  |
| **读取延迟**        | 连续子查询之间的暂停时间（毫秒）。有助于防止服务器过载并管理速率限制。                                                                                                                                                                                                                                                                        | `1000`                  |
| **开始时间偏移** | 添加到查询窗口起始时间（`@StartTime`）上的毫秒数。**负值**会使起始时间提前，从而捕获上一区间中迟到的数据——这是旧的“Overlap”行为。**正值**则相反，会使起始时间推迟，从而跳过窗口开头的那部分时间。                                                                                               | `-60000`                |
| **结束时间偏移**   | 添加到查询窗口结束时间（`@EndTime`）上的毫秒数。**负值**会使结束时间提前——适用于最新数据尚不可靠的最终一致性数据源。**正值**会使窗口向后延伸。如果计算后的结束时间不晚于有效的起始时间，则本次运行会跳过该查询。                                    | `0`                     |
| **恢复策略** | OIBus 处理未查询子区间积压任务时所采用的顺序——例如在停止一段时间后重新启动，或首次针对较大时间范围运行时。`From oldest to newest`（默认）按时间顺序处理积压任务。`From newest to oldest` 会优先查询最近的子区间，使最新数据能够立即可用，而较早的空缺则在之后回填。 | `From oldest to newest` |

#### 限流的工作原理 {#how-throttling-works}

1. **区间拆分** —— 一个 24 小时的范围在 `Max read interval = 3600`（1 小时）的设置下，会被拆分为
   24 个独立的 1 小时子查询。
2. **读取延迟** —— 在子查询之间插入暂停，以管理服务器负载。
3. **开始/结束时间偏移** —— 当 `Start time offset = -60000`（-1 分钟）时，针对 `[10:00–11:00]` 的查询
   实际上会请求 `[9:59–11:00]`，从而确保不会遗漏迟到的数据。`End time offset` 也会以同样的方式偏移另一侧边界。
4. **恢复策略** —— 仅当有多个子区间需要追赶处理时才会起作用。使用 `From newest
to oldest` 时，只有当积压中的每个子区间都已被查询过后，被追踪的时刻才会前移——这样可以避免在
   OIBus 在追赶过程中重启时跳过尚未查询的较早区间。

:::info 偏移量应用于整个查询范围
开始/结束时间偏移只会应用一次，作用于整个查询窗口的起始和结束位置——而不是在因最大读取间隔而将大范围
拆分为多个分块时，应用于每个子区间的起始位置。
:::

#### 推荐配置 {#recommended-configurations}

| 场景                       | 最大读取间隔 | 读取延迟 | 开始时间偏移 |
| ------------------------------ | ----------------- | ---------- | ----------------- |
| 网络稳定、数据集较小 | 3600（1 小时）     | 500        | 0（无）          |
| 网络不稳定               | 1800（30 分钟）     | 2000       | 0（无）          |
| 大规模历史数据检索    | 7200（2 小时）    | 1000       | 0（无）          |
| 实时且偶有间隙 | 900（15 分钟）      | 200        | -15000（-15 秒）  |

最大读取间隔之间的权衡，以及开始/结束时间偏移的实例讲解（包括项目并非同时刷新的批量多项目场景）
——请参见 [调整南向历史调用设置](../advanced/history-query-timing.md)。
:::
