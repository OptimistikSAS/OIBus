### 限流设置 {#throttling-settings}

限流控制着 OIBus 如何调节历史数据请求的节奏。这些设置出现在每个**分组**上（对于支持分组的连接器），
或每个**项目**上（对于单项目连接器）。分组中的项目可以通过关闭**与组同步**开关来覆盖分组的默认值。

| 设置             | 描述                                                                                                                                                                                                          | 示例值         |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------- |
| **最大读取间隔** | 每个子查询的最大持续时间（秒）。较大的时间范围会自动拆分为不超过该值的多个分块。                                                                                                                              | `3600`         |
| **读取延迟**     | 连续子查询之间的暂停时间（毫秒）。有助于防止服务器过载并应对速率限制。                                                                                                                                        | `1000`         |
| **起始时间偏移** | 添加到查询窗口起始时间（`@StartTime`）上的毫秒数。**负值**会使起始时间提前，从而捕获上一区间中迟到的数据——这就是旧的“Overlap”行为。**正值**则相反，会使起始时间推后，跳过窗口开头相应长度的时间。              | `-60000`       |
| **结束时间偏移** | 添加到查询窗口结束时间（`@EndTime`）上的毫秒数。**负值**会使结束时间提前——适用于最新几行数据尚不可靠的最终一致性数据源。**正值**会使窗口向后延伸。如果计算后的结束时间不晚于有效的起始时间，则本次运行跳过该查询。 | `0`            |
| **恢复策略**     | OIBus 追赶未查询子区间积压的顺序——例如停止一段时间之后，或首次针对较大时间范围运行时。`从最旧到最新`（默认）按时间顺序处理积压。`从最新到最旧` 会优先查询最近的子区间，使最新数据能够立即可用，较早的空缺随后再回填。 | `从最旧到最新` |

#### 限流的工作原理 {#how-throttling-works}

1. **区间拆分** —— 当 `最大读取间隔 = 3600`（1 小时）时，一个 24 小时的范围会被拆分为 24 个独立的 1 小时子查询。
2. **读取延迟** —— 在子查询之间插入暂停，以控制服务器负载。
3. **起始/结束时间偏移** —— 当 `起始时间偏移 = -60000`（-1 分钟）时，针对 `[10:00–11:00]` 的查询实际上会请求
   `[9:59–11:00]`，从而确保不会遗漏迟到的数据。`结束时间偏移` 以同样的方式偏移另一侧边界。
4. **恢复策略** —— 仅当有多个子区间需要追赶时才会起作用。使用 `从最新到最旧` 时，只有当积压中的每个子区间都已被查询后，
   跟踪的时刻才会前移——这样可以避免 OIBus 在追赶过程中重启时跳过尚未查询的较早区间。

:::info 偏移量应用于整个查询范围
起始/结束时间偏移只会应用一次，作用于整个查询窗口的起始和结束位置——而不是在大范围按最大读取间隔拆分为多个分块时，
应用于每个子区间的起始位置。
:::

#### 推荐配置 {#recommended-configurations}

| 场景                 | 最大读取间隔   | 读取延迟 | 起始时间偏移     |
| -------------------- | -------------- | -------- | ---------------- |
| 网络稳定、数据集较小 | 3600（1 小时） | 500      | 0（无）          |
| 网络不稳定           | 1800（30 分钟）| 2000     | 0（无）          |
| 大规模历史数据检索   | 7200（2 小时） | 1000     | 0（无）          |
| 实时且偶有间隙       | 900（15 分钟） | 200      | -15000（-15 秒） |

:::tip 深入了解

以及起始时间偏移与结束时间偏移的实例讲解（包括项目并非同时刷新的批量多项目场景）——请参见
[调整南向历史调用设置](../advanced/history-query-timing.md)。
:::
