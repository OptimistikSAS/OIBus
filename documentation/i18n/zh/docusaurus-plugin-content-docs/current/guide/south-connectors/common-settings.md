# 通用设置

**South 连接器**从特定来源（例如 MQTT 代理、MSSQL 数据库）获取数据，并将其转发到 North 缓存。
每个连接器管理一个或多个**项目（items）**——即需要采集的单个数据点或查询。项目可以选择性地
组织成**分组（groups）**，以共享通用的调度和限流配置。

## 添加 South 连接器 {#adding-a-south-connector}

1. 导航到 **South** 页面。
2. 点击 **+** 按钮。
3. 选择连接器类型并配置其设置。
4. 从连接器的显示页面监控或调整设置。

## 通用设置 {#general-settings}

| 设置            | 说明                                             | 示例值                |
| --------------- | ------------------------------------------------ | --------------------- |
| **Name**        | 便于识别的用户友好标签。                         | `My MSSQL Connector`  |
| **Description** | 可选的说明信息（连接细节、访问权限、独特特征）。 | `Production database` |
| **Enabled**     | 从列表或其显示页面启用/禁用该连接器。            | Enabled/Disabled      |

## 特定部分 {#specific-section}

请参阅每个连接器的文档以了解其特定类型的设置。

### 测试连接 {#testing-connection}

使用 **Test settings** 按钮验证您的连接配置。

## 分组 {#groups}

分组用于捆绑共享相同采集调度的项目。每个分组包含：

| 设置                 | 说明                                                                                                  | 示例值         |
| -------------------- | ----------------------------------------------------------------------------------------------------- | -------------- |
| **Name**             | 该连接器内分组的唯一标签。                                                                            | `Group A`      |
| **Scan mode**        | 用于为该分组内所有项目采集数据的调度。                                                                | `Every 1 min`  |
| **Throttling**       | _（仅限支持历史查询的连接器）_ 分组内项目继承的默认限流设置。                                         | `3600, 200, 0` |
| **Caching strategy** | _（仅限 IoT 系列连接器）_ 与该分组同步的项目所继承的默认缓存策略。参见[缓存策略](#caching-strategy)。 | `On change`    |

分配到分组的项目会继承该分组的扫描模式。对于支持历史查询的连接器，项目默认还会继承分组的限流设置
（最大读取间隔、读取延迟、开始时间偏移、结束时间偏移、恢复策略），但每个项目可以通过禁用
**Sync with group** 来单独覆盖这些设置。

**未分配到任何分组**的项目直接在项目上定义自己的扫描模式。

分组的作用不仅限于调度：在 North 一侧，可以在分组级别指定转换器（transformer），
这样分组内的每个项目都会以相同方式进行转换，而无需逐个配置每个项目。无论 South
连接器是否支持历史查询，这一点都适用。

:::note SQL 和 REST 连接器的执行模型
对于基于 SQL 和 REST 的连接器，同一分组内的项目仍然**逐一**按顺序获取。分组提供
共享的调度和默认限流设置，但每个项目运行的是各自独立的查询。
:::

### 分组操作 {#group-actions}

分组可以直接从项目编辑表单或项目列表中的分组下拉菜单中创建、编辑和删除。删除分组
不会删除其中的项目——它们会变为未分配状态。

## 并发执行 {#concurrent-execution}

默认情况下，South 连接器一次只处理一个项目（或一个项目分组）：即使多个扫描模式同时触发，
也只有一个查询在任意时刻运行，其余的会排队等待。

如果某个扫描模式再次触发，而它所针对的项目或分组仍在运行——或已经在排队等待上一次
触发的处理——那么这次新的触发将被跳过，而不是被堆积起来。发生这种情况时会记录一条
警告日志，每个项目/分组每小时最多记录一次，这样当扫描模式对当前工作负载配置得过于
激进时，不会淹没日志，同时仍能让您知晓这一情况。

某些连接器类型可以根据其底层连接模型的表现安全地同时运行多个查询，并在其自身配置中
以 **Max parallel queries** 设置的形式暴露此功能——详情请参阅该连接器的文档
（例如 [OPC UA](./opcua.mdx#parallel-queries)）。对于其他所有连接器类型，执行始终
保持完全顺序化，且不可配置。

## 项目 {#items}

一个项目从数据源读取一个数据点、一条查询或一组文件。项目列在连接器的页面上，可在其中创建、编辑、复制、启用/禁用、删除、
移动到分组、导入和导出。除了逐个创建之外，项目还可以[从浏览弹窗中添加](#exploring-the-data-source)，或由
[项同步](#items-synchronisation)保持更新。

### 创建和编辑项目 {#creating-and-editing-an-item}

项目弹窗分为三个步骤，显示在其顶部的步骤栏中：

| 步骤           | 内容                                                                                                                     |
| -------------- | ------------------------------------------------------------------------------------------------------------------------ |
| **常规**       | 名称、分组、计划和**已启用**，然后是**历史设置**（支持历史查询的连接器）和**缓存**设置（IoT 系列连接器）。               |
| **设置**       | 连接器自身的项目设置（请参阅每个连接器的页面），其下方紧接着是[测试面板](#testing-an-item)，可在编辑设置的同时进行测试。 |
| **检查并保存** | 整个项目的只读摘要：常规、历史和缓存设置，然后是其连接器设置。                                                           |

只有当前步骤有效时，**下一步**才会继续。新项目在最后一步保存；正在编辑或复制的项目可以在任意步骤保存。当保存因某个字段
无效而失败时，弹窗会打开第一个存在错误的步骤，并在步骤栏中标记每个存在错误的步骤。

要连续创建多个相似的项目，请使用**保存并继续添加**（在连接器的创建/编辑页面上为**确定并继续添加**）：项目被保存后，
弹窗会再次打开以创建下一个项目，并沿用相同的分组、计划和历史设置。

在连接器的创建/编辑页面上，项目（与分组和项同步一样）保留在页面中，并与连接器一起保存，因此按钮为**确定**而不是**保存**。

### 项目字段 {#item-fields}

| 设置             | 步骤 | 说明                                                                                            | 示例值                  |
| ---------------- | ---- | ----------------------------------------------------------------------------------------------- | ----------------------- |
| **名称**         | 常规 | 北向连接器和转换器用于识别该数据点的唯一引用。                                                  | `Temperature_Sensor1`   |
| **组**           | 常规 | 该项目所属的分组。对于拥有自己计划的独立项目，请保持为**无**。                                  | `Group A`               |
| **计划**         | 常规 | 决定 OIBus 何时采集数据的扫描模式。仅当项目没有分组时显示（否则显示分组的计划）。               | `Every 1 min`           |
| **已启用**       | 常规 | 该项目是否处于激活状态。                                                                        | 启用/禁用               |
| **与组同步**     | 常规 | _（支持历史查询的连接器，已分组的项目）_ 启用后，下列历史设置将从分组继承。                     | 启用/禁用               |
| **最大读取间隔** | 常规 | _（支持历史查询的连接器）_ 最大子查询时长（秒）。                                               | `3600`                  |
| **读取延迟**     | 常规 | _（支持历史查询的连接器）_ 连续子查询之间的暂停时间（毫秒）。                                   | `200`                   |
| **起始时间偏移** | 常规 | _（支持历史查询的连接器）_ 添加到 `@StartTime` 的毫秒数。负值会使其提前，以捕获延迟到达的数据。 | `-60000`                |
| **结束时间偏移** | 常规 | _（支持历史查询的连接器）_ 添加到 `@EndTime` 的毫秒数。负值会使其提前。                         | `0`                     |
| **恢复策略**     | 常规 | _（支持历史查询的连接器）_ 补录积压的未查询子区间时所采用的顺序：由旧到新（默认）或由新到旧。   | `From oldest to newest` |
| **缓存策略**     | 常规 | _（仅限 IoT 系列连接器）_ 过滤实际被缓存并转发的采集值。参见[缓存策略](#caching-strategy)。     | `On change`             |
| **特定设置**     | 设置 | 因连接器类型而异——请参阅每个连接器的文档。                                                      | —                       |

> 有关如何设定**最大读取间隔**、**读取延迟**、**起始时间偏移**和**结束时间偏移**的指南——包括针对大量积压数据以及无法
> 一次性提交所有项目的数据源的实际示例——请参阅[历史连接器的高级调优](../advanced/history-query-timing.md)。

### 测试项目 {#testing-an-item}

**设置**步骤包含测试面板，因此无需离开该步骤即可修改项目设置并再次测试。**运行测试**会使用当前编辑中的设置（无论是否已
保存）查询数据源，并显示原始结果。对于支持历史查询的连接器，**从此处查询数据** / **查询数据直到**用于设置测试查询的时间范围。

还可以让原始结果通过该项目的某个北向转换器，以预览转换后的输出——参见
[针对真实南向项目测试转换器](../engine/transformers.mdx#testing-a-transformer-against-a-real-south-item)。

> **提示**：先在连接器上使用**测试设置**检查连接，然后再测试单个项目。

### 项目操作 {#item-actions}

- **禁用/启用**：可从项目弹窗或直接从连接器的显示页面切换。可以一次性启用或禁用多个选中的项目。
- **复制**：打开预先填入该项目设置的项目弹窗，以创建一个相似的项目。
- **查看最新值**（🔍）：打开只读面板，显示该项目的最后一次检索状态。详情请参阅
  [查看最后检索到的值](#inspecting-the-last-retrieved-value)。
- **移动到组**：选择多个项目并使用批量操作菜单，一次性将它们重新分配到某个分组。

### 导入/导出项目 {#importexport-items}

- **导出**：将所有项目下载为 CSV。列包括 `name`、`enabled`、`scanMode`、`group`、`syncWithGroup`、`maxReadInterval`、
  `readDelay`、`startTimeOffset`、`endTimeOffset`、`recoveryStrategy`，以及特定于连接器的 `settings_*` 列。
- **导入**：上传 CSV 以批量创建或更新项目。导出现有列表可获得一个具有正确列名的有效模板。
  > **注意**：系统会在应用导入之前验证重复项和格式的正确性。

## 浏览数据源 {#exploring-the-data-source}

能够浏览其数据源的连接器会在**测试设置**旁边显示一个**浏览**按钮。它会打开**浏览数据源**弹窗：一棵展示数据源内容的树，
在展开节点时逐级加载。

| 连接器                                                    | 树中显示的内容                                                  | 对所选节点的操作            |
| --------------------------------------------------------- | --------------------------------------------------------------- | --------------------------- |
| [OPC UA](./opcua.mdx#node-metadata)                       | 服务器的地址空间，附带节点元数据（节点 ID、类型、描述、单位……） | **添加为项**、**保持同步…** |
| [BACnet/IP](./bacnet.mdx#discovering-devices-and-objects) | 设备，然后是每个设备的对象                                      | **添加为项**、**保持同步…** |
| MSSQL、MySQL、PostgreSQL、Oracle、SQLite                  | 表（在可获取时附带列数和行数），然后是每个表的列                | **添加为项**                |
| [Folder Scanner](./folder-scanner.mdx)                    | 输入文件夹中的文件夹和文件，附带大小和日期                      | —（仅浏览）                 |

点击某个节点，可在侧边面板中显示其详细信息（数据源为其提供的元数据），每个值都带有一个复制按钮。浏览使用当前编辑中的
设置，因此在连接器保存之前，也可以在连接器的创建/编辑页面上使用。

:::tip 浏览与连接器自身的连接
对于设置相同且正在运行的连接器，浏览会通过其已打开的连接进行，而不是建立第二个连接——这样，限制每个客户端会话数量的
服务器（例如 OPC UA）就不会拒绝它。已禁用或未保存的连接器则通过一个临时实例进行浏览，该实例会在弹窗关闭时释放，因此
浏览永远不会启动连接器自身的采集。
:::

### 选择节点 {#selecting-nodes}

对于支持对所选节点执行操作的连接器，每个节点都有一个复选框。拥有子节点的节点还提供**选择** _该节点_ **的所有子节点**，
它会一次性加载并勾选其直接子节点（如果它们已全部勾选，则取消勾选）。所选节点的数量显示在弹窗底部的操作旁边：

- **添加为项**根据所选节点一次性创建项目——参见[下文](#adding-explored-nodes-as-items)。
- **保持同步…**创建一个从所选节点进行发现的[项同步](#items-synchronisation)：向导打开时以这些节点作为其发现范围，并使用
  连接器的[发现默认值](#discovery-defaults)。与**添加为项**不同，同步会在每次运行时保持项目最新：新的点会获得一个项目，
  已消失的点的项目会被禁用。

所选节点代表的内容取决于其类型：点（OPC UA 变量、BACnet 对象、SQL 列）代表其自身，其他任何节点（文件夹、设备、表）
代表其下的所有内容。

### 将浏览到的节点添加为项目 {#adding-explored-nodes-as-items}

**添加为项**会发现所选节点下的点，并打开**从数据源添加项**弹窗，以便在创建项目之前对其进行检查：

- **组**、**计划**和**启用这些项**适用于每个添加的项目。选择分组时，项目采用该分组的计划。
- 每一行对应一个项目，包含其名称（可编辑）及其主要设置。取消勾选某一行即可将其排除，或使用表头复选框全选或全不选。
- 如果某一行的设置已被现有项目读取，则会被标记为**已由** _该项目_ **读取**，并保持未勾选状态。如果某个名称已被其他项目
  或行使用，则会被标记为**名称已被使用**。

**添加项**会创建已勾选的行。项目根据连接器的[发现默认值](#discovery-defaults)进行命名和设置；发现默认值中未包含的每个
项目设置都会获得其通常的默认值，与项目弹窗中一致。

#### SQL 表作为项目 {#sql-tables-as-items}

对于 SQL 连接器，每个所选的表（或所选列所属的每个表）生成一个以该表命名的项目，其查询读取该表：

- 所选的表读取其所有列（`SELECT *`）；所选的列则仅读取这些列。
- OIBus 会选取一个**日期/时间列**来跟踪该表：在表的日期/时间列中，它优先选择常用名称（`timestamp`、`time`、`date`、
  `datetime`，或以 `_at`、`_time`、`_date`、`timestamp` 结尾），否则选择第一个。该列始终会被读取（即使未被选中），且
  查询每次运行只读取该时间范围内的行。例如，选中某个 MSSQL 表的 `tag` 和 `value` 列时：

  ```sql
  SELECT [timestamp], [tag], [value] FROM [dbo].[measures] WHERE [timestamp] > @StartTime AND [timestamp] <= @EndTime
  ```

  项目的**跟踪时间戳**会在该列上启用，并使用与其 SQL 类型匹配的日期/时间类型，因此每次运行都从上一次停止的位置开始。

- 没有任何日期/时间列的表在每次运行时都会被完整读取，且不进行跟踪：启用之前请检查其查询。

表名和列名会按照连接器自身的 SQL 方言加上引号。生成的查询只是一个起点：之后可编辑该项目以过滤行或重命名列。

## 缓存策略 {#caching-strategy}

对于**IoT 系列连接器**（OPC UA、Modbus、ADS、OPC Classic、S7、MQTT、BACnet/IP），每个项目都可以过滤实际被
缓存并转发到 North 连接器的采集值，而不是缓存每一个读取或接收到的值。这可以减小缓存大小，并
降低对于稳定或缓慢变化的数据点的 North 连接器负载。

| 设置                           | 说明                                                                                                                                                                                                                         | 示例值       |
| ------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------ |
| **Caching strategy**           | `All values`（默认）：缓存每一个值。`On change`：仅当值与上次缓存的值不同时才缓存。`Threshold`：仅当值的变动超过配置的量时才缓存。若在与分组同步的项目上未设置，则该项目继承分组的缓存策略。                                 | `On change`  |
| **Threshold type**             | _（仅限 Threshold 策略）_ `Absolute`：比较原始数值差。`Percentage`：以配置范围的百分比来比较差值。                                                                                                                           | `Percentage` |
| **Threshold**                  | _（仅限 Threshold 策略）_ 缓存新值所需的最小变化量——根据 **Threshold type** 的不同，可解释为绝对差值或范围的百分比。                                                                                                         | `5`          |
| **Range low** / **Range high** | _（仅限百分比类型的 Threshold 策略）_ 值的预期下限/上限，用于计算阈值所依据的百分比跨度。                                                                                                                                    | `0` / `100`  |
| **Max caching interval**       | _（"All values" 时不显示）_ 可选的心跳间隔（毫秒）。即使某个值不满足 **On change** 或 **Threshold** 的条件，只要自上次缓存值以来经过的时间达到该值，仍会被缓存——这样即便是稳定的数据点也会定期产生存活证明数据。留空以禁用。 | `3600000`    |

与调度设置不同，**Threshold type**、**Threshold**、**Range low**/**Range high** 以及 **Max
caching interval** 始终在项目本身上配置——即使项目的 **Caching strategy** 是从分组继承的，
这些字段也永远不会被继承。

:::note 并非所有连接器都支持
由于 MQTT 载荷不保证是数值类型，MQTT 项目不提供 **Threshold** 策略。**On change** 会改为
对值进行深度相等比较，因此它适用于任何载荷形式。
:::

:::tip 首个值始终会被缓存
项目采集到的第一个值——或者在其缓存比较状态消失后（例如项目被删除并重新创建）再次采集到的
第一个值——始终会被缓存，因为此时尚无可供比较的对象。该比较状态会被持久化，因此它会在
OIBus 重启后依然保留，而不会在每次重新连接时重置。
:::

分组也可以配置 **Caching strategy**，与该分组同步的项目会默认使用它。但特定于阈值的字段
永远不会被继承：如果某个分组的缓存策略为 **Threshold**，每个与之同步的项目仍必须自行配置
**Threshold type**/**Threshold**/**Range**——若不设置，则回退为绝对阈值 `0`（即任何变化都会被缓存）。

## 最大瞬时值跟踪 {#max-instant-tracking}

支持历史查询的 South 连接器会跟踪最后一次成功检索的时间戳（即 _max instant_，最大瞬时值），
以便每次运行仅获取新数据。该瞬时值是按项目跟踪还是在分组间共享，取决于分组实际的查询方式：

- 如果该连接器可以将分组项目合并为单次查询（即它*不是*上文所述那种始终逐一查询项目的
  SQL/REST 风格连接器），**并且**该项目启用了 **Sync with group**，则整个分组共享**一个**
  跟踪瞬时值——因为分组作为单个整体被查询，没有有意义的、可单独跟踪的每项目值。
- 否则（无分组、未启用同步，或是 SQL/REST 风格的连接器），即使项目属于某个分组，每个
  项目也会独立跟踪自己的瞬时值。

:::tip 离开共享分组会保留跟踪瞬时值，而不是缓存的值
当某个项目不再由共享分组瞬时值支持时——其分组被设为无、**Sync with group** 被关闭，
或该分组本身被删除——它会将该分组的_跟踪瞬时值_带入到自己新的、独立的跟踪中，因此它
会从该处继续，而不是重新查询整个回溯窗口。分组最后缓存的_值_**不会**被带过来；项目
自己的值只会在下一次独立查询时重新填充。直接从一个已同步的分组移动到另一个分组不会
触发此行为：项目会在整个过程中持续参考共享瞬时值，只是换到了新分组下。
:::

### 配置更改时的行为 {#behaviour-when-configuration-changes}

| 操作               | 对最大瞬时值的影响                                                                                                                                             |
| ------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 更改项目的分组     | 已独立的项目会保留自己的跟踪瞬时值。离开共享分组的项目会将该分组的跟踪瞬时值带入自己的跟踪中（见上方提示）。在两个已同步分组之间移动时，将始终使用共享瞬时值。 |
| 更改分组的扫描模式 | 跟踪瞬时值（无论是按项目还是共享的）在新的扫描模式下都会被保留。                                                                                               |
| 删除分组           | 项目变为未分配状态。原本独立的项目保留自己的跟踪瞬时值；原本与该分组同步的项目会将其共享的跟踪瞬时值带入自己的跟踪中。                                         |
| 删除项目           | 该项目自己的跟踪瞬时值将被移除；只要分组中还有其他项目，共享的分组瞬时值不受影响。                                                                             |
| 删除连接器         | 所有项目、分组和跟踪瞬时值都会被移除。                                                                                                                         |

:::warning 更改限流设置时的数据缺口和重复
如果您更改了某个分组或项目的最大读取间隔、开始时间偏移或结束时间偏移，下一次查询将从当前
跟踪瞬时值开始使用新参数。明显不同的偏移量可能会在边界处造成小的数据缺口或重复。
:::

### 查看最后检索到的值 {#inspecting-the-last-retrieved-value}

点击任意项目行上的 **🔍** 图标以打开 **Last retrieved value** 面板。它显示：

| 设置                | 说明                                                                                                                                               | 示例值                        |
| ------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------- |
| **Item name**       | 项目的名称。                                                                                                                                       | `Temperature_Sensor1`         |
| **Group**           | 该项目所属的分组（如有）。                                                                                                                         | `Group A`                     |
| **Query time**      | 该项目最后一次查询执行的时间戳。                                                                                                                   | `2024-01-15T10:30:00.000Z`    |
| **Tracked instant** | 为该项目存储的_最大瞬时值_——将用作下一次查询的 `@StartTime`。如果尚未运行过查询，则为空。                                                          | `2024-01-15T10:29:55.000Z`    |
| **Value**           | 最后缓存的结果。对于基于文件的连接器：文件名及修改时间的列表。对于历史查询连接器：最后一次子查询的原始 JSON 载荷。如果尚未检索到任何数据，则为空。 | `[{"file": "data.csv", ...}]` |

- 诊断数据缺口——将跟踪瞬时值与当前时间进行比较，以查看项目落后多少。
- 确认基于文件的连接器最后看到的确切文件或记录。

## 项同步 {#items-synchronisation}

与其手动创建和维护项目，**项同步**会浏览或查询数据源，保留值得处理的内容，然后据此创建/更新项目，或将其转发到
OIAnalytics——可按需运行一次，也可以像其他采集一样按计划运行。

每个同步属于一个南向连接器，并以以下两种模式之一运行：

- **在本地创建/更新项**——同步拥有其创建的项目，在后续运行中更新它们，并禁用（从不删除）不再找到对应点的项目。
- **推送到 OIAnalytics**——每次运行都将发现的记录原样转发到 OIAnalytics，不进行字段映射，不创建本地项目，也不与上一次
  运行进行比较。这是 SQL 连接器的唯一模式（参见[模式](#mode)）。

支持该功能的连接器及其发现来源：

| 连接器系列                                          | 发现范围                                                 | 模式                     |
| --------------------------------------------------- | -------------------------------------------------------- | ------------------------ |
| **基于树的连接器**（OPC UA、BACnet/IP）             | 在浏览树中选取的节点——若未选取任何节点，则为整个数据源。 | 本地或推送到 OIAnalytics |
| **SQL**（MSSQL、MySQL、PostgreSQL、Oracle、SQLite） | 一个元数据查询：它返回的每一行就是一条发现的记录。       | 仅推送到 OIAnalytics     |
| 其他任何连接器类型（包括 Folder Scanner）           | 尚不支持：**来源**步骤会改为显示一条简短提示。           | —                        |

:::tip 项同步还是添加为项？
要根据数据源的内容一次性创建项目，请在浏览弹窗中选择节点并使用[添加为项](#adding-explored-nodes-as-items)。当数据源会
随时间变化（新增点、移除点）且项目必须随之更新时，请使用项同步。
:::

### 管理项同步 {#managing-items-synchronisations}

在南向连接器的页面上，点击**管理项同步**（位于**管理组**旁边）以列出该连接器的同步，并使用 **+** 按钮创建一个。每一行
显示同步的名称、计划、模式及其是否已启用，并提供以下操作：

| 操作              | 说明                                                                        |
| ----------------- | --------------------------------------------------------------------------- |
| **立即运行**（▶） | 立即触发一次真实运行——参见[运行项同步](#running-an-items-synchronisation)。 |
| **运行历史**      | 以往的运行及其状态和计数——参见[运行历史](#run-history)。                    |
| **编辑**（✏️）    | 在向导中打开该同步。                                                        |
| **复制**          | 打开预先填入该同步设置的向导（名称加上 `-copy` 后缀），并另存为一个新同步。 |
| **删除**          | 移除该同步。它创建的项目及其推送的元数据**不会**被删除。                    |

也可以从[浏览弹窗](#selecting-nodes)创建同步：选择节点，然后点击**保持同步…**。

连接器的创建/编辑页面上也有同样的**管理项同步**按钮。在该页面中，所做的更改保留在页面中，并与连接器一起保存（与项目和
分组一样），预览则使用当前编辑中的连接器设置运行——因此可以在保存连接器本身之前试用同步。**立即运行**和**运行历史**仅在
连接器保存后，从连接器页面中可用。

### 向导 {#the-wizard}

同步通过一个五步向导创建和编辑。其顶部的步骤栏显示当前所在位置，点击某个步骤即可打开它。

| 步骤     | 设置内容                                                |
| -------- | ------------------------------------------------------- |
| **来源** | 名称以及要发现的内容：要浏览的节点，或 SQL 元数据查询。 |
| **筛选** | 要处理哪些发现的记录，并预览匹配的记录。                |
| **项**   | 模式，以及在本地模式下记录如何转换为项目。              |
| **计划** | 何时运行，以及是否启用计划运行。                        |
| **检查** | 摘要，以及一次运行将执行的操作的预览。                  |

**来源**步骤在填写名称（对于 SQL 还需填写查询）后即可通过**下一步**离开。新同步在**检查**步骤保存；正在编辑的同步可以在
任意步骤保存。

#### 来源 {#source}

- **名称**——在该连接器的同步中唯一。
- **发现范围**：
  - **基于树的连接器**：**选择节点...**会打开浏览树，并勾选当前节点；勾选要从中发现的节点，然后点击**使用这些节点**。
    点代表其自身，其他任何节点（文件夹、设备）代表其下的所有内容。点击节点标签上的叉号即可移除该节点。没有节点时，将
    发现整个数据源。
  - **SQL 连接器**：在 SQL 编辑器中编写元数据查询——它独立于任何项目自身的查询，返回的每一行都会成为一条发现的记录
    （例如 `SELECT tag, description, unit FROM tag_list`）。当连接器可被浏览时，其表和列会显示在编辑器上方以供参考。
    **测试查询**会运行该查询，并以表格或 JSON 形式显示其原始行。

#### 筛选 {#filter}

**资格筛选**列出发现的记录必须**全部**满足（逻辑与）才会被处理的条件——留空则所有记录都符合条件。每个条件包含：

| 设置       | 说明                                                                     | 示例值     |
| ---------- | ------------------------------------------------------------------------ | ---------- |
| **字段**   | 发现的记录中的一个字段。会建议预览记录中的字段。                         | `type`     |
| **运算符** | `等于`、`不等于`、`包含`、`匹配（正则表达式）`、`存在`、`大于`、`小于`。 | `等于`     |
| **值**     | 要比较的值——`存在` 不使用该值。                                          | `Variable` |

使用表格下方的字段添加条件；使用其铅笔和垃圾桶图标编辑或移除条件。

打开该步骤时会发现数据源，并显示**符合条件的记录：*eligible* / *discovered***，同时在表格中显示前 20 条匹配的记录，以便
查看它们包含哪些字段。修改条件后，请点击**刷新预览**。发现是一次与数据源之间的真实往返：预览一个大型数据源的开销与一次
运行相同，只是没有写入操作。

#### 项 {#items-step}

##### 模式 {#mode}

选择**在本地创建/更新项**或**推送到 OIAnalytics**。在两者之间切换会清除为另一种模式所做的配置。

- **推送到 OIAnalytics**会将每次运行中符合条件的记录原样转发到 OIAnalytics。保存和运行永远不会因注册状态而被阻止，但只有在
  OIBus [注册到 OIAnalytics](../installation/oianalytics.mdx) 之后才会进行推送：在此之前，向导中会显示一条警告，且每次运行都会
  记录一条警告日志，不发送任何内容。
- **在本地创建/更新项**会在下方显示**项字段映射**。

:::note SQL 连接器仅推送到 OIAnalytics
对于 SQL 连接器，一个项目就是一条自由格式的查询，而一条查询可以同时返回多个不同的点——在这里项目和点并不是一回事。对于这些
连接器，同步从不创建或更新项目，模式选择器会被一条提示所取代。要根据 SQL 表创建项目，请在浏览弹窗中使用
[添加为项](#sql-tables-as-items)。
:::

##### 项字段映射 {#item-field-mapping}

连接器项目的每个字段都可以映射为：

- **未映射**——新项目获得该字段通常的默认值，与项目弹窗中一致（更新的项目保留其自身的值），
- 一个常量（对于是/否、选项、计划和分组字段为下拉列表；其他情况为自由文本），或
- 一个从发现的记录中取值的 `{{field}}` 表达式——参见[映射表达式](#mapping-expressions)。

**名称**、**组**和**计划**显示在最前面。名称下方的**项名称示例：**显示前几条匹配记录将生成的名称。**组**下拉列表默认为
**无**，并且可以像在项目弹窗中一样创建、编辑或删除分组；选择分组时，项目采用该分组的计划。

其他字段以及[标识键字段](#identity-key-fields)位于**高级**下。当连接器具有[发现默认值](#discovery-defaults)时，它们会填充
该部分，该部分保持折叠并显示摘要（例如 `已映射其他 3 个字段，记录由 id 标识`）；否则，该部分会展开显示，因为所有内容都必须
手动映射。

两个标记用于指导映射：

- **必填**——根据当前显示的其他字段，该字段必须映射，项目才有效。否则无法保存。一旦项目被映射到某个分组中，计划即可免填。
- **控制可见性**——该字段决定其他字段是否适用，因此它只能取常量：其值必须在编辑时已知，而不是按记录解析。分组、计划以及每个
  历史设置（最大读取间隔、读取延迟、时间偏移、恢复策略、与组同步）也是如此。

##### 标识键字段 {#identity-key-fields}

**标识键字段**指定一个或多个记录字段，其组合值用于在多次运行之间识别一条记录——例如 OPC UA 和 BACnet 的 `id`。在本地模式下
至少需要一个：

- 本地同步在每次运行时都会重新发现数据源，并按此键将记录与上一次运行进行匹配：记录可能是新增、已变更或未变更的，而不再
  出现的键则为缺失（参见[运行项同步](#running-an-items-synchronisation)）。如果同一次运行中的两条记录具有相同的键，则以
  后一条为准。
- **推送到 OIAnalytics**从不比较多次运行，因此没有标识键字段：跨运行关联记录的工作交由 OIAnalytics 完成。

##### 映射表达式 {#mapping-expressions}

项目字段使用 `{{field}}` 占位符语法：

- **恰好**为一个占位符的值（例如 `{{nodeId}}`）会取该字段的原始值并保留其类型——数值型记录字段会原样写入数值型设置，而不会
  被转换为文本。
- 位于其他文本中的占位符（例如 `Sensor {{nodeId}}`）属于字符串插值——结果始终为文本。
- 记录中缺失的字段会解析为空值，而不会导致运行失败。

##### 发现默认值 {#discovery-defaults}

发现的记录始终具有相同结构的连接器带有发现默认值：新的同步（以及[添加为项](#adding-explored-nodes-as-items)）一开始就使用
这些标识键字段和此映射，之后可以修改。

| 连接器    | 标识键 | 项字段映射                                                                                                                                                         |
| --------- | ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| OPC UA    | `id`   | 名称 `{{path}}`（从发现根节点开始的各级显示名称，以 `/` 连接），节点 ID `{{nodeId}}`，模式 `DA`，时间戳来源 `OIBus`。参见[节点元数据](./opcua.mdx#node-metadata)。 |
| BACnet/IP | `id`   | 名称 `{{deviceName}} - {{name}}`，设备地址和实例、对象类型和实例、路由（`{{routed}}`、网络号、MAC 地址）取自记录；属性 `present-value`，时区 `UTC`。               |

#### 计划 {#schedule}

- **计划**——驱动计划运行的扫描模式。保持为**仅手动**则只能通过**立即运行**来运行该同步。
- **已启用**——是否触发计划运行。即使已禁用，**立即运行**仍然有效。

在本地模式下，会有一条提醒说明：当某个点不再被找到时，为其创建的项目将被禁用。

#### 检查 {#review}

**检查**步骤汇总该同步（名称、发现范围、条件数量、模式、计划），并预览一次运行将执行的操作——打开该步骤即运行预览，
**刷新预览**会再次运行：

- **在本地创建/更新项**：每条记录都会与上一次运行进行比较，并被归类为**新增**、**已变更**、**未变更**、**已重新激活**或
  **缺失**，同时显示其标识键和字段。已变更的记录会高亮显示不同的字段，鼠标悬停时显示先前值；缺失的记录以灰显方式显示上一次
  运行的值。
- **推送到 OIAnalytics**：将被推送的记录，与发现时完全一致。

**导出 CSV** 会下载预览的行。预览不会写入任何内容。

### 运行项同步 {#running-an-items-synchronisation}

一次运行始终会（按发现范围的定义）发现数据源并保留符合条件的记录，然后根据模式执行操作：

- **在本地创建/更新项**按标识键将符合条件的记录与上一次运行进行匹配：为每条新增、已变更或已重新激活的记录创建或更新一个
  项目，跳过未变更的记录，并禁用（从不删除）每条缺失记录对应的项目，原因为 "Configuration workflow no longer discovers this
  entry"。新项目会为映射未包含的每个字段（在适用时）获得通常的默认值。
- **推送到 OIAnalytics**将符合条件的记录原样转发到 OIAnalytics，每次运行发送一条消息。不会创建、更新或禁用任何内容。

:::tip 立即运行适用于已禁用的连接器
构建和测试同步无需先启用连接器：与浏览一样，**立即运行**适用于已禁用的连接器。但是，当南向连接器被禁用时，**计划**运行
会被跳过。
:::

### 运行历史 {#run-history}

每次运行——无论是手动还是定时、成功与否——都会被记录。从同步列表中打开的**运行历史**页面首先是一个搜索表单：

- **开始时间晚于 / 开始时间早于**——运行开始时间的日期范围。
- **状态**和**触发方式**——筛选标签（再次点击可移除某个标签，或点击**清除**全部移除）。每个状态标签除颜色外还有其自身的
  图标（运行中为加载图标，已完成为对勾，出错为叉号）。

表格按运行显示：

| 列                      | 说明                                         |
| ----------------------- | -------------------------------------------- |
| **状态**                | `运行中`、`已完成` 或 `出错`。               |
| **触发方式**            | `手动`（立即运行）或 `定时`。                |
| **开始时间 / 完成时间** | 运行开始的时间，以及结束的时间（如已结束）。 |
| **触发者**              | 点击立即运行的用户；定时运行时为空。         |
| **已发现**              | 运行在资格筛选之前发现的记录数量。           |
| **错误**                | 运行出错时的失败消息——否则为 **Ø**。         |

某一行上的**查看有效载荷**（👁）会打开该次运行所执行的操作，呈现方式与**检查**步骤的预览相同：被归类为**新增**、**已变更**、
**未变更**、**已重新激活**或**缺失**的记录（本地模式），或已推送的记录（推送到 OIAnalytics），以及已创建 / 已更新 / 已禁用 /
已推送的计数和**导出 CSV**。这是运行时所处理并存储的数据——而不是一次新的查询——因此即使数据源此后发生了变化，它仍然准确。
当运行仍处于 `运行中` 状态时不可用。
