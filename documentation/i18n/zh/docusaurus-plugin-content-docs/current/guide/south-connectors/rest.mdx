# REST

使用可配置的方法、查询参数、头信息和请求正文，从任何 HTTP/HTTPS REST API 查询数据。

## 连接设置 {#connection-settings}

### 主要配置 {#main-configuration}

| 设置                    | 描述                                                            | 示例值                    |
| ----------------------- | ----------------------------------------------------------------- | -------------------------- |
| **Host**                | REST API 服务器的基础 URL。必须以 `http://` 或 `https://` 开头。   | `http://server.com:8080`    |
| **接受未经授权的证书**  | 允许使用自签名或无效证书的 HTTPS 连接。                            | Enabled/Disabled            |
| **超时**                | 报告连接失败之前的持续时间（秒）。默认：`30`。                    | `30`                        |

### 身份验证 {#authentication}

| 设置          | 描述                                          | 示例值                                     |
| ------------- | ----------------------------------------------- | -------------------------------------------- |
| 身份验证方法  | 连接的身份验证类型。                            | `None`、`Basic`、`Bearer`、`API Key`         |
| Username      | 用于 Basic 身份验证的用户名。                   | `api_user`                                   |
| Password      | 用于 Basic 身份验证的密码。                     | `••••••••`                                   |
| Token         | 在 `Authorization` 头中发送的 Bearer token。    | `eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...`    |
| API Key       | 用于 API Key 身份验证的头名称或查询参数名称。   | `X-Api-Key`                                  |
| API Value     | 与请求一起发送的密钥值（加密存储）。            | `••••••••`                                   |
| Add to        | API key/value 对被注入的位置。                  | `header`、`query-params`                     |

### 代理配置 {#proxy-configuration}

| 设置            | 描述                             | 示例值                            |
| --------------- | -------------------------------- | ---------------------------------- |
| **使用代理**    | 通过代理服务器路由请求。         | Enabled/Disabled                   |
| **代理 URL**    | 代理服务器的完整 URL。           | `http://proxy.example.com:8080`    |
| **代理用户名**  | 代理身份验证的用户名（如需要）。 | `proxy_user`                       |
| **代理密码**    | 代理身份验证的密码（如需要）。   | `••••••••`                         |

### 连接测试 {#connection-test}

OIBus 可以在执行任何项目查询之前测试与服务器的连接。这有助于验证凭据和可达性。

| 设置             | 描述                                                    | 示例值    |
| ---------------- | --------------------------------------------------------- | ----------- |
| **Method**       | 用于测试请求的 HTTP 方法。默认：`GET`。                    | `GET`        |
| **Test Endpoint** | 附加到主机的路径。默认：`/`。                             | `/health`    |
| **Body**         | `POST` 或 `PUT` 测试请求的可选 JSON 正文。                 | `{}`         |
| **Success code** | 表示连接成功的 HTTP 状态代码。默认：`200`。                | `200`        |

:::info
测试正文仅在方法为 `POST` 或 `PUT` 时发送。
:::

## 分组设置 {#group-settings}

项目可以组织成分组。每个分组定义一个共享的采集计划和默认的限流设置。同一分组中的项目仍然是
**依次逐个**获取的——分组只是提供各项目可以覆盖的通用默认值。

| 设置        | 描述                                                                                             | 示例值                     |
| ----------- | -------------------------------------------------------------------------------------------------- | --------------------------- |
| **名称**    | 该连接器内分组的唯一标签。                                                                         | `Group A`                   |
| **扫描模式** | 用于采集分组中所有项目的计划。                                                                     | `Every 1 min`                |
| **限流**    | 该分组中项目继承的默认限流值（最大读取间隔、读取延迟、开始时间偏移、结束时间偏移、恢复策略）。     | `3600, 200, 0, 0, oldest`   |

## 项目设置 {#item-settings}

每个项目对应一个特定的 API 端点，并定义如何请求和解读响应。项目默认从所属分组继承扫描模式
和限流设置，但可以通过禁用**与分组同步**对每个设置进行单独覆盖。

### 请求配置 {#request-configuration}

| 设置             | 描述                                          | 示例值         |
| ---------------- | ----------------------------------------------- | --------------- |
| **Method**       | 数据请求使用的 HTTP 方法。默认：`GET`。         | `GET`            |
| **Endpoint**     | 附加到主机的路径。                              | `/api/data`       |
| **Return type**  | 响应的处理方式——结构化正文或原始文件下载。      | `body`、`file`   |

### 查询参数 {#query-parameters}

添加以查询字符串参数形式附加到请求 URL 的键/值对。可使用 `@StartTime` 和 `@EndTime`
变量将查询的时间窗口直接注入参数值中。

| 设置             | 描述                                                                       | 示例值          |
| ---------------- | ----------------------------------------------------------------------------- | ----------------- |
| **Key**          | 查询参数的名称。                                                              | `from`             |
| **Value**        | 参数的值；可以包含 `@StartTime` 或 `@EndTime` 占位符。                        | `@StartTime`       |
| **Date format**  | 当值包含 `@StartTime` 或 `@EndTime` 时显示——配置瞬时值的格式化方式。          | `iso-string`       |

#### 查询参数的日期/时间格式 {#datetime-format-for-query-parameters}

当参数值包含 `@StartTime` 或 `@EndTime` 时，会出现日期格式配置部分：

| 设置         | 描述                                     | 示例值                                                    |
| ------------ | ------------------------------------------ | ------------------------------------------------------------ |
| **Type**     | 日期时间值的表示方式。                     | `iso-string`、`unix-epoch`、`unix-epoch-ms`、`string`         |
| **Timezone** | 用于格式化的时区（仅适用于 `string` 类型）。 | `UTC`、`Europe/Paris`                                        |
| **Format**   | 自定义格式模式（仅适用于 `string` 类型）。  | `yyyy-MM-dd HH:mm:ss`                                          |

### 头信息 {#headers}

向请求添加自定义 HTTP 头。与查询参数一样，头的值支持使用相同的日期/时间格式配置进行
`@StartTime` 和 `@EndTime` 替换。

| 设置       | 描述                                                        | 示例值            |
| ---------- | -------------------------------------------------------------- | ------------------- |
| **Key**    | 头名称。                                                        | `X-Custom-Header`    |
| **Value**  | 头的值；可以包含 `@StartTime` 或 `@EndTime` 占位符。            | `Bearer my_token`     |

:::info Content-Type
当配置了正文但未显式定义 `Content-Type` 头时，OIBus 会自动添加
`Content-Type: application/json`。
:::

### 请求正文 {#request-body}

可以为 `POST`、`PUT`、`PATCH` 和 `DELETE` 请求发送 JSON 正文。正文支持使用 `@StartTime` 和
`@EndTime` 占位符将查询时间窗口注入负载中。

| 设置             | 描述                                                                | 示例值                    |
| ---------------- | ---------------------------------------------------------------------- | --------------------------- |
| **Content**      | 请求的 JSON 正文；可以包含 `@StartTime` 或 `@EndTime` 占位符。          | `{"from": "@StartTime"}`     |
| **Date format**  | 当正文包含 `@StartTime` 或 `@EndTime` 时显示——配置瞬时值的格式化方式。 | `iso-string`                 |

正文的日期/时间格式配置遵循与[查询参数](#datetime-format-for-query-parameters)相同的设置。

### 响应处理 {#response-handling}

`Return type` 设置控制 OIBus 如何解读服务器的响应。

| 设置        | 描述                                                                                                                             | 示例值           |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------ | ------------------ |
| Return type | `body`：响应作为文本读取；OIBus 会根据 `Content-Type` 头自动检测 JSON 或 XML。`file`：响应正文以二进制文件保存，如提供 `Content-Disposition` 文件名则使用该名称。 | `body`、`file`     |

:::info 文件模式下的文件名
当服务器未提供 `Content-Disposition` 头时，文件会以基于连接器名称、项目名称和随机标识符
自动生成的名称保存。
:::

### 跟踪最大瞬时值 {#tracking-the-maximum-instant}

当返回类型为 `body` 且响应为 JSON 时，OIBus 可以自动跟踪响应中最近的时间戳。这会将下一次
查询的 `@StartTime` 向前推进，以避免重新获取已见过的数据。

| 设置               | 描述                                                              | 示例值                  |
| ------------------ | --------------------------------------------------------------------- | -------------------------- |
| **Track instant**  | 启用从 JSON 响应中提取最大时间戳。                                    | Enabled/Disabled            |
| **JSONPath**       | 用于定位 JSON 响应中时间戳值的表达式。                                | `$.data[*].timestamp`       |
| **Date format**    | OIBus 应如何解读提取出的时间戳值（类型、时区、格式、区域设置）。      | `iso-string`                |

#### 跟踪瞬时值的日期/时间格式 {#tracking-instant-datetime-format}

| 设置         | 描述                                       | 示例值                                                    |
| ------------ | -------------------------------------------- | ------------------------------------------------------------ |
| **Type**     | JSON 字段中日期时间的表示方式。               | `iso-string`、`unix-epoch`、`unix-epoch-ms`、`string`         |
| **Timezone** | 用于解析的时区（仅适用于 `string` 类型）。    | `UTC`、`Europe/Paris`                                        |
| **Format**   | 用于解析的自定义格式模式（仅适用于 `string` 类型）。 | `yyyy-MM-dd HH:mm:ss`                                    |
| **Locale**   | 用于月/日名称解析的区域设置（仅适用于 `string` 类型）。 | `en-En`                                                |

:::info JSONPath
OIBus 使用 [JSONPath Plus](https://github.com/JSONPath-Plus/JSONPath) 库。当多个值与
JSONPath 表达式匹配时，会使用其中的最大时间戳作为新的 `@StartTime`。
:::

## 时间变量 {#time-variables}

以下变量可用于查询参数值、头的值和请求正文：

| 设置          | 描述                                                                     | 示例值                       |
| ------------- | ---------------------------------------------------------------------------- | ------------------------------- |
| `@StartTime`  | 当前查询区间的开始时间。每次查询后会更新为跟踪到的最大瞬时值。               | `2024-01-15T10:00:00.000Z`       |
| `@EndTime`    | 当前查询区间的结束时间（受限于当前时间或子区间结束时间）。                   | `2024-01-15T11:00:00.000Z`       |

:::info 查询拆分
当请求的时间范围较大时，OIBus 会根据**最大读取间隔**限流设置将其拆分为更小的子区间。
每个子区间都有各自的 `@StartTime` / `@EndTime` 对。
:::
