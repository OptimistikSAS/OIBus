# BACnet®/IP

BACnet®（ASHRAE 135）是楼宇自动化和控制设备的标准通信协议 —— 适用于 HVAC 控制器、计量表、照明等类似设备。OIBus 使用
[@bacnet-js/client](https://github.com/bacnet-js/client) 库，通过 UDP 作为 BACnet/IP 客户端进行通信。

## 特定设置 {#specific-settings}

### 连接 {#connection}

| 设置                | 描述                                                                                     | 示例值             |
| ------------------- | ---------------------------------------------------------------------------------------- | ------------------ |
| **端口**             | 用于 BACnet/IP 通信的 UDP 端口。`47808`（`0xBAC0`）是标准的 BACnet/IP 端口。使用相同端口和 **本地网卡** 的连接器共享一个套接字，因此在连接器运行期间，使用未保存设置进行的测试或 **浏览** 也能收到应答。 | `47808`             |
| **APDU 超时**        | 等待设备响应请求的最长时间（毫秒），超过则视为失败。                                      | `6000`              |
| **重试间隔**         | 传输层故障（例如本地套接字本身失败）后，重新连接前等待的时间（毫秒）。                    | `10000`             |
| **发现方式**         | **测试设置** 和 **浏览** 的根级别如何查找设备：**广播 Who-Is** 列出所有应答广播 `Who-Is` 的设备；**目标设备（单播）** 不发送任何 `Who-Is`，直接访问某一台设备；**路由器（单播）** 只向一台 BACnet 路由器发送 `Who-Is`，由其转发到其后的各个网络。 | `广播 Who-Is` |
| **目标设备地址**     | _（选择 **目标设备（单播）** 时显示）_ 设备的 IP 地址（及可选端口）。 | `192.168.1.10` |
| **目标设备实例**     | _（选择 **目标设备（单播）** 时显示）_ 设备的设备实例（`0` – `4194302`）。 | `201` |
| **路由器地址**       | _（选择 **路由器（单播）** 时显示）_ BACnet 路由器的 IP 地址（及可选端口）。 | `192.168.1.20` |
| **广播地址**         | _（选择 **广播 Who-Is** 时显示）_ 用于发现设备的 `Who-Is` 广播地址。启用 BBMD 时将被忽略：此时 `Who-Is` 通过 BBMD 发送。 | `255.255.255.255`  |
| **本地网卡**         | 可选。BACnet/IP 套接字绑定的本地网卡 IP。留空则使用所有网卡（参见[何时设置本地网卡](#when-to-set-the-local-interface)）。 | `192.168.1.50`     |
| **最大并行查询数**   | OIBus 同时读取的项目（或同步分组）的最大数量，最多 `16`。对同一设备的请求仍按顺序逐个发送，因此较大的值只会加快分布在多个设备上的项目的读取。 | `1` |

:::tip 使用目标设备而非广播

有些网络根本不转发 BACnet 广播流量（路由子网、VLAN，或某项直接禁用广播的策略），而且设备通常会在其所在子网上以
广播 `I-Am` 应答 `Who-Is`，当 OIBus 位于其他子网时，该广播永远无法到达 OIBus。由于 `ReadProperty`、
`ReadPropertyMultiple` 和 `SubscribeCOV` 都是单播 —— 直接发送到每个项目配置的 **设备地址** —— 因此无论广播
是否可用，实际的数据采集都能正常工作。只有 **测试设置** 和 **浏览** 中的设备列表依赖 `Who-Is`/`I-Am`。**目标设备（单播）**
发现方式则不使用它们：根据设备的地址和实例（与 YABE 相同）直接读取该设备，这只需要普通的 IP 路由即可 —— 与
`ReadProperty` 已经要求的可达性相同，无需 BBMD。

对于[BACnet 路由器后面的设备](#devices-behind-a-bacnet-router)，**路由器（单播）** 发现方式只向路由器发送
`Who-Is`。设备仍以 `I-Am` 应答，而位于其他子网的路由器通常会在其所在子网上广播这些应答：请同时启用
[BBMD](#bbmd-foreign-device-registration)。`Who-Is` 仍发送给路由器，由 BBMD 将应答带回 OIBus。

:::

### 何时设置本地网卡 {#when-to-set-the-local-interface}

OIBus 在 BACnet 端口上打开一个 UDP 套接字。**本地网卡** 为空时，套接字监听所有网卡，并由操作系统选择每个请求
发出的网卡。在以下情况下，请将其设置为连接 BACnet 网络的网卡的 IP 地址：

- **OIBus 主机有多块网卡** —— 办公网络和 OT 网络、VPN、Docker 或 Hyper-V 虚拟网卡。发往 `255.255.255.255`
  的广播 `Who-Is` 只会从一块网卡发出（通常是默认路由所在的网卡），其他网卡上的设备永远收不到。
- **设备应答到一个它们无法访问的地址**，因为操作系统选择了另一块网卡的地址作为请求的源地址。

其他情况请留空。将 **广播地址** 设置为子网自身的广播地址（例如 `172.27.23.255`）通常就足以让操作系统选对网卡。

:::caution Linux
在 Linux 上，绑定到某个 IP 地址的套接字收不到任何广播：设备广播的 `I-Am` 应答和 COV 通知都会丢失。在 Linux 上，
仅在使用 **目标设备（单播）** 发现方式且项目采用轮询时设置 **本地网卡**，否则请确认发现和 COV 仍然正常。Windows
会将广播投递给绑定到其某块网卡的套接字。
:::

### 轮询与 COV 订阅 {#polling-and-cov-subscriptions}

每个项目的**扫描模式**决定其采集方式，与其他南向连接器完全一致：

- 常规扫描模式（例如 `Every 1 min`）会 **轮询** 该项目 —— 每次扫描模式触发时，OIBus 发送一次 `ReadProperty` 或
  `ReadPropertyMultiple` 请求。
- 保留的 **Subscription** 扫描模式会将项目切换为 **变化上报（COV）**模式 —— OIBus 只需订阅一次，
  设备在值发生变化时主动推送新值，而不再被轮询。

在同一扫描周期内到期的项目会按物理设备分组，并通过每批一次 `ReadPropertyMultiple` 请求一起读取，而不是每个点
发送一次请求。如果设备拒绝 `ReadPropertyMultiple`（许多小型控制器未实现该服务），则改为使用 `ReadProperty`
逐个读取属性。当设备对某个属性返回错误（未知对象或属性）时，只跳过该项目并在日志中记录警告，请求中的其他项目
仍会被采集。

| 设置                     | 描述                                                                                                                       | 示例值 |
| ------------------------ | ---------------------------------------------------------------------------------------------------------------------- | ------ |
| **每次请求最大对象数**    | OIBus 在向一个设备发送的单次 `ReadPropertyMultiple` 请求中打包的最大对象/属性组合数量，以及单次 `ReadRange` 请求读取的趋势日志记录数量。如果设备拒绝过大的请求（例如不支持 APDU 分段），请降低此值。 | `20`   |
| **COV 订阅有效期**        | 请求的 COV 订阅有效期（秒）。`0` 表示请求一个永不过期的订阅。                                                              | `300`  |
| **COV 续订提前量**        | 在有限有效期的 COV 订阅到期前多少秒，OIBus 会将其续订，但绝不会早于有效期过半之前。当有效期为 `0` 时无效。                 | `60`   |

COV 订阅或续订失败时（例如设备离线），OIBus 会不断重试直到成功：先在 **重试间隔** 后重试，之后每次间隔加倍，最长
每 10 分钟一次。只有第一次失败会记录为警告，后续失败以 debug 级别记录，失败后重新成功时会再次记录。设备只能保存有限数量的
COV 订阅，因此连接器停止时 OIBus 会取消其订阅；在网络故障后重新连接时，OIBus 会续订原有订阅，而不是新增订阅。

### 数据限流 {#data-throttling}

适用于处于 **Subscription** 扫描模式的项目 —— 传入的 COV 通知会被缓冲，并按批次而非逐条刷新到 北向缓存。

| 设置             | 描述                                       | 示例值 |
| ---------------- | ------------------------------------------ | ------ |
| 刷新前的消息数   | 刷新到 北向缓存之前累积的 COV 通知数量   | `1000` |
| 刷新间隔         | 自动刷新累积消息之间的延迟时间（毫秒）      | `1000` |

### BBMD / 外部设备注册 {#bbmd-foreign-device-registration}

**BBMD**（BACnet 广播管理设备）在不同的 BACnet/IP 子网之间转发广播消息 ——
例如 `Who-Is` 发现请求和 COV 通知。当 OIBus 与目标设备不在同一个本地 IP 广播域时（例如路由子网、VLAN 或 VPN
链路），请启用此选项。

| 设置             | 描述                                                                     | 示例值           |
| ---------------- | ------------------------------------------------------------------------- | ---------------- |
| **启用**          | 将 OIBus 注册为远程 BBMD 的外部设备，而不是在本地子网上广播。            | 启用/禁用         |
| **BBMD 地址**     | _（启用后显示）_ 要注册的 BBMD 的 IP 地址（及可选端口）。                | `10.0.0.1:47808` |
| **外部设备 TTL**  | _（启用后显示）_ 外部设备注册的有效期（秒）。OIBus 会在到期前自动续订。  | `900`             |

启用后，若发现方式为**广播 Who-Is**，设备发现（**测试设置**、**浏览**的根级别）会通过 BBMD 进行，而不是简单的本地
广播。

即使连接器未运行，**测试设置**和项目的 **测试** 也会先将 OIBus 注册为外部设备：BBMD 只会在已注册的设备之间转发
广播。如果 BBMD 拒绝注册（或没有响应），测试会失败并显示该错误。

:::note BBMD 不仅仅用于发现

注册为外部设备对 **COV 订阅** 同样重要：设备通常会在其自身子网上以本地广播方式发送
`UnconfirmedCOVNotification`，而不是定向单播给订阅者。如果没有外部设备注册，即使建立订阅所用的单播
`SubscribeCOV` 请求成功了，这些通知也永远无法从远程子网到达 OIBus。因此，即使发现方式为**目标设备（单播）**，
BBMD 也可以保持启用 —— 这两个设置解决的是不同的问题：一个关乎 OIBus 如何主动发起请求（发现），另一个
关乎远程广播流量能否到达 OIBus（COV 接收）。

:::

## 项目设置 {#item-settings}

每个项目对应一个设备上的一个 BACnet 对象属性。

| 设置           | 描述                                                                             | 示例值           |
| -------------- | -------------------------------------------------------------------------------- | ---------------- |
| **设备地址**    | 目标设备的 IP 地址（及可选端口）；对于[路由设备](#devices-behind-a-bacnet-router)，则为其 BACnet 路由器的地址。 | `192.168.1.10`   |
| **设备实例**    | 设备的 BACnet 实例编号。用于标识和日志记录；请求实际按 IP 地址寻址，而非此编号。 | `10`              |
| **对象类型**    | 要读取的 BACnet 对象类型。                                                       | `模拟输入`        |
| **对象实例**    | 对象在设备内的实例编号。                                                         | `1`               |
| **属性**        | 要读取的对象属性。                                                               | `当前值`          |
| **设备时区**    | _（趋势日志）_ 设备时钟所用的时区：其[趋势日志](#history-from-trend-logs)记录以设备本地时间标记时间戳，此设置会将其转换为准确的时刻。每个项目单独设置，因为不同设备的时钟设置可能不同。 | `Europe/Paris` |
| **路由设备**    | 设备位于路由器之后的另一个 BACnet 网络上。启用后显示下面两个设置。               | 启用/禁用         |
| **网络号**      | _（路由设备）_ 设备所在网络的 BACnet 网络号。                                    | `2`               |
| **MAC 地址**    | _（路由设备）_ 设备在该网络上的地址：MS/TP 为十进制站号，其他网络为以冒号分隔的十六进制字节。 | `5`               |

:::note 对象类型

`模拟输入`、`模拟输出`、`模拟值`、`二进制输入`、`二进制输出`、`二进制值`、`多状态输入`、`多状态输出`、
`多状态值`、`累加器`、`脉冲转换器`、`控制回路`、`整数值`、`正整数值`、`大模拟值`、`字符串值`：这些对象每次读取一个
属性，通过轮询或 COV 采集。

`趋势日志`：项目采集趋势日志中的记录——参见[从趋势日志获取历史数据](#history-from-trend-logs)。**属性** 不适用，
因此会被隐藏。

其他 BACnet 对象类型（计划表、日历、文件等）不受此连接器支持。

:::

:::note 属性

`当前值`（默认）、`状态标志`、`可靠性`、`停用`、`单位`。

`状态标志` 以四个 `0`/`1` 字符发送，按 BACnet 顺序依次为 in-alarm、fault、overridden、out-of-service：
`0100` 表示对象处于故障状态。`可靠性` 和 `单位` 以其 BACnet 枚举编号发送。

对于处于 **Subscription** 扫描模式的项目，`当前值` 和 `状态标志` 通过标准的 `SubscribeCOV` 服务订阅，所有
支持 COV 的设备都支持该服务。其他属性使用 `SubscribeCOVProperty`，这是一个许多设备并未实现的可选服务：当设备
拒绝该服务时，OIBus 会记录一条警告，建议改用普通扫描模式轮询该项目。这类属性订阅在设备上永不过期；OIBus 仍会
按照与其他 COV 订阅相同的节奏续订，并在项目被删除或连接器停止时取消订阅。

:::

:::note 测试项目

点击 **测试** 会直接从项目的 **设备地址** 读取该项目，不发送任何 `Who-Is`。设备拒绝读取时，测试会显示解码后的
错误，例如设备没有该对象时显示 `OBJECT/UNKNOWN_OBJECT`：请检查项目的对象类型和对象实例。

:::

## 从趋势日志获取历史数据 {#history-from-trend-logs}

**趋势日志**对象在设备内部按固定间隔或在值变化时记录另一个对象的值，保存在一个带时间戳的记录缓冲区
中。**对象类型** 为 `趋势日志` 的项目会采集这些记录，而不是读取当前值：OIBus 读取趋势日志的缓冲区
（`ReadRange`），并以记录时间发送每条记录。

- 使用普通扫描模式时，每次运行都会采集自上次运行以来记录的数据，与其他历史项目相同：项目的 **最大读取间隔**、
  **读取延迟** 和时间偏移量均适用。
- 在[历史查询](../history-queries.md)中，BACnet 南向连接器的趋势日志可以补全所请求的时间范围，前提是设备仍保存
  着这些记录——趋势日志缓冲区大小固定，最旧的记录会被最先删除。
- 趋势日志项目不能使用 **Subscription** 扫描模式：在该模式下只会记录一条警告。

缓冲区从最新的记录开始向前读取，每个 `ReadRange` 请求读取 **每次请求最大对象数** 条记录，直到遇到早于请求范围的记录。

:::caution 设备时区
BACnet 设备以其本地时间记录数据，不带时区信息。请将每个趋势日志项目的 **设备时区** 设置为其设备时钟所用的时区，
否则每条记录都会偏移相应的时差。
:::

## BACnet 路由器后面的设备 {#devices-behind-a-bacnet-router}

许多楼宇控制器本身并不在 IP 网络上：它们位于 MS/TP（RS-485）总线或其他 BACnet 网络上，处在一个 BACnet
路由器（通常是楼宇的监控控制器）之后。这类设备没有 IP 地址；OIBus 通过路由器访问它，项目设置如下：

| 设置         | 值                                                                                                                                         |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------ |
| **设备地址** | 路由器的 IP 地址（及端口）。                                                                                                               |
| **路由设备** | 启用。                                                                                                                                     |
| **网络号**   | 设备所在网络的 BACnet 网络号，与路由器上的配置一致（`1` – `65534`）。                                                                      |
| **MAC 地址** | 设备在该网络上的地址：MS/TP 设备为其站号，十进制（`0` – `255`）；其他网络为以冒号分隔的十六进制地址字节（BACnet/IP 设备为 `0A:00:00:05:BA:C0`：IP 地址加端口）。 |

用于发现的 `Who-Is` 是全局广播，路由器会将其转发到其后的各个网络：**浏览** 会列出路由设备及其网络号和 MAC
地址，**测试设置** 则以 `192.168.1.20, network 2, MAC 5` 的形式显示它们。通过 BBMD 时，`Who-Is` 在每个子网上
仍是本地广播，因此无法以这种方式发现路由设备：请改用 **路由器（单播）** 发现方式；当路由器位于其他子网时，请保持
BBMD 启用。**目标设备（单播）** 发现方式无法访问路由设备。

:::caution 路由设备的 COV 订阅
OIBus 使用的 BACnet 库（`@bacnet-js/client` 3.3.2）发送 COV 订阅请求以及读取趋势日志的 `ReadRange` 请求时，
跳数为 `0`，会被路由器丢弃。该问题已在库中修复但尚未发布：在 OIBus 集成该更新之前，请对路由设备上
的项目使用轮询扫描模式——在 **Subscription** 扫描模式下，它们只会记录一条警告——且无法读取路由设备的趋势日志。
:::

## 发现设备和对象 {#discovering-devices-and-objects}

点击 **浏览** 以交互方式浏览 BACnet 网络，而无需手动输入设备和对象标识符：

1. 在根级别，OIBus 会列出设备及其名称和实例编号。发现方式为**目标设备（单播）**时，列出的就是该设备，不发送任何
   `Who-Is`；发现方式为**路由器（单播）**时，OIBus 只向路由器发送一条 `Who-Is` 请求；否则会广播该请求（若启用了
   BBMD，则通过 BBMD 转发）。随后列出所有响应的设备。`Who-Is` 是全局广播，因此[BACnet 路由器后面的设备](#devices-behind-a-bacnet-router)也会被列出。
2. 选择一个设备会读取其对象列表，并显示该设备暴露的每个对象，同时在可获取时附上其当前值。如果设备无法在一次
   响应中发送完整的对象列表（不支持分段，在 MS/TP 中很常见），则会逐条读取该列表。

在连接器自身的设置页面使用 **测试设置**，可运行与设备发现相同的操作，作为一次快速的连通性检查，而无需打开完整
的浏览窗口。发现方式为**目标设备（单播）**时，它会读取设备名称，若设备未以配置的设备实例应答则测试失败。
