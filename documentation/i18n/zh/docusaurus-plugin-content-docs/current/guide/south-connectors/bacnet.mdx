# BACnet®/IP

BACnet®（ASHRAE 135）是楼宇自动化和控制设备的标准通信协议 —— 适用于 HVAC 控制器、计量表、照明等类似设备。OIBus 使用
[@bacnet-js/client](https://github.com/bacnet-js/client) 库，通过 UDP 作为 BACnet/IP 客户端进行通信。

## 特定设置 {#specific-settings}

### 连接 {#connection}

| 设置                | 说明                                                                                     | 示例值             |
| ------------------- | ---------------------------------------------------------------------------------------- | ------------------ |
| **本地网卡**         | 用于绑定 BACnet/IP 套接字的本地网络接口 IP。留空则由操作系统选择默认接口。                | `192.168.1.50`     |
| **端口**             | 用于 BACnet/IP 通信的 UDP 端口。`47808`（`0xBAC0`）是标准的 BACnet/IP 端口。               | `47808`             |
| **APDU 超时**        | 等待设备响应请求的最长时间（毫秒），超过则视为失败。                                      | `6000`              |
| **广播地址**         | 当**发现目标地址**和 BBMD 均不适用时，用于设备发现（`Who-Is`）的广播地址。                | `255.255.255.255`  |
| **发现目标地址**     | 可选。设置后，**测试设置** 和 **浏览** 的根级别会直接向该设备发送单播 `Who-Is`，而不再广播。留空则在整个子网广播。 | `192.168.1.10` |
| **重试间隔**         | 传输层故障（例如本地套接字本身失败）后，重新连接前等待的时间（毫秒）。                    | `10000`             |
| **最大并行查询数**   | OIBus 同时读取的数据项（或同步组）的最大数量，最多 `16`。对同一设备的请求仍按顺序逐个发送，因此较大的值只会加快分布在多个设备上的数据项的读取。 | `1` |

:::tip 使用单播发现而非广播

有些网络根本不转发 BACnet 广播流量（路由子网、VLAN，或某项直接禁用广播的策略）。由于 `ReadProperty`、
`ReadPropertyMultiple` 和 `SubscribeCOV` 本身就是单播 —— 直接发送到每个数据项配置的 **设备地址** —— 因此
无论广播是否可用，实际的数据采集都能正常工作。只有 **测试设置** 和 **浏览** 中的设备列表依赖
`Who-Is`/`I-Am`，也只有这两者默认使用广播。设置 **发现目标地址** 会将它们指向某一台具体设备，这只需要普通的
IP 路由即可 —— 与 `ReadProperty` 已经要求的可达性相同，无需 BBMD。

:::

### 轮询与 COV 订阅 {#polling-and-cov-subscriptions}

每个数据项的 **调度模式** 决定其采集方式，与其他 South 连接器完全一致：

- 常规调度（例如 `每 1 分钟`）会 **轮询** 该数据项 —— 每次调度触发时，OIBus 发送一次 `ReadProperty` 或
  `ReadPropertyMultiple` 请求。
- 保留的 **Subscription** 调度会将数据项切换为 **变化上报（Change of Value，COV）** 模式 —— OIBus 只需订阅一次，
  设备在值发生变化时主动推送新值，而不再被轮询。

在同一轮询周期内到期的数据项会按物理设备分组，并通过每批一次 `ReadPropertyMultiple` 请求一起读取，而不是每个点
发送一次请求。如果设备拒绝 `ReadPropertyMultiple`（许多小型控制器未实现该服务），则改为使用 `ReadProperty`
逐个读取属性。当设备对某个属性返回错误（未知对象或属性）时，只跳过该数据项并在日志中记录警告，请求中的其他数据项
仍会被采集。

| 设置                     | 说明                                                                                                                       | 示例值 |
| ------------------------ | ---------------------------------------------------------------------------------------------------------------------- | ------ |
| **每次请求最大对象数**    | OIBus 在向一个设备发送的单次 `ReadPropertyMultiple` 请求中打包的最大对象/属性组合数量。如果设备拒绝过大的请求（例如不支持 APDU 分段），请降低此值。 | `20`   |
| **COV 订阅有效期**        | 请求的 COV 订阅有效期（秒）。`0` 表示请求一个永不过期的订阅。                                                              | `300`  |
| **COV 续订提前量**        | 在有限有效期的 COV 订阅到期前多少秒，OIBus 会将其续订，但绝不会早于有效期过半之前。当有效期为 `0` 时无效。                 | `60`   |

COV 订阅或续订失败时（例如设备离线），OIBus 会不断重试直到成功：先在 **重试间隔** 后重试，之后每次间隔加倍，最长
每 10 分钟一次。只有第一次失败会记录为警告，后续失败以 debug 级别记录，失败后重新成功时会再次记录。设备只能保存有限数量的
COV 订阅，因此连接器停止时 OIBus 会取消其订阅；在网络故障后重新连接时，OIBus 会续订原有订阅，而不是新增订阅。

### 数据节流 {#data-throttling}

适用于处于 **Subscription** 调度模式的数据项 —— 传入的 COV 通知会被缓冲，并按批次而非逐条刷新到 North 缓存。

| 设置             | 说明                                       | 示例值 |
| ---------------- | ------------------------------------------ | ------ |
| 刷新前的消息数   | 刷新到 North 缓存之前累积的 COV 通知数量   | `1000` |
| 刷新间隔         | 自动刷新累积消息之间的延迟时间（毫秒）      | `1000` |

### BBMD / 外部设备注册 {#bbmd-foreign-device-registration}

**BBMD**（BACnet Broadcast Management Device，BACnet 广播管理设备）在不同的 BACnet/IP 子网之间转发广播消息 ——
例如 `Who-Is` 发现请求和 COV 通知。当 OIBus 与目标设备不在同一个本地 IP 广播域时（例如路由子网、VLAN 或 VPN
链路），请启用此选项。

| 设置             | 说明                                                                     | 示例值           |
| ---------------- | ------------------------------------------------------------------------- | ---------------- |
| **启用**          | 将 OIBus 注册为远程 BBMD 的外部设备，而不是在本地子网上广播。            | 启用/禁用         |
| **BBMD 地址**     | _（启用后显示）_ 要注册的 BBMD 的 IP 地址（及可选端口）。                | `10.0.0.1:47808` |
| **外部设备 TTL**  | _（启用后显示）_ 外部设备注册的有效期（秒）。OIBus 会在到期前自动续订。  | `900`             |

启用后，若未设置**发现目标地址**，设备发现（**测试设置**、**浏览**的根级别）会通过 BBMD 进行，而不是简单的本地
广播。

即使连接器未运行，**测试设置**和数据项的 **测试** 也会先将 OIBus 注册为外部设备：BBMD 只会在已注册的设备之间转发
广播。如果 BBMD 拒绝注册（或没有响应），测试会失败并显示该错误。

:::note BBMD 不仅仅用于发现

注册为外部设备对 **COV 订阅** 同样重要：设备通常会在其自身子网上以本地广播方式发送
`UnconfirmedCOVNotification`，而不是定向单播给订阅者。如果没有外部设备注册，即使建立订阅所用的单播
`SubscribeCOV` 请求成功了，这些通知也永远无法从远程子网到达 OIBus。因此，即使设置了**发现目标地址**，
BBMD 也可以保持启用 —— 这两个设置解决的是不同的问题：一个关乎 OIBus 如何主动发起请求（发现），另一个
关乎远程广播流量能否到达 OIBus（COV 接收）。

:::

## 数据项设置 {#item-settings}

每个数据项对应一个设备上的一个 BACnet 对象属性。

| 设置           | 说明                                                                             | 示例值           |
| -------------- | -------------------------------------------------------------------------------- | ---------------- |
| **设备地址**    | 目标设备的 IP 地址（及可选端口）；对于[路由设备](#devices-behind-a-bacnet-router)，则为其 BACnet 路由器的地址。 | `192.168.1.10`   |
| **设备实例**    | 设备的 BACnet 实例编号。用于标识和日志记录；请求实际按 IP 地址寻址，而非此编号。 | `10`              |
| **对象类型**    | 要读取的 BACnet 对象类型。                                                       | `模拟输入`        |
| **对象实例**    | 对象在设备内的实例编号。                                                         | `1`               |
| **属性**        | 要读取的对象属性。                                                               | `当前值`          |
| **路由设备**    | 设备位于路由器之后的另一个 BACnet 网络上。启用后显示下面两个设置。               | 启用/禁用         |
| **网络号**      | _（路由设备）_ 设备所在网络的 BACnet 网络号。                                    | `2`               |
| **MAC 地址**    | _（路由设备）_ 设备在该网络上的地址：MS/TP 为十进制站号，其他网络为以冒号分隔的十六进制字节。 | `5`               |

:::note 对象类型

`模拟输入`、`模拟输出`、`模拟值`、`二进制输入`、`二进制输出`、`二进制值`、`多状态输入`、`多状态输出`、
`多状态值`。这些类型涵盖了暴露简单标量值的对象；其他 BACnet 对象类型（计划表、日历、趋势日志等）不受此连接器
支持。

:::

:::note 属性

`当前值`（默认）、`状态标志`、`可靠性`、`停用`、`单位`。

`状态标志` 以四个 `0`/`1` 字符发送，按 BACnet 顺序依次为 in-alarm、fault、overridden、out-of-service：
`0100` 表示对象处于故障状态。`可靠性` 和 `单位` 以其 BACnet 枚举编号发送。

对于处于 **Subscription** 调度模式的数据项，`当前值` 和 `状态标志` 通过标准的 `SubscribeCOV` 服务订阅，所有
支持 COV 的设备都支持该服务。其他属性使用 `SubscribeCOVProperty`，这是一个许多设备并未实现的可选服务：当设备
拒绝该服务时，OIBus 会记录一条警告，建议改用普通调度模式轮询该数据项。这类属性订阅在设备上永不过期；OIBus 仍会
按照与其他 COV 订阅相同的节奏续订，并在数据项被删除或连接器停止时取消订阅。

:::

:::note 测试数据项时验证静态绑定

点击 **测试** 会先向数据项的 **设备地址** 直接发送单播 `Who-Is`。如果设备响应，OIBus 会检查返回的设备实例是否
与数据项配置的 **设备实例** 一致，如果不一致则记录一条警告 —— 从而在静态绑定配置错误悄悄导致从（或归因于）
错误设备采集数据之前将其发现。完全不响应 `Who-Is` 的设备（某些受限的配置文件未实现该服务）不会导致测试失败
—— 真正决定测试成败的是 `ReadProperty` 的结果。

:::

## BACnet 路由器后面的设备 {#devices-behind-a-bacnet-router}

许多楼宇控制器本身并不在 IP 网络上：它们位于 MS/TP（RS-485）总线或其他 BACnet 网络上，处在一个 BACnet
路由器（通常是楼宇的监控控制器）之后。这类设备没有 IP 地址；OIBus 通过路由器访问它，数据项设置如下：

| 设置         | 值                                                                                                                                         |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------ |
| **设备地址** | 路由器的 IP 地址（及端口）。                                                                                                               |
| **路由设备** | 启用。                                                                                                                                     |
| **网络号**   | 设备所在网络的 BACnet 网络号，与路由器上的配置一致（`1` – `65534`）。                                                                      |
| **MAC 地址** | 设备在该网络上的地址：MS/TP 设备为其站号，十进制（`0` – `255`）；其他网络为以冒号分隔的十六进制地址字节（BACnet/IP 设备为 `0A:00:00:05:BA:C0`：IP 地址加端口）。 |

用于发现的 `Who-Is` 是全局广播，路由器会将其转发到其后的各个网络：**浏览** 会列出路由设备及其网络号和 MAC
地址，**测试设置** 则以 `192.168.1.20, network 2, MAC 5` 的形式显示它们。通过 BBMD 时，`Who-Is` 在每个子网上
仍是本地广播，因此无法以这种方式发现路由设备：请改为将 **发现目标地址** 设置为路由器。

:::caution 路由设备的 COV 订阅
OIBus 使用的 BACnet 库（`@bacnet-js/client` 3.3.2）发送 COV 订阅请求时跳数（hop count）为 `0`，会被路由器
丢弃。该问题已在库中修复但尚未发布：在 OIBus 集成该更新之前，请对路由设备上的数据项使用轮询调度——在
**Subscription** 调度模式下，它们只会记录一条警告。
:::

## 发现设备和对象 {#discovering-devices-and-objects}

点击 **浏览** 以交互方式浏览 BACnet 网络，而无需手动输入设备和对象标识符：

1. 在根级别，OIBus 会发送一条 `Who-Is` 请求 —— 如果设置了**发现目标地址**则直接发给该设备，否则进行广播
   （若启用了 BBMD，则通过 BBMD 转发）—— 并列出所有响应的设备，包括其名称和实例编号。`Who-Is` 是全局广播，因此[BACnet 路由器后面的设备](#devices-behind-a-bacnet-router)也会被列出。
2. 选择一个设备会读取其对象列表，并显示该设备暴露的每个对象，同时在可获取时附上其当前值。如果设备无法在一次
   响应中发送完整的对象列表（不支持分段，在 MS/TP 中很常见），则会逐条读取该列表。

在连接器自身的设置页面使用 **测试设置**，可运行与设备发现相同的操作，作为一次快速的连通性检查，而无需打开完整
的浏览窗口。
