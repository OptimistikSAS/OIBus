# 西门子 S7

S7 South 连接器通过 **ISO-on-TCP**（RFC1006）使用西门子 S7 通信协议，直接从西门子 S7-200/300/400/1200/1500
PLC 读取数据。它会在每次扫描模式触发时查询 PLC 内存（数据块、输入、输出、标志位、定时器、计数器），
无需经过 OPC 服务器或单独的代理程序。

OIBus 使用 [nodes7](https://github.com/st-one-io/nodes7) 库与 PLC 进行通信。

:::warning 测试版连接器
该连接器目前处于**测试版（beta）**阶段。在生产环境中依赖它之前，请针对您的 PLC 型号和固件对其
进行充分测试。
:::

## 特定设置 {#specific-settings}

| 设置                | 说明                                                                                                                                                    | 示例值          |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------- |
| **Host**            | PLC 的 IP 地址或主机名。                                                                                                                                | `192.168.1.100` |
| **Port**            | 要连接的 ISO-on-TCP 端口（部分网关使用 502，但西门子 PLC 通常使用 `102`）。                                                                             | `102`           |
| **Connection type** | OIBus 向 PLC 呈现的 TSAP（传输服务访问点）身份：`PG`（编程设备）、`OP`（操作面板）或 `S7 Basic`。必须与 PLC 的连接机制/安全设置所允许的连接类型相匹配。 | `S7 Basic`      |
| **Rack**            | CPU 在其机架中的机架号。对于 S7-1200/1500 及独立 CPU，通常为 `0`。                                                                                      | `0`             |
| **Slot**            | CPU 在其机架中的插槽号。对于 S7-1200/1500 通常为 `1`，对于 S7-300/400 通常为 `2`。                                                                      | `1`             |
| **Connect timeout** | 建立连接时等待的最长时间（毫秒）。                                                                                                                      | `10000`         |
| **Request timeout** | 等待读取请求响应的最长时间（毫秒）。                                                                                                                    | `15000`         |
| **Retry interval**  | 连接失败或意外断开后，重试前等待的时间（毫秒）。                                                                                                        | `10000`         |

:::tip Connection type、Rack 和 Slot
在 S7-1200/1500 CPU 上，TIA Portal 中的**保护与安全 &gt; 连接机制**设置控制着允许哪些连接类型
（PG/OP/S7 Basic）——如果 OIBus 无法连接，请检查所选的 **Connection type** 是否在该处被允许。
**Rack**/**Slot** 取决于 CPU 型号及其物理/虚拟位置；如果默认值不起作用，请查阅您的 PLC 文档。
:::

## 项目设置 {#item-settings}

每个项目只有一个 **Address** 设置，使用 nodes7 的地址语法：

| 设置        | 说明                                                      | 示例值      |
| ----------- | --------------------------------------------------------- | ----------- |
| **Address** | 要读取的 PLC 内存地址，使用 nodes7 的地址语法（见下文）。 | `DB1,REAL0` |

### 地址语法 {#address-syntax}

地址的格式为 `[DB<n>,]<type><offset>[.<bitOrArrayLength>][.<arrayLength>]`：

- **`DB<n>,`** ——用于寻址数据块所需的前缀（例如 `DB1,`）；省略它则改为寻址某个 PLC 范围的内存
  区域（见下文）。
- **`<type>`** ——要在该偏移量处读取的数据类型。常见类型：`X`（单个位——需要位偏移量）、
  `BYTE`/`B`、`INT`/`I`、`DINT`/`DI`、`WORD`/`W`、`DWORD`/`D`、`REAL`/`R`、`CHAR`/`C`、`STRING`/`S`。
- **`<offset>`** ——数据块或内存区域内的字节偏移量。
- **`.<bitOrArrayLength>`** ——对于 `X` 类型，表示位偏移量（`0`–`7`）；对于其他类型，表示可选的
  数组长度，用于将若干个连续的值作为数组读取。

在数据块之外，相同的 `<type><offset>` 语法适用于 PLC 内存区域，这些区域由各自的前导字母标识：
`M`/`MB`/`MW`/`MD`/`MR`（Merker/存储器位、字节、字、双字、实数）、`I`/`E`（输入）、`Q`/`A`（输出）、
`T`（定时器）、`C`（计数器）。

| 地址           | 含义                                                |
| -------------- | --------------------------------------------------- |
| `DB1,REAL0`    | 数据块 1 中字节偏移量 0 处的单个 `REAL`（浮点数）。 |
| `DB1,INT2`     | 数据块 1 中字节偏移量 2 处的单个 `INT`。            |
| `DB1,X4.0`     | 数据块 1 中字节偏移量 4、位 0 处的单个位。          |
| `DB1,REAL0.20` | 从字节偏移量 0 开始的 20 个 `REAL` 值组成的数组。   |
| `M32.2`        | Merker 存储器中字节偏移量 32、位 2 处的单个位。     |
| `MR4`          | Merker 存储器中字节偏移量 4 处的单个 `REAL`。       |

有关完整的地址语法（包括定时器、计数器和字符串类型），请参阅
[nodes7 README](https://github.com/st-one-io/nodes7#usage-example)。

:::note 值以文本形式读取
无论 PLC 的数据类型是什么，OIBus 都会将每个 S7 项目的值报告为字符串（例如 `"3.14"`、`"true"`）。
在配置下游的转换器或 North 连接器时请考虑到这一点。
:::

## 缓存策略 {#caching-strategy}

与其他 IoT 系列连接器一样，S7 项目支持按项目配置[缓存策略](./common-settings.md#caching-strategy)
（`All values`、`On change`、`Threshold`），以过滤实际被缓存并转发的读取值。
