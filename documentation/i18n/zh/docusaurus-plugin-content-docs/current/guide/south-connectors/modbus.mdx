# Modbus

Modbus 是一种用于 PLC 网络的通信协议。它最初是为 RS232、RS422 和 RS485 等串行接口开发的，后来扩展支持 TCP 模式。OIBus
使用 [jsmodbus](https://github.com/Cloud-Automation/node-modbus) 库，**仅支持 TCP 模式**。

## 特定设置 {#specific-settings}

### 连接配置 {#connection-configuration}

| 设置             | 描述                                                                                                                                                                       | 示例值   |
| ---------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------- |
| **主机**               | Modbus 服务器所在机器的 IP 地址或主机名。                                                                                                                              | `192.168.1.100` |
| **端口**               | 用于连接的端口（默认为 502）。                                                                                                                                      | `502`           |
| **连接超时**  | 等待连接建立的最长时间（以毫秒为单位）。                                                                                                                          | `10000`         |
| **重试间隔**    | 连接失败后，两次重连之间等待的时间（以毫秒为单位）。                                                                                                | `10000`         |
| **网络超时**   | 在空闲连接上开始发送 TCP keepalive 探测之前等待的延迟（以毫秒为单位）。用于保持连接在防火墙和 NAT 设备关闭空闲套接字的情况下不中断。 | `15000`         |
| **从站 ID**           | 标识 Modbus 源机器（默认为 1）。                                                                                                              | `1`             |
| **地址偏移量**     | 大多数 PLC 没有偏移量（Modbus 选项）。有些 PLC 的地址范围可能从 1 而不是 0 开始（JBus 选项）                                                                                          | `Modbus`        |

### 查询优化 {#query-optimisation}

| 设置                  | 描述                                                                                                                                                                                                                                             | 示例值    |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------- |
| **分组批量查询？** | 启用后，将相同 Modbus 类型的条目合并为尽可能少的请求，而不是为每个条目发送一个请求。默认禁用。                                                                                                           | 启用/禁用 |
| **分组间隙**         | _（仅在启用**分组批量查询？**时显示）_ 将相同类型的非连续条目合并为单个 Modbus 请求时允许的最大地址间隙（以寄存器为单位）。设置为 `0` 表示仅批量处理严格连续的地址（默认）。 | `0` – `100`      |

在默认禁用**分组批量查询？**的情况下，OIBus 为每个条目发送一个 Modbus 请求 —— 完全不进行合并。
启用后，OIBus 会将地址连续的相同 Modbus 类型（线圈、离散输入、输入寄存器、保持寄存器）条目
合并为单个请求，从而减少与设备之间的往返次数。

当**分组间隙 > 0** 时，几乎（但并非完全）连续的条目也会被合并。例如，地址为 1、3 和 5 的三个保持寄存器
通常需要三个单独的请求。设置分组间隙为 2 后，这三个寄存器可在一个请求中读取（两个中间的填充寄存器会被获取但丢弃）。

:::tip 何时增加分组间隙

较大的间隙会以在线路上多传输少量数据（填充寄存器）为代价，换取更少的 TCP 往返次数。当设备响应较慢或网络延迟较高时，这通常是有益的。如果最小化流量比最小化往返次数更重要，请将其保持为 `0`。

:::

:::info 协议限制

无论分组间隙如何设置，OIBus 每次请求都不会超过 Modbus 规范限制：

- **线圈 / 离散输入（FC01 / FC02）：** 最多 2000 位。
- **输入寄存器 / 保持寄存器（FC03 / FC04）：** 最多 125 个字。

超出这些限制的范围将自动拆分为多个请求。

:::

## 条目设置 {#item-settings}

| 设置                | 描述                                                                                                                                                                           | 示例值      |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------ |
| Address                | 设备内寄存器的地址，不包含前导数据类型数字。接受纯十进制数字（例如 `1`）或以 `0x` 为前缀的十六进制数字（例如 `0x0001`）。 | `0x0001`           |
| Modbus type            | 指定是_线圈_、_离散输入_、_输入寄存器_还是_保持寄存器_（默认）。                                                                                 | `Holding Register` |
| Data type              | 适用于_保持寄存器_或_输入寄存器_。定义从寄存器获取的数据类型（Bit、UInt16、Int16、UInt32、Int32、Big UInt64、Big Int64、Float、Double）。  | `UInt16`           |
| Bit index              | （_仅 Bit 数据类型_）要从读取值中提取的位索引（0 到 15）。                                                                                                | `0` to `15`        |
| Multiplier Coefficient | 对获取的值进行乘法运算（默认为 1）。                                                                                                                                        | `1`                |

:::info 关于 Modbus 地址

PLC 文档通常使用**莫迪康约定表示法（Modicon Convention Notation，MCN）**：一个十进制数字，其**首位数字表示数据类型**，其余数字表示寄存器编号。

| 首位数字 | 数据类型        |
| ------------- | ---------------- |
| `0`           | Coil             |
| `1`           | Discrete Input   |
| `3`           | Input Register   |
| `4`           | Holding Register |

OIBus 期望地址**不包含前导类型数字**，以纯十进制数字或以 `0x` 为前缀的十六进制数字形式输入。数据类型通过**Modbus 类型**字段单独声明。

**将 MCN 地址转换为 OIBus 地址：**

1. 从 MCN 地址中去除前导类型数字。
2. 直接输入剩余的数字。十进制和以 `0x` 为前缀的十六进制均可接受。

**示例：**

| MCN 地址 | 去除类型数字 | OIBus 地址     | Modbus 类型      |
| ----------- | ---------------- | ----------------- | ---------------- |
| `40001`     | `0001`           | `1` or `0x0001`   | Holding Register |
| `40100`     | `0100`           | `100` or `0x0064` | Holding Register |
| `30005`     | `0005`           | `5` or `0x0005`   | Input Register   |
| `00157`     | `0157`           | `157` or `0x009D` | Coil             |

**MCN 地址范围：**

| 类型             | 标准（5 位数字） | 扩展（6 位数字） |
| ---------------- | ------------------- | ------------------- |
| Coil             | 00001 – 09999       | 000001 – 065535     |
| Discrete Input   | 10001 – 19999       | 100001 – 165535     |
| Input Register   | 30001 – 39999       | 300001 – 365535     |
| Holding Register | 40001 – 49999       | 400001 – 465535     |

**地址偏移量：** **地址偏移量**设置控制寄存器编号是从 0（Modbus）还是从 1（JBus）开始。大多数 PLC 使用 Modbus 约定（无偏移量）。如果数值看起来偏移了一位，请检查您的设备文档。

:::

有关更多详细信息，请参阅 [莫迪康约定表示法（MCN）](https://www.modbus.org/docs/PI_MBUS_300.pdf)。
