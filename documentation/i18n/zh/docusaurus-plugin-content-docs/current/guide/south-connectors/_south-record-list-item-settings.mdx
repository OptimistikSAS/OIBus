## 分组设置 {#group-settings}

项目可以被组织到分组中。每个分组定义一个共享的采集计划和默认的限流设置。同一分组中的项目仍然是**依次逐个**获取的——分组只是为各个项目提供了可被覆盖的通用默认值。

| 设置           | 描述                                                                                                                                       | 示例值             |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------- |
| **名称**       | 该连接器内分组的唯一标签。                                                                                                                 | `Group A`                 |
| **扫描模式**  | 用于采集分组内所有项目的计划。                                                                                                                  | `Every 1 min`             |
| **限流** | 分组内项目继承的默认限流值（最大读取间隔、读取延迟、开始时间偏移、结束时间偏移、恢复策略）。 | `3600, 200, 0, 0, oldest` |

## 项目设置 {#item-settings}

每个项目都可以单独配置自己的查询参数，以及（可选的）用于增量读取源数据的追踪时刻。项目会从其所属分组继承扫描模式和限流默认值，但通过禁用**与分组同步**，可以为每个项目单独覆盖各项设置。

### 查询配置 {#query-configuration}

查询字段接受标准 SQL 语法，并支持内部变量以增强数据检索的弹性和性能优化。

#### 查询变量 {#query-variables}

| 设置      | 描述                                                                                           | 示例值              |
| ------------ | ----------------------------------------------------------------------------------------------------- | -------------------------- |
| `@StartTime` | 初始化为首次执行时间，之后更新为被追踪字段的最新时间戳 | `2024-01-15T10:00:00.000Z` |
| `@EndTime`   | 设为当前时间（`now()`），或在查询被拆分时设为子区间的结束时间                              | `2024-01-15T11:00:00.000Z` |

查询示例：

```sql
SELECT device_id, value, reading_time
FROM sensor_data
WHERE reading_time > @StartTime
AND reading_time < @EndTime
ORDER BY reading_time
```

:::info 查询拆分
为处理大数据集，查询可以根据**最大读取间隔**限流设置，自动拆分为更小的基于时间的分块。
:::

### 追踪时刻配置 {#tracking-instant-configuration}

查询返回的每一列都会原样发送到下游——OIBus 不会对其进行解析、重新格式化或重塑。唯一可选的项目级设置是**追踪时刻**：一个字段，其在一批数据中的最大值将成为下一次查询的 `@StartTime`，用于实现增量采集。

| 设置           | 描述                                                                                                    | 示例值               |
| ----------------- | -------------------------------------------------------------------------------------------------------------- | ---------------------------- |
| **追踪时刻** | 启用后使用下方字段进行增量采集。禁用时，每次查询都会重新读取完整的结果集。 | 启用/禁用            |
| **字段名称**    | 你的 SELECT 语句中要追踪的日期时间列的名称                                                  | `timestamp`、`reading_time` |
| **类型**          | 该列的数据类型。可用的取值因连接器而异——请参见下方连接器专属说明。        | `iso-string`、`unix-epoch`  |
| **时区**      | 存储的日期时间的时区（用于字符串/日期类型）                                                        | `UTC`、`Europe/Paris`       |
| **格式**        | 基于字符串的日期时间的格式模式                                                      | `yyyy-MM-dd HH:mm:ss`       |
| **区域设置**        | 格式元素所用的区域设置（例如月份名称）                                                 | `en_US`、`fr_FR`            |

:::warning 类型一致性要求
在查询中使用日期时间转换时，请确保 SELECT 列表和 WHERE 子句中的类型保持一致：

有问题的做法（可能导致意外行为）：

```sql
SELECT value, CONVERT(datetime, string_field) AS timestamp
FROM table
WHERE string_field > @StartTime
```

推荐的做法：

```sql
SELECT value, CONVERT(datetime, string_field) AS timestamp
FROM table
WHERE CONVERT(datetime, string_field) > @StartTime
```

:::

### 数据流处理过程 {#data-flow-process}

1. OIBus 依次执行每个已配置的查询。
2. 数据行按原样发送到下游——不会对任何列进行解析、重新格式化或重塑。
3. 如果启用了**追踪时刻**，则提取该批数据中被追踪字段的最大值，转换为 UTC，并存储为下一次的
   `@StartTime`。
4. 数据以记录列表内容的形式（每行一条）发送到已配置的北向连接器。
5. 若要将该数据渲染为 CSV（或其他格式），请为北向连接器或历史查询附加一个兼容的转换器——例如
   **record-list-to-csv**。详见 [转换器](../engine/transformers.mdx)。

:::tip 最佳实践

1. 在追踪时刻时，选择取值一致且递增的字段。
2. 对于字符串日期时间，确保数据库存储与查询变量之间的格式匹配。
3. 在日期时间字段上添加索引以提升查询性能。
4. 使用最大读取间隔将大的时间范围拆分为可管理的分块。

:::
