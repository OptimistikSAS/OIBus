# OIAnalytics 注册

将 OIBus 注册到 OIAnalytics® 是可选的，但它可以解锁集中式远程管理功能：配置同步、远程命令执行、
日志转发和简化的升级流程——所有这些都无需对 OIBus 所在机器进行入站访问。

## 注册流程 {#registration-process}

<div style={{ textAlign: 'center' }}>
  ![OIAnalytics 注册流程](../../../static/img/guide/installation/oianalytics-registration.svg)
</div>

**1 – 2 · 发起注册**

- 在 OIBus 中导航到**引擎**页面。
- 点击 **OIAnalytics** 按钮，填写注册表单，然后点击**注册**。

**3 · 在 OIAnalytics 中验证**

- 在 OIAnalytics 中，前往**配置 → OIBus**，找到待处理的注册请求。
- 输入 OIBus 注册界面上显示的**六位字符代码**（该代码也会发送到 OIAnalytics 中配置的电子邮件地址）。
- 授予所需的权限——**API 访问权限是必须的**。

**4 – 5 · 完成**

- OIBus 轮询 OIAnalytics 以确认注册是否已获批准。
- 注册成功后，OIBus 会将其完整配置（不含密钥——参见[密钥管理](#secret-management)）发送给 OIAnalytics。
- 如果在[引擎设置 → 日志参数](../engine/engine-settings.mdx#logging-parameters)中启用了日志转发，转发将随之开始。

**6 – 7 · 持续同步**

- OIBus 定期轮询 OIAnalytics 以获取新命令。
- 每条命令都会被验证、执行并确认。

| 设置                    | 说明                                         | 默认值 |
| -------------------------- | --------------------------------------------------- | ------- |

## 在连接器中使用注册信息 {#using-the-registration-in-connectors}

注册完成后，[OIAnalytics South 连接器](../south-connectors/oianalytics.mdx)、
[OIAnalytics North 连接器](../north-connectors/oianalytics.md)以及历史查询都可以复用注册设置，
而无需单独配置连接参数：

1. 打开连接器或历史查询的配置。
2. 启用**使用 OIAnalytics 注册**。
3. 保存——主机、身份验证和代理设置将自动从注册信息中继承。

## 日志转发 {#log-forwarding}

当在[引擎设置 → 日志参数](../engine/engine-settings.mdx#logging-parameters)中启用了 OIAnalytics 日志级别后，
OIBus 会将其日志转发到 OIAnalytics。转发频率和最低日志级别取决于日志配置——日志是按批量发送的，
而非持续流式发送。转发的日志可在 OIAnalytics 的 OIBus 日志页面中进行搜索和过滤，其保留期限遵循
OIAnalytics 的策略。

## 命令架构 {#command-architecture}

### 基于拉取的通信 {#pull-based-communication}

OIBus 使用**拉取模式**——它主动发起与 OIAnalytics 的所有通信。这意味着：

- OIBus 所在机器无需任何入站网络连接。
- 所有流量均通过出站的 **HTTPS（端口 443）**。
- OIBus 按配置的间隔轮询 OIAnalytics，并从响应体中读取所有待处理的命令。

:::info 防火墙要求
只需允许**出站 HTTPS（TCP 443）**访问 OIAnalytics 域名即可，无需任何入站规则。
:::

### 版本升级流程 {#version-upgrade-process}

升级包通过 OIAnalytics 下载，因此 OIBus 所在机器无需直接访问 GitHub。

1. OIBus 接收到包含目标版本的升级命令，并通过 OIAnalytics 下载发行包。
2. OIBus 将包解压到一个临时的 `update` 文件夹，然后关闭自身。此时 OIBus 本身的工作已完成——
   其余流程在启动器一侧进行，一旦它注意到进程已停止即会开始处理。
3. **OIBus 启动器**（`oibus-launcher`）在下一次启动周期检测到 `update` 文件夹中的新二进制文件。
   在替换它们之前，会先备份当前的 OIBus 二进制文件以及匹配升级备份模式的数据文件夹子目录
   （默认是 `cache/` 文件夹——OIAnalytics 可以覆盖此设置），然后启动升级后的 OIBus。
4. 如果升级后的 OIBus 启动失败（崩溃，或未能在大约 30 秒内启动完成），启动器会自动恢复备份的
   二进制文件和文件夹，并重新启动之前的版本。

:::info 启动器架构
`oibus-launcher` 将主 `oibus` 进程作为子进程运行。每当 `oibus` 停止时——无论是正常停止还是异常停止——
启动器都会检查 update 文件夹：如果存在新的二进制文件，就执行升级（如上所述，先进行备份），
否则就直接重启现有的二进制文件。这样可以自动处理升级和崩溃恢复两种情况。
:::

:::danger 磁盘空间要求
在安装新版本之前，启动器会备份当前的二进制文件以及匹配备份模式的文件夹（默认是 `cache/` 文件夹）——
请确保您有足够的可用磁盘空间来容纳这些内容的第二份副本。请核实可用空间，并在低活动时段安排升级。
:::

## 安全架构 {#security-architecture}

### 密钥管理 {#secret-management}

OIBus 采用**零信任模型**，确保密钥（密码、令牌、API 密钥）永远不会以明文形式离开 OIBus 所在机器：

- 当 OIBus 将其配置发送给 OIAnalytics 时，所有密钥在传输前都会被**剥离**。只有非敏感设置会被同步。
- 当通过 OIAnalytics 输入密钥时，它会在浏览器中传输前**立即使用 OIBus 的 RSA 公钥加密**（RSA-OAEP）。
  OIAnalytics 永远不会看到明文值。
- 在 OIBus 所在机器上，密钥以本地加密方式存储。私钥永远不会离开 OIBus 实例。

使用**重新生成加密密钥**命令来轮换 RSA 密钥对。重新生成后，存储在 OIAnalytics 中的密钥必须重新输入，
因为旧的密文将无法再被解密。

:::info 加密细节
**算法**：RSA-OAEP——在注册期间会为每个 OIBus 实例生成唯一的密钥对。

密钥一旦到达 OIBus 所在机器，就会使用 [OIBus 安全模型](../advanced/oibus-security.md)进行存储。
:::

## 故障排除 {#troubleshooting}

| 问题                  | 需检查的内容                                              |
| ---------------------- | ---------------------------------------------------------- |
| 注册失败     | 到 OIAnalytics 的网络连通性和防火墙规则。    |
| 代码未被接受      | 确认六位字符代码是否匹配且未过期。   |
| 命令未执行 | OIAnalytics 中是否已授予命令权限。                |
| 升级失败          | 数据文件夹的可用磁盘空间和写入权限。 |
| 连接错误      | 代理设置、证书信任和防火墙规则。     |
