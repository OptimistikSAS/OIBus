# IP 过滤器

默认情况下,OIBus 只接受来自本地计算机的连接。任何需要访问 OIBus Web 界面或 API 的远程工作站,都必须通过
IP 过滤规则明确允许其 IP 地址。

:::info 本地主机始终被允许
以下地址被永久允许,无法移除:
`127.0.0.1`、`::1`、`::ffff:127.0.0.1`、`::ffff:7f00:1`、`0:0:0:0:0:0:0:1`
:::

## 地址格式 {#address-format}

每条 IP 过滤规则包含一个**地址**字段。OIBus 支持 IPv4、IPv6 和通配符模式。

| 模式                 | 示例            | 匹配范围                                             |
| -------------------- | --------------- | ----------------------------------------------------- |
| 精确 IPv4            | `192.168.1.100` | 仅该特定地址                                         |
| IPv4 通配符          | `192.168.1.*`   | 从 `192.168.1.0` 到 `192.168.1.255` 的所有地址       |
| 精确 IPv6            | `2001:db8::1`   | 仅该特定地址                                         |
| IPv6 前缀通配符      | `2001:db8:*`    | 该前缀下的所有地址                                   |
| 允许所有             | `*`             | 每一个远程地址                                       |

:::note IPv4 和 IPv6 等价性
以 `192.168.1.100` 形式输入的 IPv4 地址会自动同时匹配其 IPv6 映射形式 `::ffff:192.168.1.100`,因此单条规则可以
同时覆盖两种连接类型。
:::

## 管理过滤器 {#managing-filters}

IP 过滤器在 OIBus 界面的**引擎 → IP 过滤器**中进行管理。

每条规则有两个字段:

| 字段         | 描述                                                          |
| ------------ | ------------------------------------------------------------- |
| **地址**     | 要允许的 IP 地址或模式(见上文格式)                          |
| **描述**     | 用于标识该规则的自由文本注释(例如 `Production SCADA server`) |

规则可以随时添加、编辑和删除。更改会立即生效 —— 无需重启。

## 通过 API 添加过滤器 {#adding-a-filter-via-the-api}

过滤器也可以通过编程方式创建。每个 OIBus API 端点都需要身份验证(Basic 或 Bearer 令牌),因此请求必须包含凭证。
以下示例使用 `curl` 添加一条允许特定子网的规则:

```bash title="Allow a specific subnet"
curl --location 'http://localhost:2223/api/ip-filters' \
--user 'admin:<password>' \
--header 'Content-Type: application/json' \
--header 'Accept: application/json' \
--data '{
  "address": "192.168.1.*",
  "description": "Plant network"
}'
```

要允许所有远程地址(在初始设置期间很有用):

```bash title="Allow all IP addresses"
curl --location 'http://localhost:2223/api/ip-filters' \
--user 'admin:<password>' \
--header 'Content-Type: application/json' \
--header 'Accept: application/json' \
--data '{
  "address": "*",
  "description": "Allow all traffic"
}'
```

:::info
有关可用端点的完整列表,请访问 [API 文档页面](../../api/index.mdx)。
:::

:::danger 开放访问与代理服务器
IP 过滤规则适用于**所有**传入连接 —— 包括 OIBus Web 界面和[代理服务器](./engine-settings.mdx#proxy-server)。
因此,允许所有 IP 地址(`*`)也会将代理开放给网络上的每一台机器。代理服务器可以配置为要求自己的用户名/密码
(见[身份验证](./engine-settings.mdx#authentication)),但如果留空,任何可达的主机都可以通过 OIBus 转发任意流量。
在生产环境中,请始终将访问限制在已知的 IP 地址范围内。
:::

:::note 完全禁用 IP 过滤
如果 OIBus 是使用 `--ignoreIpFilters` 标志启动的,所有 IP 过滤都会被绕过,现有规则也不会被应用。设置此标志后,
**IP 过滤器**页面将变为只读,并显示提示信息而非通常的规则列表。
:::

:::tip 最佳实践

- 使用精确地址或能满足需求的最窄通配符(例如使用 `192.168.10.*` 而非 `*`)。
- 为每条规则添加清晰的描述,以便日后识别和清理过期条目。
- 请注意,IP 过滤规则同时保护 Web 界面和[代理服务器](./engine-settings.mdx#proxy-server) —— 授予其中一个的
  访问权限也会授予对另一个的访问权限。
  :::

## 测试 IP 过滤规则 {#test-ip-filter-rules}

在将规则应用于实际运行的实例之前,使用下方的测试工具验证您的规则行为。在**过滤规则**字段中每行输入一条规则,
然后输入您要检查的 IP 地址并点击**测试**。

该测试工具应用与 OIBus 相同的匹配逻辑:

- 本地主机地址始终被视为允许。
- `*` 匹配任何地址。
- `192.168.1.*` 匹配前三个八位组为 `192.168.1` 的任何地址。
- IPv4 地址也会以其 `::ffff:<ipv4>` 的 IPv6 映射形式进行测试。
