# 转换器

**转换器**位于数据源和北向连接器之间。它会在数据放入连接器缓存之前，将传入的数据转换为北向连接器所期望的格式。除了格式转换之外，转换器也是**过滤**北向连接器接收哪些数据的机制——详情参见[数据过滤](../north-connectors/common-settings.md#data-filtering)。

转换器是**在北向连接器上**配置的，位于其设置页面的**转换器**部分。

---

## 配置转换器 {#configuring-a-transformer}

点击转换器部分中的**添加**以打开配置弹窗。三个字段用于引导配置过程。

### 1 — 来源 {#1--source}

选择数据的来源。

| 来源                   | 描述                                                                                       |
| ---------------------- | ------------------------------------------------------------------------------------------ |
| **南向连接器**         | 由某个已配置的南向连接器采集的数据                                                         |
| **OIBus API**          | 通过 REST API 推送到 OIBus 的数据。需要一个数据源 ID（`dataSourceId`）字符串来标识来源系统 |
| **OIAnalytics 设定点** | 从 OIAnalytics 发送的写回命令                                                              |

### 2 — 项目范围（仅限南向连接器） {#2--item-scope-south-connectors-only}

当来源为南向连接器时，您可以限制转换器所应用的项目。

| 范围       | 描述                                     |
| ---------- | ---------------------------------------- |
| **全部项** | 所选南向连接器的每个项目都会经过此转换器 |
| **按组**   | 只处理属于特定分组的项目                 |
| **特定项** | 从搜索列表中手动挑选单个项目             |

:::tip
单个北向连接器可以配置**多个转换器**，各自具有不同的来源和范围。这样您就可以对同一个南向连接器的不同部分应用不同的转换——例如，为一组温度传感器配置一个转换器，为流量计配置另一个转换器。当传入的一批数据混合了由不同转换器覆盖的项目时，OIBus 会自动将其拆分，使每一部分都由实际针对它的转换器处理。
:::

如果同一个项目可能匹配多个转换器（例如一个针对某个分组，另一个针对同一南向连接器的“全部项”），OIBus 会按照以下优先级解析，最具体的优先：

1. 针对该**特定项目**的转换器。
2. 针对该项目所属**分组**的转换器。
3. 针对该南向连接器**所有项目**（未选择分组，也未选择特定项目）的转换器——即兜底转换器。

按此顺序匹配到的第一个已配置转换器将被使用；同一层级内的并列情况按转换器在列表中的位置决定。

### 3 — 转换器 {#3--transformer}

选定来源后，列表会自动过滤，仅显示兼容的转换器。可选项取决于所选南向连接器的类型：

| 南向连接器类型                                                                        | 兼容的标准转换器                                                                          |
| ------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| **OPC UA、OPC Classic、Modbus、ADS、S7、OSIsoft PI、OIAnalytics**（PLC / 历史数据库） | CSV、JSON、MQTT 有效载荷、Modbus 值、OIAnalytics（选择时间精度）、OPCUA 值                |
| **MQTT、REST、SFTP、FTP、Folder Scanner、ODBC、OLEDB**（基于文件 / 查询）             | 时间值（来自 CSV）、MQTT 有效载荷（来自 CSV）、CSV（来自 JSON）、OIAnalytics（来自 JSON） |
| **MySQL、PostgreSQL、MSSQL、Oracle、SQLite、MongoDB**（基于查询，输出行列表）         | CSV（来自记录列表）                                                                       |
| **OIBus API**                                                                         | 时间值（来自 CSV）、MQTT 有效载荷（来自 CSV）、CSV（来自 JSON）、OIAnalytics（来自 JSON） |
| **OIAnalytics 设定点**                                                                | MQTT 有效载荷、Modbus 值、OPCUA 值                                                        |

此列表中还会显示自定义转换器，它们始终由用户命名。此外，**忽略**和**不转换**（见下文）对每种来源类型都可用。

选择转换器后，其设置表单会直接显示在弹窗中。

---

## 标准转换器 {#standard-transformers}

标准转换器是内置的，只需配置即可使用——无需编写代码。

---

### 忽略和不转换 {#ignore-and-no-transform}

这两个转换器对**所有**来源类型都可用，与内容类型无关，且不需要任何配置。

| 转换器     | 行为                                                                                                                                                |
| ---------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| **忽略**   | 丢弃数据。不缓存任何内容，也不向北向连接器发送任何内容。可用于（通过项目/分组范围）屏蔽南向连接器针对某个北向连接器的部分输出，而无需禁用项目本身。 |
| **不转换** | 按原样缓存接收到的数据，不做任何转换。当北向连接器已经接受南向连接器的原生内容类型时使用此选项。                                                    |

---

### 适用于 PLC 和历史数据库南向连接器 {#for-plc-and-historian-south-connectors}

这些转换器处理由 OPC UA、OPC Classic、Modbus、TwinCAT ADS、Siemens S7 和 OSIsoft PI 等连接器产生的结构化**时间值**数组。

每个时间值对象具有如下结构：

```json
{ "pointId": "plant/temp1", "timestamp": "2024-01-15T10:00:00.000Z", "data": { "value": "23.5" } }
```

---

#### CSV {#csv}

将时间值数组转换为 CSV 文件。每一行对应一次读数。三列（点位 ID、时间戳、值）会映射到可配置的列标题。可选的按列 JavaScript 表达式可以在写入之前对各个值进行转换。

##### 设置 {#settings}

| 设置                      | 描述                                                                                                                                               |
| ------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| **文件名**                | 输出文件名；支持 `@CurrentDate`（当前 UTC 时间戳），以及在内容来自南向历史查询时支持 `@QueryStartTime`/`@QueryEndTime`（查询的时间窗口，否则为空） |
| **编码**                  | `UTF_8`、`UTF_8_BOM`、`LATIN_1` 或 `UTF_16_LE`                                                                                                     |
| **第一行作为表头**        | 是否包含列标题行                                                                                                                                   |
| **分隔符**                | 列分隔符                                                                                                                                           |
| **换行符**                | 行结束符（`LF`、`CRLF`、`CR`）                                                                                                                     |
| **引号字符**              | `DOUBLE_QUOTE`、`SINGLE_QUOTE` 或 `NONE`                                                                                                           |
| **转义字符**              | `DOUBLE_QUOTE` 或 `BACKSLASH`                                                                                                                      |
| **点位 ID（引用）的列名** | 点位标识符列的表头标签                                                                                                                             |
| **值的列名**              | 值列的表头标签                                                                                                                                     |
| **时间戳的列名**          | 时间戳列的表头标签                                                                                                                                 |
| **时间戳输出类型**        | 输出格式（`iso-string`、`unix-epoch`、`unix-epoch-ms`、`string`）                                                                                  |
| **时间戳输出格式**        | 类型为 `string` 时的自定义模式（例如 `yyyy-MM-dd HH:mm:ss.SSS`）                                                                                   |
| **输出时区**              | 类型为 `string` 时用于格式化的时区                                                                                                                 |
| **点位 ID 处理**          | 应用于每个点位 ID 的可选 JS 表达式（变量：`value`）                                                                                                |
| **值处理**                | 应用于每个值的可选 JS 表达式（变量：`value`）                                                                                                      |
| **时间戳处理**            | 应用于每个已格式化时间戳的可选 JS 表达式（变量：`value`）                                                                                          |

##### 示例 {#example}

**输入（OPC UA 项目：temp1、pressure1）**

```json
[
  { "pointId": "plant/temp1", "timestamp": "2024-01-15T10:00:00.000Z", "data": { "value": "23.5" } },
  { "pointId": "plant/pressure1", "timestamp": "2024-01-15T10:00:00.000Z", "data": { "value": "102.1" } }
]
```

使用分隔符 `SEMI_COLON`、`pointIdProcess: value.split('/').pop()` 以及 `valueProcess: String(value).replace('.', ',')`：

:::tip 此处为何使用分号
`valueProcess` 将小数点转换为逗号（`23.5` → `23,5`），这在某些地区是常见做法。如果使用逗号作为**分隔符**，则会产生一个额外的、意料之外的列。使用 `;` 作为分隔符可以避免这种冲突。
:::

**输出 CSV**

```csv
Reference;Timestamp;Value
temp1;2024-01-15T10:00:00.000Z;23,5
pressure1;2024-01-15T10:00:00.000Z;102,1
```

---

#### JSON {#json}

一个透明的直通转换器，将时间值数组重新序列化为 JSON 文件。当北向连接器需要通用 JSON 文件而非内部时间值格式时使用（例如 Azure Blob 或 File Writer 等基于文件的北向连接器）。

此转换器**没有任何配置选项**。

##### 示例 {#example-1}

**输入** — 来自 OPC UA 或 Modbus 南向连接器的任意时间值数组。

**输出** — 完全相同的 JSON 内容，保存为 `.json` 文件。

---

#### MQTT 有效载荷 {#mqtt-payloads}

使用**点位 ID → 主题**映射表将每条读数映射为一条 MQTT 消息。点位 ID 没有匹配项的读数会被静默丢弃。有效载荷是一个 JSON 字符串，包含 `data` 字段并合并了 `timestamp`。

##### 设置 {#settings-1}

| 设置       | 描述                          |
| ---------- | ----------------------------- |
| **映射表** | `{ pointId, topic }` 对的列表 |

##### 示例 {#example-2}

映射表：`plant/temp1 → sensors/temperature`，`plant/pressure1 → sensors/pressure`

**输入**

```json
[
  { "pointId": "plant/temp1", "timestamp": "2024-01-15T10:00:00.000Z", "data": { "value": "23.5" } },
  { "pointId": "plant/pressure1", "timestamp": "2024-01-15T10:00:00.000Z", "data": { "value": "102.1" } },
  { "pointId": "plant/unknown", "timestamp": "2024-01-15T10:00:00.000Z", "data": { "value": "0" } }
]
```

**输出** — `plant/unknown` 被丢弃（无映射）

```json
[
  { "topic": "sensors/temperature", "payload": "{\"value\":\"23.5\",\"timestamp\":\"2024-01-15T10:00:00.000Z\"}" },
  { "topic": "sensors/pressure", "payload": "{\"value\":\"102.1\",\"timestamp\":\"2024-01-15T10:00:00.000Z\"}" }
]
```

---

#### Modbus 值 {#modbus-values}

使用**点位 ID → 地址**映射表将每条读数映射为一条 Modbus 写命令。值会被转换为相应的类型：线圈使用布尔值，保持寄存器使用整数。没有匹配项的读数会被丢弃。

##### 设置 {#settings-2}

| 设置       | 描述                                                                            |
| ---------- | ------------------------------------------------------------------------------- |
| **映射表** | `{ pointId, address, modbusType }` 的列表（`modbusType`：`coil` 或 `register`） |

##### 示例 {#example-3}

映射表：`plant/valve1 → 0x0010 (coil)`，`plant/speed → 0x0020 (register)`

**输入**

```json
[
  { "pointId": "plant/valve1", "timestamp": "2024-01-15T10:00:00.000Z", "data": { "value": "true" } },
  { "pointId": "plant/speed", "timestamp": "2024-01-15T10:00:00.000Z", "data": { "value": "1450" } }
]
```

**输出**

```json
[
  { "address": "0x0010", "value": true, "modbusType": "coil" },
  { "address": "0x0020", "value": 1450, "modbusType": "register" }
]
```

---

#### OIAnalytics（选择时间精度） {#oianalytics-select-time-precision}

为 OIAnalytics 北向连接器准备读数。时间戳可以被截断到所选精度以减少存储占用。只有 `pointId`、`timestamp` 和 `data.value` 字段会被转发——额外的质量字段会被剥离。为了节省带宽，读数以 OIAnalytics **紧凑格式**写入：三个大小相同的并行数组（`timestamps`、`values`、`references`），第 i 条读数由每个数组的第 i 个元素组成。

##### 设置 {#settings-3}

| 设置           | 描述                                                                                                                                     |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| **时间戳精度** | 时间戳精度：`ms`（不变）、`s`、`min` 或 `hr`                                                                                             |
| **引用处理**   | 应用于每个点位 ID 以构建 OIAnalytics 引用的可选 JavaScript 表达式，`value` 为点位 ID（例如 `value.replace('plant/', '').toUpperCase()`） |

##### 示例 — 精度 `s` {#example--precision-s}

**输入**

```json
[{ "pointId": "tag/temp1", "timestamp": "2024-01-15T10:00:00.523Z", "data": { "value": "23.5", "quality": "good" } }]
```

**输出** — 毫秒被清零，`quality` 被剥离

```json
{ "timestamps": ["2024-01-15T10:00:00.000Z"], "values": ["23.5"], "references": ["tag/temp1"] }
```

---

#### OPCUA 值 {#opcua-values}

使用**点位 ID → 节点 ID**映射表将每条读数映射为一条 OPC UA 写命令。值按原样转发。没有匹配项的读数会被丢弃。

##### 设置 {#settings-4}

| 设置       | 描述                           |
| ---------- | ------------------------------ |
| **映射表** | `{ pointId, nodeId }` 对的列表 |

##### 示例 {#example-4}

映射表：`plant/temp1 → ns=1;s=Temperature`，`plant/valve1 → ns=1;s=Valve1`

**输入**

```json
[
  { "pointId": "plant/temp1", "timestamp": "2024-01-15T10:00:00.000Z", "data": { "value": "23.5" } },
  { "pointId": "plant/valve1", "timestamp": "2024-01-15T10:00:00.000Z", "data": { "value": "true" } }
]
```

**输出**

```json
[
  { "nodeId": "ns=1;s=Temperature", "value": "23.5" },
  { "nodeId": "ns=1;s=Valve1", "value": "true" }
]
```

---

### 适用于基于文件和查询的南向连接器 {#for-file-and-query-based-south-connectors}

这些转换器处理由 REST、SFTP、FTP、Folder Scanner、ODBC 和 OLEDB 等连接器产生的文件或 JSON 有效载荷，以及通过 **OIBus API** 注入的数据。

---

#### 时间值（来自 CSV） {#time-values-from-csv}

解析 CSV 文件，并将每一行映射为一个 OIBus 时间值对象。转换器会根据配置的格式将原始时间戳字符串转换为 ISO-8601。

##### 设置 {#settings-5}

| 设置           | 描述                                                                         |
| -------------- | ---------------------------------------------------------------------------- |
| **包含表头**   | 第一行是否为表头行                                                           |
| **CSV 分隔符** | 列分隔符（`COMMA`、`SEMI_COLON`、`TAB` 等）                                  |
| **点位 ID 列** | 包含点位标识符的列名（表头模式）或从零开始的索引                             |
| **时间戳列**   | 包含时间戳的列名或索引                                                       |
| **值列**       | 包含值的列名或索引                                                           |
| **时间戳类型** | 原始时间戳的格式（`iso-string`、`unix-epoch`、`unix-epoch-ms`、`string`）    |
| **时区**       | 解析所用的时区（仅当类型为 `string` 时使用）                                 |
| **格式**       | 自定义日期时间模式（仅当类型为 `string` 时使用，例如 `yyyy-MM-dd HH:mm:ss`） |

##### 示例 {#example-5}

当 REST 南向连接器从 API 获取 CSV 导出文件，或 Folder Scanner 南向连接器拾取由其他系统放置的 CSV 文件时，此转换器非常有用。

**输入 CSV**（由 REST 项目获取）

```csv
SensorID,Timestamp,Reading
tag/temp1,2024-01-15T10:00:00.000Z,23.5
tag/temp1,2024-01-15T10:01:00.000Z,23.8
tag/pressure1,2024-01-15T10:00:00.000Z,102.1
```

**输出（时间值 JSON）**

```json
[
  { "pointId": "tag/temp1", "timestamp": "2024-01-15T10:00:00.000Z", "data": { "value": 23.5 } },
  { "pointId": "tag/temp1", "timestamp": "2024-01-15T10:01:00.000Z", "data": { "value": 23.8 } },
  { "pointId": "tag/pressure1", "timestamp": "2024-01-15T10:00:00.000Z", "data": { "value": 102.1 } }
]
```

这些时间值随后可以转发给任何接受结构化读数的北向连接器（OIAnalytics、MQTT、OPC UA……）。

---

#### MQTT 有效载荷（来自 CSV） {#mqtt-payloads-from-csv}

解析 CSV 文件，并将每一行转换为一条带有主题和有效载荷的 MQTT 消息。支持两种有效载荷模式：

- **简单** — 单个列成为有效载荷，并转换为配置的类型。
- **对象** — 多个列被组装成一个 JSON 对象有效载荷。

##### 设置 {#settings-6}

| 设置             | 描述                                                                  |
| ---------------- | --------------------------------------------------------------------- |
| **包含表头**     | 第一行是否为表头行                                                    |
| **CSV 分隔符**   | 列分隔符                                                              |
| **主题列**       | 包含 MQTT 主题的列名或索引                                            |
| **有效载荷类型** | `string`、`number`、`boolean`、`datetime` 或 `object`                 |
| **值列**         | 值所在的列（仅限简单有效载荷类型）                                    |
| **对象字段**     | `{ key, column, dataType }` 映射的列表（仅限对象有效载荷）            |
| **日期时间设置** | 输入/输出日期时间转换（当有效载荷类型或某个字段为 `datetime` 时适用） |

##### 示例 — 简单有效载荷 {#example--simple-payload}

**输入 CSV**

```csv
topic,value
plant/pump1/speed,1450
plant/pump1/running,true
```

**输出（MQTT 消息）**

```json
[
  { "topic": "plant/pump1/speed", "payload": "1450" },
  { "topic": "plant/pump1/running", "payload": "true" }
]
```

##### 示例 — 对象有效载荷 {#example--object-payload}

**输入 CSV**

```csv
topic,value,quality,timestamp
plant/sensor1,23.5,good,2024-01-15T10:00:00.000Z
plant/sensor2,48.0,good,2024-01-15T10:00:00.000Z
```

对象字段：`value → number`，`quality → string`，`timestamp → datetime`

**输出（MQTT 消息）**

```json
[
  { "topic": "plant/sensor1", "payload": "{\"value\":23.5,\"quality\":\"good\",\"timestamp\":\"2024-01-15T10:00:00.000Z\"}" },
  { "topic": "plant/sensor2", "payload": "{\"value\":48.0,\"quality\":\"good\",\"timestamp\":\"2024-01-15T10:00:00.000Z\"}" }
]
```

---

#### CSV（来自 JSON） {#csv-from-json}

解析 JSON 结构并写入 CSV 文件。**行迭代路径**（JSONPath 表达式）用于标识成为行的对象数组，每个已配置的**字段**将行内的某个路径映射到一个 CSV 列。字段支持日期时间转换、类型转换以及可选的按字段 JavaScript 后处理表达式。

##### 设置 {#settings-7}

| 设置                  | 描述                                                                                                                                               |
| --------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| **输出文件名**        | 输出文件名；支持 `@CurrentDate`（当前 UTC 时间戳），以及在内容来自南向历史查询时支持 `@QueryStartTime`/`@QueryEndTime`（查询的时间窗口，否则为空） |
| **编码**              | `UTF_8`、`UTF_8_BOM`、`LATIN_1` 或 `UTF_16_LE`                                                                                                     |
| **第一行作为表头**    | 是否包含列标题行                                                                                                                                   |
| **CSV 分隔符**        | 列分隔符                                                                                                                                           |
| **行分隔符**          | 行结束符（`LF`、`CRLF`、`CR`）                                                                                                                     |
| **引号字符**          | `DOUBLE_QUOTE`、`SINGLE_QUOTE` 或 `NONE`                                                                                                           |
| **转义字符**          | `DOUBLE_QUOTE` 或 `BACKSLASH`                                                                                                                      |
| **空值**              | 字段缺失或为 null 时写入的字符串（默认为空字符串）                                                                                                 |
| **行迭代器 JSONPath** | 指向行数组的 JSONPath（例如 `$.data[*]`）                                                                                                          |
| **字段映射**          | 每个 CSV 列对应一个条目（见下文）                                                                                                                  |

每个**字段**条目：

| 设置             | 描述                                                                 |
| ---------------- | -------------------------------------------------------------------- |
| **列名**         | CSV 中的表头标签                                                     |
| **JSONPath**     | 指向当前行内某个值的 JSONPath（例如 `$.timestamp`）                  |
| **数据类型**     | `string`、`number`、`boolean`、`datetime`、`array` 或 `object`       |
| **日期时间设置** | 数据类型为 `datetime` 时的输入和输出格式/时区/类型                   |
| **字段处理**     | 用于对提取值进行后处理的可选 JS 表达式（例如 `value.toUpperCase()`） |

##### 示例 {#example-6}

REST 南向连接器从 API 获取一份 JSON 报告。**CSV（来自 JSON）**转换器提取相关字段，并为 File Writer 北向连接器重新格式化。

**输入 JSON**（由 REST 项目返回）

```json
{
  "data": [
    { "ts": "2024-01-15T10:00:00.000Z", "tag": "temp1", "val": 23.5, "ok": true },
    { "ts": "2024-01-15T10:01:00.000Z", "tag": "temp1", "val": 23.8, "ok": true },
    { "ts": "2024-01-15T10:00:00.000Z", "tag": "pressure1", "val": 102.1, "ok": false }
  ]
}
```

配置：

- 行迭代器 JSONPath：`$.data[*]`
- 字段：`Timestamp`（`$.ts`，datetime）、`Tag`（`$.tag`，string）、`Value`（`$.val`，number）、`OK`（`$.ok`，boolean）

**输出 CSV**

```csv
Timestamp,Tag,Value,OK
2024-01-15T10:00:00.000Z,temp1,23.5,true
2024-01-15T10:01:00.000Z,temp1,23.8,true
2024-01-15T10:00:00.000Z,pressure1,102.1,false
```

:::info 嵌套的 JSON 字符串
**CSV（来自 JSON）**和下面的 **OIAnalytics（来自 JSON）**都可以自动解析被 JSON 字符串化的中间节点——例如某个 MQTT 南向连接器，其消息以原始字符串形式携带 JSON 有效载荷。如果某个路径片段解析到一个本身包含 JSON 的字符串，路径的其余部分会针对解析后的值继续解析。这同样适用于**行迭代路径**本身：它可以跨越该字符串边界，并仍然为每个嵌套匹配产生一行，因此一条包含多个读数的消息会被拆分为多行。完整示例请参见下面的 [OIAnalytics（来自 JSON）](#oianalytics-from-json)。
:::

#### OIAnalytics（来自 JSON） {#oianalytics-from-json}

通过 JSONPath 表达式从任意 JSON 结构中提取点位 ID、值和时间戳，并生成 OIAnalytics 紧凑格式的时间值（`timestamps`、`values` 和 `references` 三个并行数组）——与 [OIAnalytics（选择时间精度）](#oianalytics-select-time-precision)转换器的输出相同。**行迭代路径**标识有效载荷的哪一部分成为一行（一个时间值），每次匹配产生一行；点位 ID、值和时间戳路径随后相对于该行进行解析。

当南向连接器（通常是 MQTT、REST 或 Folder Scanner）提供的原始 JSON 与 OIBus 内部时间值结构不一致，而您又希望不编写自定义转换器就直接将其发送给 OIAnalytics 北向连接器时，就应该使用此转换器。

##### 设置 {#settings-8}

| 设置                  | 描述                                                                                                                                                                                                     |
| --------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **行迭代器 JSONPath** | 指向成为时间值的行数组的 JSONPath（例如 `$[*]`）。当直接遍历失败时，会自动解析被 JSON 字符串化的中间节点，因此该路径可以进入包含原始 JSON 文本的字段（例如 MQTT 有效载荷），并仍然为每个嵌套匹配产生一行 |
| **点位 ID JSONPath**  | 指向当前行内点位标识符的 JSONPath（例如 `$[*].id`）；通配符（`[*]`）会解析为当前行的索引                                                                                                                 |
| **值 JSONPath**       | 指向当前行内值的 JSONPath                                                                                                                                                                                |
| **时间戳 JSONPath**   | 指向当前行内原始时间戳的 JSONPath。如果无法解析，则回退为当前时间                                                                                                                                        |
| **引用处理**          | 应用于每个解析出的点位 ID 以构建 OIAnalytics 引用的可选 JavaScript 表达式，`value` 为点位 ID（例如 `value.replace('plant/', '').toUpperCase()`）                                                         |
| **时间戳输入类型**    | 原始时间戳的格式：`字符串`、`ISO 字符串`、`Unix 纪元（秒）` 或 `Unix 纪元（毫秒）`                                                                                                                       |
| **时区**              | 解析时使用的时区（仅当输入类型为 `字符串` 时使用）                                                                                                                                                       |
| **格式**              | 自定义日期时间模式（仅当输入类型为 `字符串` 时使用，例如 `yyyy-MM-dd HH:mm:ss`）                                                                                                                         |
| **区域设置**          | 解析月份/星期名称时使用的区域设置（仅当输入类型为 `字符串` 时使用）                                                                                                                                      |
| **时间戳精度**        | 结果 ISO 时间戳被截断到的输出精度：`毫秒`、`秒`、`分钟` 或 `小时`                                                                                                                                        |

##### 示例 — 带有 JSON 字符串化有效载荷的 MQTT 消息 {#example--mqtt-messages-with-a-json-stringified-payload}

某个 MQTT 南向连接器将每条消息交付为 `{ message, timestamp, item }`，其中 `message` 是**原始 MQTT 有效载荷字符串**。单条消息可以携带多个指标，因此行迭代路径使用了**两个**通配符——一个用于外层消息数组，另一个用于每条消息（被 JSON 字符串化的）有效载荷内部的指标——并为每个指标展开一行，无论某条消息携带的是一个读数还是多个读数。

**输入** — 第一条消息携带两个指标，第二条携带一个

```json
[
  {
    "message": "{\"metrics\":[{\"name\":\"PLANT.UNIT1.TANK3.LEVEL\",\"value\":52.2936,\"timestamp\":\"2026-07-16T08:50:18.808Z\"},{\"name\":\"PLANT.UNIT1.TANK3.TEMP\",\"value\":18.4,\"timestamp\":\"2026-07-16T08:50:19.001Z\"}]}"
  },
  { "message": "{\"metrics\":[{\"name\":\"PLANT.UNIT2.PUMP1.SPEED\",\"value\":1450,\"timestamp\":\"2026-07-16T08:50:20.500Z\"}]}" }
]
```

配置：

- 行迭代器 JSONPath：`$[*].message.metrics[*]`
- 点位 ID JSONPath：`$[*].message.metrics[*].name`
- 值 JSONPath：`$[*].message.metrics[*].value`
- 时间戳 JSONPath：`$[*].message.metrics[*].timestamp`
- 时间戳输入类型：`ISO 字符串`，时间戳精度：`毫秒`

第一个 `[*]` 遍历外层消息数组；第二个跨越 `message` 字符串边界（自动解析）以遍历其中的指标。两者会针对每一行一起解析，因此同一份配置既能处理单指标消息，也能处理多指标消息。

**输出** — 三行：两行来自第一条消息，一行来自第二条消息

```json
{
  "timestamps": ["2026-07-16T08:50:18.808Z", "2026-07-16T08:50:19.001Z", "2026-07-16T08:50:20.500Z"],
  "values": [52.2936, 18.4, 1450],
  "references": ["PLANT.UNIT1.TANK3.LEVEL", "PLANT.UNIT1.TANK3.TEMP", "PLANT.UNIT2.PUMP1.SPEED"]
}
```

### 适用于 SQL 数据库和 MongoDB 南向连接器 {#for-sql-database-and-mongodb-south-connectors}

MySQL、PostgreSQL、MSSQL、Oracle、SQLite 和 MongoDB 南向连接器不会自行序列化查询结果——每一行（或每一个文档）都会按数据库返回的原样，作为**记录列表**（record-list）内容（一个扁平行对象数组）发送到下游。将这些数据渲染为任何其他形式（包括 CSV）是转换器的工作。

#### CSV（来自记录列表） {#csv-from-record-list}

将行数组转换为 CSV 文件。行中出现的每个键都会自动成为一列——无需仅为了让某个字段出现在输出中而声明它。只有当某一列需要重命名、转换为特定类型、重新格式化（日期）或通过 JavaScript 表达式处理时，才需要声明字段（通过**字段映射**，使用与 [CSV（来自 JSON）](#csv-from-json)相同的按字段映射模型）。任何未被字段配置覆盖的列都会原样写出。

##### 设置 {#settings-9}

| 设置               | 描述                                                                      |
| ------------------ | ------------------------------------------------------------------------- |
| **文件名**         | 输出文件名模式（支持 `@CurrentDate`、`@QueryStartTime`、`@QueryEndTime`） |
| **编码**           | 输出字符编码（`UTF_8`、`UTF_8_BOM`、`LATIN_1`、`UTF_16_LE`）              |
| **第一行作为表头** | 是否写入包含列名的表头行                                                  |
| **压缩文件**       | 对输出文件进行 Gzip 压缩                                                  |
| **分隔符**         | 列分隔符（`COMMA`、`SEMI_COLON`、`TAB` 等）                               |
| **换行符**         | 行分隔符（`CRLF`、`LF`、`CR`）                                            |
| **引号字符**       | 用于给字段加引号的字符（`DOUBLE_QUOTE`、`SINGLE_QUOTE`、`NONE`）          |
| **转义字符**       | 用于转义带引号字段内引号字符的字符（`BACKSLASH`、`DOUBLE_QUOTE`）         |
| **空值**           | 当已配置字段为 `null` 或在行中缺失时写出的值                              |
| **字段映射**       | 按列覆盖的列表（重命名、类型转换、重新格式化或处理）——见下文              |

**字段映射**中的每个条目通过其在源行中的名称定位一列：

| 设置             | 描述                                                                            |
| ---------------- | ------------------------------------------------------------------------------- |
| **字段名**       | 要配置的列名，与源行中的某个键相匹配                                            |
| **列名**         | 该列在输出 CSV 中的表头。留空则保留原始字段名。                                 |
| **数据类型**     | 值的转换类型：`string`、`number`、`boolean`、`datetime`、`array` 或 `object`    |
| **字段处理**     | 类型转换之后应用的可选 JavaScript 表达式（例如 `value.toUpperCase()`）          |
| **日期时间设置** | 仅当数据类型为 `datetime` 时显示——输入/输出类型、时区、格式和区域设置（见下文） |

当**数据类型**为 `datetime` 时，**日期时间设置**描述如何解析原始值以及如何渲染它：

| 设置                           | 描述                                                                    |
| ------------------------------ | ----------------------------------------------------------------------- |
| **时间戳输入类型**             | 如何解析原始值（`string`、`iso-string`、`unix-epoch`、`unix-epoch-ms`） |
| **输入时区 / 格式 / 区域设置** | 当输入类型为 `string` 时用于解析原始值                                  |
| **时间戳输出类型**             | 如何渲染该值（`string`、`iso-string`、`unix-epoch`、`unix-epoch-ms`）   |
| **输出时区 / 格式 / 区域设置** | 当输出类型为 `string` 时用于渲染该值                                    |

##### 示例 {#example-7}

**输入**（来自某个 MySQL 项目的记录列表内容）

```json
[
  { "deviceId": "sensor-1", "readingTime": "2024-01-15T10:00:00.000Z", "value": 23.5 },
  { "deviceId": "sensor-1", "readingTime": "2024-01-15T10:01:00.000Z", "value": 23.8 }
]
```

仅配置一个字段（`readingTime`，数据类型 `datetime`，输入类型 `iso-string`，输出类型 `string`，格式为 `yyyy-MM-dd HH:mm:ss`，时区为 `Europe/Paris`）——`deviceId` 和 `value` 未配置，因此原样透传：

**输出 CSV**

```csv
deviceId,value,readingTime
sensor-1,23.5,2024-01-15 11:00:00
sensor-1,23.8,2024-01-15 11:01:00
```

## 自定义转换器 {#custom-transformers}

当没有标准转换器适合您的用例时，您可以使用 JavaScript 或 TypeScript 编写**自定义转换器**。自定义代码运行在一个安全的隔离沙箱中，无法访问主机文件系统、Node.js 模块或网络。

自定义转换器在**引擎 → 自定义转换器**页面中创建，随后可在任何北向连接器的转换器选择列表中使用。

### 转换函数 {#transform-function}

您的代码必须导出一个 `transform` 函数（或一个默认导出）。它接收四个参数，并且必须返回一个结果对象。

```typescript
/**
 * @param content  - The raw input data as a UTF-8 string (JSON, CSV, XML…)
 * @param source   - Metadata about the data source ({ type, dataSourceId, … })
 * @param filename - The original filename (or a generated ID if no file was involved)
 * @param options  - The transformer options as configured in the UI
 */
export function transform(
  content: string,
  source: object,
  filename: string,
  options: object
): { data: unknown; filename: string; numberOfElement?: number } {
  // …
}
```

| 返回字段          | 描述                                                             |
| ----------------- | ---------------------------------------------------------------- |
| `data`            | 写入缓存文件的内容（见下文）：字符串、原始二进制数据或任何其他值 |
| `filename`        | 输出存储在北向连接器缓存中时使用的文件名                         |
| `numberOfElement` | 可选的已处理记录数，会显示在日志和指标中                         |

转换器的输出会**原样写入缓存文件**，然后由北向连接器根据其内容类型读回。`data` 按其类型处理：

| 返回的 `data`                              | 存储为                    | 适用于                                             |
| ------------------------------------------ | ------------------------- | -------------------------------------------------- |
| **字符串**                                 | 原样存储该字符串（UTF-8） | 任意输出类型——由您控制确切的文本                   |
| **`Uint8Array` / `ArrayBuffer`**（二进制） | 原始字节，逐字节保留      | 仅限 **`any`** 输出类型（文件类北向连接器）        |
| 任何**其他值**（对象、数组、数字……）       | `JSON.stringify(data)`    | 读取 JSON 的类型化输出（`time-values`、`mqtt` 等） |

:::caution 使 `data` 与输出类型匹配；确保 `filename` 是字符串

- 对于**类型化**输出类型（`time-values`、`mqtt`、`oianalytics`、`modbus`、`opcua`），北向连接器会将缓存文件作为 **JSON** 读取——请返回字符串或对象/数组（OIBus 会将其序列化为 JSON）。在这里返回二进制数据将无法解析。
- **二进制**输出（`Uint8Array`/`ArrayBuffer`）用于 **`any`** 输出类型，此时文件类北向连接器（File Writer、S3、Azure、OIAnalytics 文件上传）会原样写入/上传这些字节。
- 非字符串、非二进制的值如果被 `JSON.stringify` 拒绝（循环结构、`BigInt`）或丢弃（函数），转换会以明确的错误失败，而不会被缓存。

`filename` **必须是字符串**——它会成为缓存文件名并被记录到连接器指标中，因此在此处返回对象或数组可能会破坏指标持久化。当您从输入数据（MQTT 主题、有效载荷字段等）推导文件名时，请将其转换为字符串并去除路径分隔符，例如 `` `mqtt_${String(topic).replace(/[\\/]/g, '_')}.json` ``。
:::

### 示例 {#examples}

#### 示例 1 — 将 JSON 数组重新格式化为 CSV（JavaScript） {#example-1--reformat-a-json-array-to-csv-javascript}

某个 REST 南向连接器返回一个 JSON 数组。此转换器将其转换为以分号分隔的 CSV 文件，供 File Writer 北向连接器使用。

**输入（`content`）**

```json
[
  { "ts": "2024-01-15T10:00:00.000Z", "id": "temp1", "val": 23.5 },
  { "ts": "2024-01-15T10:01:00.000Z", "id": "temp1", "val": 23.8 },
  { "ts": "2024-01-15T10:00:00.000Z", "id": "pressure1", "val": 102.1 }
]
```

**输出**

```csv
Timestamp;Tag;Value
2024-01-15T10:00:00.000Z;temp1;23.5
2024-01-15T10:01:00.000Z;temp1;23.8
2024-01-15T10:00:00.000Z;pressure1;102.1
```

**代码**

```javascript
export function transform(content, source, filename, options) {
  const Papa = require('papaparse');
  const rows = JSON.parse(content);

  const csv = Papa.unparse(
    rows.map(r => ({
      Timestamp: r.ts,
      Tag: r.id,
      Value: r.val
    })),
    { delimiter: ';', header: true }
  );

  return {
    data: csv,
    filename: `export_${filename.replace('.json', '.csv')}`,
    numberOfElement: rows.length
  };
}
```

#### 示例 2 — 过滤并丰富时间值（TypeScript） {#example-2--filter-and-enrich-time-values-typescript}

只保留高于配置阈值的读数，并为每条读数添加一个派生的 `status` 字段。

**输入（`content`）** — 标准时间值数组，`options.threshold = 20`

```json
[
  { "pointId": "plant/temp1", "timestamp": "2024-01-15T10:00:00.000Z", "data": { "value": "23.5" } },
  { "pointId": "plant/temp2", "timestamp": "2024-01-15T10:00:00.000Z", "data": { "value": "18.0" } },
  { "pointId": "plant/pressure1", "timestamp": "2024-01-15T10:00:00.000Z", "data": { "value": "102.1" } }

```

**输出** — `temp2` 被丢弃（18.0 ≤ 20），其余读数被标注

```json
  { "pointId": "plant/pressure1", "timestamp": "2024-01-15T10:00:00.000Z", "data": { "value": "102.1", "status": "HIGH" } }
]
```

**代码**

```typescript
type TimeValue = { pointId: string; timestamp: string; data: { value: string } };

export function transform(
  content: string,
  _source: object,
  _filename: string,
  options: { threshold: number }
): { data: string; filename: string; numberOfElement: number } {
  const values: Array<TimeValue> = JSON.parse(content);
  const threshold = options.threshold ?? 0;

  const filtered = values
    .filter(v => parseFloat(v.data.value) > threshold)
    .map(v => ({
      ...v,
      data: {
        ...v.data,
        status: parseFloat(v.data.value) > threshold * 2 ? 'HIGH' : 'NORMAL'
      }
    }));

  console.info(`Kept ${filtered.length} / ${values.length} values above threshold ${threshold}`);

  return {
    data: JSON.stringify(filtered),
    filename: `filtered_${Date.now()}.json`,
    numberOfElement: filtered.length
  };
}
```

```javascript
export function transform(content, _source, _filename, _options) {
  const { JSONPath } = require('jsonpath-plus');
  const data = JSON.parse(content);

  const timestamps = JSONPath({ path: '$.records[*].header.ts', json: data });
```

#### 示例 5 — 将 MQTT JSON 消息规范化为时间值（JavaScript） {#example-5--normalize-mqtt-json-messages-to-time-values-javascript}

**MQTT 南向连接器**将每批接收到的消息作为单个 `any-content` 有效载荷交付：一个由 `{ message, timestamp, item: { id, name, topic } }` 组成的 JSON 数组，其中 `message` 是**原始 MQTT 有效载荷字符串**。该原始有效载荷可以是任意形式——一个裸数字、一个 JSON 字符串、一个扁平对象，或一个读数数组（参见本地测试环境发布的 [JSON 主题](../../developer/local-test-stack.md#json-topics)）。此转换器将它们全部规范化为标准时间值数组，并使用主题作为点位 ID。

**输入（`content`）** — 来自不同主题的三条消息

```json
[
  {
    "message": "{\"value\":35.17,\"unit\":\"celsius\",\"timestamp\":\"2026-06-04T08:15:06.673+00:00\",\"quality\":\"good\"}",
    "timestamp": "2026-06-04T08:15:06.700Z",
    "item": { "id": "i1", "name": "flat", "topic": "workshop1/json/flat" }
  },
  {
    "message": "44.53",
    "timestamp": "2026-06-04T08:15:06.700Z",
    "item": { "id": "i2", "name": "number", "topic": "workshop2/json/number" }
  },
  {
    "message": "[{\"timestamp\":\"2026-06-04T08:15:06.673+00:00\",\"value\":34.95},{\"timestamp\":\"2026-06-04T08:15:08.673+00:00\",\"value\":35.48}]",
    "timestamp": "2026-06-04T08:15:06.700Z",
    "item": { "id": "i3", "name": "array", "topic": "workshop1/json/array" }
  }
]
```

**输出** — 每个读数一个时间值；数组消息产生两个

```json
[
  { "pointId": "workshop1/json/flat", "timestamp": "2026-06-04T08:15:06.673+00:00", "data": { "value": "35.17" } },
  { "pointId": "workshop2/json/number", "timestamp": "2026-06-04T08:15:06.700Z", "data": { "value": "44.53" } },
  { "pointId": "workshop1/json/array", "timestamp": "2026-06-04T08:15:06.673+00:00", "data": { "value": "34.95" } },
  { "pointId": "workshop1/json/array", "timestamp": "2026-06-04T08:15:08.673+00:00", "data": { "value": "35.48" } }
]
```

**代码**

```javascript
export function transform(content, _source, _filename, _options) {
  const messages = JSON.parse(content); // [{ message, timestamp, item: { topic } }, …]
  const timeValues = [];

  // Extract a scalar value from one reading, whatever its shape.
  const toValue = reading => {
    if (reading !== null && typeof reading === 'object') {
      // Flat reading ({ value, … }); fall back to the whole object for nested shapes.
      return reading.value ?? JSON.stringify(reading);
    }
    return reading; // number, string or boolean
  };

  for (const { message, timestamp, item } of messages) {
    // The raw MQTT payload may be JSON (object/array/number/string) or plain text.
    let parsed;
    try {
      parsed = JSON.parse(message);
    } catch {
      parsed = message; // non-JSON payload: keep the raw string
    }

    const readings = Array.isArray(parsed) ? parsed : [parsed];
    for (const reading of readings) {
      timeValues.push({
        pointId: item.topic,
        timestamp: (reading && reading.timestamp) || timestamp,
        data: { value: String(toValue(reading)) }
      });
    }
  }

  return {
    data: JSON.stringify(timeValues),
    // Always a plain string filename — never a payload object (see the caution above).
    filename: `mqtt_${Date.now()}.json`,
    numberOfElement: timeValues.length
  };
}
```

:::tip 在本地生成这些有效载荷
[本地测试环境](../../developer/local-test-stack.md#json-topics)会发布完全相同的 MQTT JSON 结构（`flat`、`nested`、`array`、`mixed`、`string`、`number`），因此您可以将 MQTT 南向连接器指向它，并针对每种情况测试自定义转换器。
:::
