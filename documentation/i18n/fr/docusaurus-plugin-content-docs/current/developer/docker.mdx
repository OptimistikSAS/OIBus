# Image Docker

OIBus fournit une image Docker officielle multi-architecture. Cette page décrit ce que contient l'image, d'où
elle provient, et comment construire une variante personnalisée à partir du même `Dockerfile` si nécessaire.

Pour les instructions de déploiement (volumes, réseau, variables d'environnement, indicateurs d'exécution
recommandés), consultez le [Guide d'installation Docker](../guide/installation/installation.mdx) du côté
de la documentation destinée aux utilisateurs.

## 🐳 Utiliser l'image officielle {#-use-the-official-image}

Pour un usage quotidien, **récupérez l'image pré-construite** plutôt que de construire la vôtre :

```bash
docker pull ghcr.io/optimistiksas/oibus:latest
```

Tags disponibles :

| Tag      | Source                                                                                                                                                          |
| -------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `latest` | Dernière version stable. Mise à jour automatiquement par [`new_release.yml`](./release.mdx) à chaque publication stable.                                        |
| `beta`   | Dernière pré-version. Utilisez-la pour valider les fonctionnalités à venir dans votre environnement de test.                                                     |
| `vX.Y.Z` | Épinglé à une version spécifique (par ex. `v3.8.8`). Recommandé en production afin que les mises à jour soient une action explicite de l'opérateur. {/* <!-- x-release-please-version --> */} |

L'image est construite pour `linux/amd64` et `linux/arm64` ; Docker choisit automatiquement la bonne variante
pour votre hôte lors du `pull`. Le flux de publication complet s'exécute via
[`.github/workflows/docker.yml`](https://github.com/OptimistikSAS/OIBus/blob/main/.github/workflows/docker.yml).

### `docker run` minimal {#minimal-docker-run}

```bash
docker run -d \
  --name oibus \
  -p 2223:2223 \
  -v /path/to/persistent-data:/app/OIBus/OIBusData \
  ghcr.io/optimistiksas/oibus:latest
```

- **Port `2223`** — l'interface web / l'API d'OIBus.
- **`/app/OIBus/OIBusData`** — l'emplacement où le conteneur stocke la configuration, le cache et les journaux.
  Montez un répertoire de l'hôte à cet endroit pour que les données survivent au remplacement du conteneur.

### Exemple Docker Compose {#docker-compose-example}

Le `docker-compose.yml` du dépôt inclut une définition de service prête à l'emploi que vous pouvez copier :

```yaml title="docker-compose.yml — oibus service"
services:
  oibus:
    image: ghcr.io/optimistiksas/oibus:latest
    container_name: oibus_runtime
    ports:
      - '2223:2223'
    volumes:
      - ./data-folder:/app/OIBus/OIBusData
    restart: unless-stopped
```

Le dépôt embarque également `nginx`, `opcua-server`, `mqtt-broker`, `postgres`, et d'autres simulateurs
derrière des profils Docker Compose — utile pour une pile complète de développement / test. Voir la section
[Évaluer les performances du produit](./index.md#benchmark-the-product) pour savoir ce qui est disponible.

## 🔧 Contenu de l'image {#-whats-in-the-image}

Le Dockerfile se trouve dans
[`build/docker/Dockerfile`](https://github.com/OptimistikSAS/OIBus/blob/main/build/docker/Dockerfile).
Il est volontairement minimal — il **télécharge** le binaire OIBus pré-construit depuis la release GitHub
correspondante plutôt que de compiler depuis les sources :

{/* x-release-please-start-version */}

```dockerfile title="build/docker/Dockerfile"
FROM ubuntu

ARG TARGETARCH                         # set automatically by `docker buildx` / `--platform`
ARG ARCH=${TARGETARCH/amd64/x64}        # GitHub release filenames use x64, not amd64
ARG VERSION="v3.8.8"                    # overridden by the release workflow

RUN apt update -y && apt install -y curl unzip

WORKDIR /app
RUN curl -LO https://github.com/OptimistikSAS/OIBus/releases/download/${VERSION}/oibus-linux_${ARCH}-${VERSION}.zip
RUN unzip -a oibus-linux_${ARCH}-${VERSION}.zip -d OIBus/
WORKDIR /app/OIBus
RUN mkdir OIBusData

EXPOSE 2223
CMD ["./oibus-launcher", "--config", "./OIBusData", "--ignoreIpFilters", "true", "--ignoreRemoteUpdate", "true"]
```

{/* x-release-please-end */}

Quelques points à connaître :

- **Binaire pré-construit** : l'image récupère `oibus-linux_<arch>-<version>.zip` depuis les
  [Releases](https://github.com/OptimistikSAS/OIBus/releases). Ce zip est lui-même produit par le pipeline de
  release — voir le [Processus de release](./release.mdx#-what-the-release-workflow-actually-produces).
- **`--ignoreIpFilters true`** est intégré dans le `CMD` par défaut : le conteneur suppose que vous isolez
  déjà l'accès au niveau réseau (réseau Docker, reverse proxy, etc.). Si vous voulez que le filtre IP intégré
  à l'application s'applique, surchargez `CMD` ou reconstruisez sans cette option.
- **`--ignoreRemoteUpdate true`** désactive le chemin de mise à jour automatique du launcher : dans un
  conteneur, les mises à jour se font en remplaçant l'image par un tag plus récent, pas en modifiant le
  conteneur en cours d'exécution.
- La valeur par défaut `VERSION="v3.8.8"` dans le Dockerfile n'est qu'un espace réservé pour les builds
  locaux. {/* <!-- x-release-please-version --> */}
  Le pipeline de release passe toujours `--build-arg VERSION=<tag>` pour la surcharger.

### Arguments de build {#build-arguments}

| Argument     | Comment il est défini                        | Objectif                                                                                                                   |
| ------------ | --------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| `TARGETARCH` | Défini par `docker buildx` à partir de `--platform` | Indique au Dockerfile quelle architecture récupérer. Ne le passez pas manuellement.                                        |
| `VERSION`    | `--build-arg VERSION=...` (par défaut `v3.8.8`) | Quelle release GitHub utiliser pour récupérer les binaires. Doit correspondre à un tag de release existant. {/* <!-- x-release-please-version --> */} |

## 🛠 Construire votre propre image {#-building-your-own-image}

Vous n'avez besoin de cela que si vous modifiez le Dockerfile lui-même, testez une release qui n'a pas
encore d'image officielle, ou construisez pour une architecture que la matrice ne fournit pas. Pour tout le
reste : utilisez [l'image officielle](#-use-the-official-image).

Toutes les commandes s'exécutent depuis le répertoire `build/docker/` du dépôt.

### Construire pour l'architecture de votre hôte {#build-for-your-host-architecture}

```bash
cd build/docker
docker build -t oibus-local .
```

`docker build` utilise par défaut l'architecture de votre hôte ; `TARGETARCH` est renseigné automatiquement.

### Construire pour une architecture spécifique {#build-for-a-specific-architecture}

Utilisez `--platform`, PAS `--build-arg` :

```bash
# Build the arm64 image (works on any host via Docker Desktop / buildx)
docker buildx build --platform linux/arm64 -t oibus-local:arm64 .

# Build the amd64 image
docker buildx build --platform linux/amd64 -t oibus-local:amd64 .
```

`docker buildx` renseigne `TARGETARCH` à partir de `--platform`, le Dockerfile réécrit `amd64 → x64` pour
correspondre au nommage des assets de release, et le bon zip est récupéré.

### Épingler une version spécifique d'OIBus {#pin-a-specific-oibus-version}

{/* x-release-please-start-version */}

```bash
docker build -t oibus-local --build-arg VERSION="v3.8.8" .
```

{/* x-release-please-end */}

`VERSION` doit référencer une release GitHub existante — le Dockerfile récupère
`oibus-linux_<arch>-<version>.zip` depuis cette release. Si l'asset n'existe pas (par exemple si vous
pointez vers un tag de pré-version), l'étape `curl` échoue. Pour utiliser une pré-version, consultez la
[page des Releases](https://github.com/OptimistikSAS/OIBus/releases) pour le nom exact de l'asset et le tag.

### Construire multi-architecture en une seule fois {#build-multi-arch-in-one-shot}

```bash
docker buildx build \
  --platform linux/amd64,linux/arm64 \
  --tag oibus-local:multiarch \
  --output type=image,push=false \
  .
```

Ceci reproduit ce que fait [`docker.yml`](https://github.com/OptimistikSAS/OIBus/blob/main/.github/workflows/docker.yml)
lors d'une release, à l'exception du push vers `ghcr.io`.
