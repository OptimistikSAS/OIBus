# Enregistrement OIAnalytics

L'enregistrement d'OIBus auprès d'OIAnalytics® est optionnel, mais il débloque la gestion centralisée à distance :
synchronisation de la configuration, exécution de commandes à distance, transfert des journaux et mises à jour
simplifiées — le tout sans nécessiter d'accès entrant vers la machine OIBus.

## Processus d'enregistrement {#registration-process}

<div style={{ textAlign: 'center' }}>
  ![Processus d'enregistrement OIAnalytics](@site/static/img/guide/installation/oianalytics-registration.svg)
</div>

**1 – 2 · Initier l'enregistrement**

- Naviguez vers la page **Moteur** dans OIBus.
- Cliquez sur le bouton **OIAnalytics**, remplissez le formulaire d'enregistrement, puis cliquez sur **Enregistrer**.

**3 · Valider dans OIAnalytics**

- Dans OIAnalytics, allez dans **Configuration → OIBus** et repérez l'enregistrement en attente.
- Saisissez le **code à 6 caractères** affiché sur l'écran d'enregistrement OIBus (également envoyé à l'adresse e-mail
  configurée dans OIAnalytics).
- Accordez les permissions requises — **l'accès API est obligatoire**.

**4 – 5 · Finalisation**

- OIBus interroge OIAnalytics pour confirmer que l'enregistrement a été approuvé.
- En cas de succès, OIBus envoie sa configuration complète (secrets exclus — voir
  [Gestion des secrets](#secret-management)) à OIAnalytics.
- Le transfert des journaux démarre s'il est activé dans
  [Paramètres du moteur → Paramètres de journalisation](../engine/engine-settings.mdx#logging-parameters).

**6 – 7 · Synchronisation continue**

- OIBus interroge périodiquement OIAnalytics pour de nouvelles commandes.
- Chaque commande est validée, exécutée puis acquittée.

| Paramètre                  | Description                                                    | Défaut |
| -------------------------- | -------------------------------------------------------------- | ------ |

## Utilisation de l'enregistrement dans les connecteurs {#using-the-registration-in-connectors}

Une fois enregistrés, le [connecteur South OIAnalytics](../south-connectors/oianalytics.mdx),
le [connecteur North OIAnalytics](../north-connectors/oianalytics.md), ainsi que les requêtes d'historique peuvent
réutiliser les paramètres d'enregistrement au lieu de nécessiter des paramètres de connexion séparés :

1. Ouvrez la configuration du connecteur ou de la requête d'historique.
2. Activez **Utiliser l'enregistrement OIAnalytics**.
3. Enregistrez — l'hôte, l'authentification et le proxy sont hérités automatiquement de l'enregistrement.

## Transfert des journaux {#log-forwarding}

Lorsque le niveau de journalisation OIAnalytics est activé dans
[Paramètres du moteur → Paramètres de journalisation](../engine/engine-settings.mdx#logging-parameters), OIBus
transfère ses journaux vers OIAnalytics. La fréquence de transfert et le niveau minimal de journalisation dépendent
de la configuration de journalisation — les journaux sont regroupés puis envoyés selon ces paramètres, et non
diffusés en continu. Les journaux transférés sont consultables et filtrables dans la page des journaux OIBus
d'OIAnalytics, et leur rétention suit les politiques d'OIAnalytics.

## Architecture des commandes {#command-architecture}

### Communication basée sur le pull {#pull-based-communication}

OIBus utilise un **modèle basé sur le pull** — il initie toute communication avec OIAnalytics. Cela signifie :

- Aucune connexion réseau entrante n'est requise vers la machine OIBus.
- Tout le trafic utilise du **HTTPS sortant sur le port 443**.
- OIBus interroge OIAnalytics à l'intervalle configuré et lit les commandes en attente dans le corps de la réponse.

:::info Exigences pare-feu
Seul le **HTTPS sortant (TCP 443)** vers le domaine OIAnalytics doit être autorisé. Aucune règle entrante n'est
requise.
:::

### Processus de mise à niveau de version {#version-upgrade-process}

Les mises à niveau sont téléchargées via OIAnalytics, de sorte que la machine OIBus n'a pas besoin d'un accès direct
à GitHub.

1. OIBus reçoit une commande de mise à niveau avec la version cible et télécharge le paquet de la version via
   OIAnalytics.
2. OIBus extrait le paquet dans un dossier temporaire `update`, puis s'arrête. À ce stade, OIBus lui-même a terminé
   — le reste se passe côté launcher une fois que celui-ci constate que le processus s'est arrêté.
3. Le **launcher OIBus** (`oibus-launcher`) détecte les nouveaux binaires dans le dossier `update` lors de son
   prochain cycle de démarrage. Avant de les substituer, il sauvegarde le binaire OIBus actuel ainsi que les
   sous-dossiers du dossier de données correspondant au motif de sauvegarde de la mise à niveau (le dossier `cache/`
   par défaut — OIAnalytics peut le remplacer), puis démarre la version mise à niveau d'OIBus.
4. Si la nouvelle version d'OIBus ne démarre pas (plantage, ou non-démarrage dans un délai d'environ 30 secondes),
   le launcher restaure automatiquement le binaire et les dossiers sauvegardés et redémarre la version précédente.

:::info Architecture du launcher
`oibus-launcher` exécute le processus principal `oibus` en tant que processus enfant. Chaque fois qu'`oibus` s'arrête
— que ce soit normalement ou de manière inattendue — le launcher vérifie le dossier de mise à jour : si de nouveaux
binaires sont présents, il effectue une mise à niveau (en sauvegardant d'abord, comme décrit ci-dessus), sinon il
redémarre simplement le binaire existant. Cela gère à la fois les mises à niveau et la récupération après plantage
automatiquement.
:::

:::danger Exigence d'espace disque
Avant d'installer la nouvelle version, le launcher sauvegarde le binaire actuel ainsi que les dossiers correspondant
au motif de sauvegarde (le dossier `cache/` par défaut) — assurez-vous de disposer de suffisamment d'espace disque
libre pour contenir une seconde copie de ce contenu. Vérifiez l'espace disponible et planifiez les mises à niveau
pendant les périodes de faible activité.
:::

## Architecture de sécurité {#security-architecture}

### Gestion des secrets {#secret-management}

OIBus utilise un **modèle zero-trust** pour garantir que les secrets (mots de passe, jetons, clés API) ne quittent
jamais la machine OIBus en clair :

- Lorsqu'OIBus envoie sa configuration à OIAnalytics, tous les secrets sont **retirés** avant la transmission. Seuls
  les paramètres non sensibles sont synchronisés.
- Lorsqu'un secret est saisi via OIAnalytics, il est **immédiatement chiffré avec la clé publique RSA d'OIBus**
  (RSA-OAEP) dans le navigateur avant d'être transmis. OIAnalytics ne voit jamais la valeur en clair.
- Sur la machine OIBus, les secrets sont stockés avec un chiffrement local. La clé privée ne quitte jamais l'instance
  OIBus.

Utilisez la commande **Régénérer les clés de chiffrement** pour faire pivoter la paire de clés RSA. Après régénération, les
secrets stockés dans OIAnalytics doivent être ressaisis puisque l'ancien texte chiffré ne peut plus être déchiffré.

:::info Détails cryptographiques
**Algorithme** : RSA-OAEP — une paire de clés unique est générée par instance OIBus lors de l'enregistrement.

Une fois sur la machine OIBus, les secrets sont stockés selon le
[modèle de sécurité OIBus](../advanced/oibus-security.md).
:::

## Dépannage {#troubleshooting}

| Problème                         | Ce qu'il faut vérifier                                              |
| -------------------------------- | -------------------------------------------------------------------- |
| L'enregistrement échoue          | Connectivité réseau et règles de pare-feu vers OIAnalytics.          |
| Code non accepté                 | Vérifiez que le code à 6 caractères correspond et n'a pas expiré.    |
| Les commandes ne s'exécutent pas | Permissions de commande accordées dans OIAnalytics.                  |
| La mise à niveau échoue          | Espace disque disponible et permissions d'écriture sur le dossier de données. |
| Erreurs de connexion             | Paramètres de proxy, confiance du certificat, et règles de pare-feu. |
