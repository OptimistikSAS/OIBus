# Transformateurs

Un **transformateur** se situe entre une source de données et un connecteur North. Il convertit les données entrantes
dans le format attendu par le connecteur North avant qu'elles ne soient placées dans le cache du connecteur. Au-delà de
la conversion de format, les transformateurs sont également le mécanisme de **filtrage** des données qu'un connecteur
North reçoit — voir [Filtrage des données](../north-connectors/common-settings.md#data-filtering) pour plus de
détails.

Les transformateurs sont configurés **sur le connecteur North**, dans la section **Transformateurs** de sa page de
paramètres.

---

## Configurer un transformateur {#configuring-a-transformer}

Cliquez sur **Ajouter** dans la section Transformateurs pour ouvrir la fenêtre de configuration. Trois champs guident
la configuration.

### 1 — Source {#1--source}

Choisissez d'où proviennent les données.

| Source                    | Description                                                                                                                                            |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Connecteur South**      | Données collectées par l'un des connecteurs South configurés                                                                                           |
| **API OIBus**             | Données envoyées à OIBus via l'API REST. Nécessite une chaîne d'identifiant de source de données (`dataSourceId`) pour identifier le système d'origine |
| **Consignes OIAnalytics** | Commandes d'écriture (write-back) envoyées depuis OIAnalytics                                                                                          |

### 2 — Portée des éléments (connecteurs South uniquement) {#2--item-scope-south-connectors-only}

Lorsque la source est un connecteur South, vous pouvez restreindre les éléments auxquels le transformateur s'applique.

| Portée                   | Description                                                                |
| ------------------------ | -------------------------------------------------------------------------- |
| **Tous les éléments**    | Chaque élément du connecteur South sélectionné passe par ce transformateur |
| **Par groupe**           | Seuls les éléments appartenant à un groupe spécifique sont traités         |
| **Éléments spécifiques** | Sélectionnez individuellement des éléments dans la liste de recherche      |

:::tip
Un même connecteur North peut avoir **plusieurs transformateurs** avec des sources et des portées différentes. Cela
vous permet d'appliquer des conversions différentes à différentes parties du même connecteur South — par exemple, un
transformateur pour un groupe de capteurs de température et un autre pour des débitmètres. Lorsqu'un lot entrant
mélange des éléments couverts par différents transformateurs, OIBus le divise automatiquement pour que chaque partie
soit traitée par le transformateur qui la cible réellement.
:::

Si plusieurs transformateurs peuvent correspondre au même élément (par exemple, l'un ciblant un groupe et l'autre
« Tous les éléments » du même connecteur South), OIBus résout cela avec cette priorité, du plus spécifique au moins
spécifique :

1. Un transformateur ciblant cet **élément spécifique**.
2. Un transformateur ciblant le **groupe** de l'élément.
3. Un transformateur ciblant **tous les éléments** du connecteur South (aucun groupe, aucun élément spécifique
   sélectionné) — le repli par défaut.

Le premier transformateur configuré qui correspond, dans cet ordre, est utilisé ; les égalités au sein d'un même
niveau sont départagées par la position du transformateur dans la liste.

### 3 — Transformateur {#3--transformer}

Une fois une source sélectionnée, la liste est automatiquement filtrée pour n'afficher que les transformateurs
compatibles. Les choix disponibles dépendent du type de connecteur South choisi :

| Type de connecteur South                                                                   | Transformateurs standard compatibles                                                                              |
| ------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------- |
| **OPC UA, OPC Classic, Modbus, ADS, S7, OSIsoft PI, OIAnalytics** (automate / historien)   | CSV, JSON, Charges utiles MQTT, Valeurs Modbus, OIAnalytics (sélectionner la précision temporelle), Valeurs OPCUA |
| **MQTT, REST, SFTP, FTP, Folder Scanner, ODBC, OLEDB** (fichier / requête)                 | Valeurs temporelles (depuis CSV), Charges utiles MQTT (depuis CSV), CSV (depuis JSON), OIAnalytics (depuis JSON)  |
| **MySQL, PostgreSQL, MSSQL, Oracle, SQLite, MongoDB** (requête, sortie en liste de lignes) | CSV (depuis liste d'enregistrements)                                                                              |
| **API OIBus**                                                                              | Valeurs temporelles (depuis CSV), Charges utiles MQTT (depuis CSV), CSV (depuis JSON), OIAnalytics (depuis JSON)  |
| **Consignes OIAnalytics**                                                                  | Charges utiles MQTT, Valeurs Modbus, Valeurs OPCUA                                                                |

Les transformateurs personnalisés apparaissent également dans cette liste et sont toujours nommés par l'utilisateur.
De plus, **Ignorer** et **Pas de transformation** (voir ci-dessous) sont disponibles pour chaque type de source.

Après avoir choisi un transformateur, son formulaire de paramètres apparaît directement dans la fenêtre.

---

## Transformateurs standard {#standard-transformers}

Les transformateurs standard sont intégrés et nécessitent seulement une configuration — aucun code.

---

### Ignorer et Pas de transformation {#ignore-and-no-transform}

Ces deux transformateurs sont disponibles pour **tous** les types de source, quel que soit le type de contenu, et ne
nécessitent aucune configuration.

| Transformateur            | Comportement                                                                                                                                                                                                                                       |
| ------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Ignorer**               | Rejette les données. Rien n'est mis en cache et rien n'est envoyé au connecteur North. Utile pour faire taire une partie de la sortie d'un connecteur South pour un North donné (via la portée élément/groupe) sans désactiver l'élément lui-même. |
| **Pas de transformation** | Met en cache les données exactement telles que reçues, sans aucune conversion. Utilisez-le lorsque le connecteur North accepte déjà le type de contenu natif du South.                                                                             |

---

### Pour les connecteurs South automate et historien {#for-plc-and-historian-south-connectors}

Ces transformateurs traitent les tableaux structurés de **time-values** produits par des connecteurs tels que OPC UA,
OPC Classic, Modbus, TwinCAT ADS, Siemens S7 et OSIsoft PI.

Chaque objet time-value a cette forme :

```json
{ "pointId": "plant/temp1", "timestamp": "2024-01-15T10:00:00.000Z", "data": { "value": "23.5" } }
```

---

#### CSV {#csv}

Convertit le tableau de time-values en fichier CSV. Chaque ligne correspond à une lecture. Les trois colonnes
(identifiant du point, horodatage, valeur) sont associées à des titres de colonnes configurables. Des expressions
JavaScript facultatives par colonne permettent de transformer les valeurs individuelles avant leur écriture.

##### Paramètres {#settings}

| Paramètre                                         | Description                                                                                                                                                                                                                          |
| ------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Nom du fichier**                                | Nom du fichier de sortie ; prend en charge `@CurrentDate` (horodatage UTC courant), et, pour un contenu provenant d'une requête d'historique South, `@QueryStartTime`/`@QueryEndTime` (la fenêtre temporelle interrogée, vide sinon) |
| **Encodage**                                      | `UTF_8`, `UTF_8_BOM`, `LATIN_1` ou `UTF_16_LE`                                                                                                                                                                                       |
| **Première ligne comme en-tête**                  | Inclure ou non la ligne d'en-tête des colonnes                                                                                                                                                                                       |
| **Délimiteur**                                    | Séparateur de colonnes                                                                                                                                                                                                               |
| **Saut de ligne**                                 | Fin de ligne (`LF`, `CRLF`, `CR`)                                                                                                                                                                                                    |
| **Caractère de citation**                         | `DOUBLE_QUOTE`, `SINGLE_QUOTE` ou `NONE`                                                                                                                                                                                             |
| **Caractère d'échappement**                       | `DOUBLE_QUOTE` ou `BACKSLASH`                                                                                                                                                                                                        |
| **Nom de colonne pour l'ID du point (Référence)** | Libellé d'en-tête de la colonne d'identifiant de point                                                                                                                                                                               |
| **Nom de colonne pour la valeur**                 | Libellé d'en-tête de la colonne de valeur                                                                                                                                                                                            |
| **Nom de colonne pour l'horodatage**              | Libellé d'en-tête de la colonne d'horodatage                                                                                                                                                                                         |
| **Type de sortie de l'horodatage**                | Format de sortie (`iso-string`, `unix-epoch`, `unix-epoch-ms`, `string`)                                                                                                                                                             |
| **Format de sortie de l'horodatage**              | Motif personnalisé lorsque le type est `string` (ex. `yyyy-MM-dd HH:mm:ss.SSS`)                                                                                                                                                      |
| **Fuseau horaire de sortie**                      | Fuseau horaire utilisé pour le formatage lorsque le type est `string`                                                                                                                                                                |
| **Traitement de l'ID du point**                   | Expression JS facultative appliquée à chaque identifiant de point (variable : `value`)                                                                                                                                               |
| **Traitement de la valeur**                       | Expression JS facultative appliquée à chaque valeur (variable : `value`)                                                                                                                                                             |
| **Traitement de l'horodatage**                    | Expression JS facultative appliquée à chaque horodatage formaté (variable : `value`)                                                                                                                                                 |

##### Exemple {#example}

**Entrée (éléments OPC UA : temp1, pressure1)**

```json
[
  { "pointId": "plant/temp1", "timestamp": "2024-01-15T10:00:00.000Z", "data": { "value": "23.5" } },
  { "pointId": "plant/pressure1", "timestamp": "2024-01-15T10:00:00.000Z", "data": { "value": "102.1" } }
]
```

Avec Délimiteur : `SEMI_COLON`, `pointIdProcess: value.split('/').pop()` et
`valueProcess: String(value).replace('.', ',')` :

:::tip Pourquoi un point-virgule ici
`valueProcess` transforme le point décimal en virgule (`23.5` → `23,5`), comme cela est courant dans certaines
régions. Avec une virgule comme **délimiteur**, cela créerait une colonne supplémentaire non désirée. Utiliser `;`
comme délimiteur évite ce conflit.
:::

**CSV en sortie**

```csv
Reference;Timestamp;Value
temp1;2024-01-15T10:00:00.000Z;23,5
pressure1;2024-01-15T10:00:00.000Z;102,1
```

---

#### JSON {#json}

Un passage direct transparent qui resérialise le tableau de time-values en fichier JSON. Utilisez-le lorsque le
connecteur North attend un fichier JSON générique plutôt que le format interne time-values (par exemple un North basé
sur des fichiers comme Azure Blob ou File Writer).

Ce transformateur n'a **aucune option de configuration**.

##### Exemple {#example-1}

**Entrée** — n'importe quel tableau de time-values provenant d'un connecteur South OPC UA ou Modbus.

**Sortie** — le contenu JSON identique, enregistré sous forme de fichier `.json`.

---

#### Charges utiles MQTT {#mqtt-payloads}

Associe chaque lecture à un message MQTT via une table de correspondance **identifiant de point → topic**. Les
lectures dont l'identifiant de point n'a pas de correspondance sont silencieusement rejetées. La charge utile est une
chaîne JSON contenant les champs `data` fusionnés avec le `timestamp`.

##### Paramètres {#settings-1}

| Paramètre            | Description                          |
| -------------------- | ------------------------------------ |
| **Table de mappage** | Liste de paires `{ pointId, topic }` |

##### Exemple {#example-2}

Table de mappage : `plant/temp1 → sensors/temperature`, `plant/pressure1 → sensors/pressure`

**Entrée**

```json
[
  { "pointId": "plant/temp1", "timestamp": "2024-01-15T10:00:00.000Z", "data": { "value": "23.5" } },
  { "pointId": "plant/pressure1", "timestamp": "2024-01-15T10:00:00.000Z", "data": { "value": "102.1" } },
  { "pointId": "plant/unknown", "timestamp": "2024-01-15T10:00:00.000Z", "data": { "value": "0" } }
]
```

**Sortie** — `plant/unknown` est rejeté (pas de correspondance)

```json
[
  { "topic": "sensors/temperature", "payload": "{\"value\":\"23.5\",\"timestamp\":\"2024-01-15T10:00:00.000Z\"}" },
  { "topic": "sensors/pressure", "payload": "{\"value\":\"102.1\",\"timestamp\":\"2024-01-15T10:00:00.000Z\"}" }
]
```

---

#### Valeurs Modbus {#modbus-values}

Associe chaque lecture à une commande d'écriture Modbus via une table de correspondance **identifiant de point →
adresse**. La valeur est convertie vers le type approprié : booléens pour les bobines (coils), entiers pour les
registres de maintien. Les lectures sans correspondance sont rejetées.

##### Paramètres {#settings-2}

| Paramètre            | Description                                                                                |
| -------------------- | ------------------------------------------------------------------------------------------ |
| **Table de mappage** | Liste de triplets `{ pointId, address, modbusType }` (`modbusType` : `coil` ou `register`) |

##### Exemple {#example-3}

Table de mappage : `plant/valve1 → 0x0010 (coil)`, `plant/speed → 0x0020 (register)`

**Entrée**

```json
[
  { "pointId": "plant/valve1", "timestamp": "2024-01-15T10:00:00.000Z", "data": { "value": "true" } },
  { "pointId": "plant/speed", "timestamp": "2024-01-15T10:00:00.000Z", "data": { "value": "1450" } }
]
```

**Sortie**

```json
[
  { "address": "0x0010", "value": true, "modbusType": "coil" },
  { "address": "0x0020", "value": 1450, "modbusType": "register" }
]
```

---

#### OIAnalytics (sélectionner la précision temporelle) {#oianalytics-select-time-precision}

Prépare les lectures pour le connecteur North OIAnalytics. Les horodatages peuvent être tronqués à une précision
choisie pour réduire l'empreinte de stockage. Seuls les champs `pointId`, `timestamp` et `data.value` sont
transmis — les champs de qualité supplémentaires sont supprimés. Pour économiser de la bande passante, les lectures
sont écrites au **format compact** d'OIAnalytics : trois tableaux parallèles de même taille (`timestamps`, `values`,
`references`), la i-ème lecture étant constituée du i-ème élément de chaque tableau.

##### Paramètres {#settings-3}

| Paramètre                      | Description                                                                                                                                                                                                |
| ------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Précision de l'horodatage**  | Précision de l'horodatage : `ms` (inchangé), `s`, `min` ou `hr`                                                                                                                                            |
| **Traitement de la référence** | Expression JavaScript facultative appliquée à chaque identifiant de point pour construire la référence OIAnalytics, `value` étant l'identifiant de point (ex. `value.replace('plant/', '').toUpperCase()`) |

##### Exemple — Précision `s` {#example--precision-s}

**Entrée**

```json
[{ "pointId": "tag/temp1", "timestamp": "2024-01-15T10:00:00.523Z", "data": { "value": "23.5", "quality": "good" } }]
```

**Sortie** — les millisecondes sont mises à zéro, `quality` est supprimé

```json
{ "timestamps": ["2024-01-15T10:00:00.000Z"], "values": ["23.5"], "references": ["tag/temp1"] }
```

---

#### Valeurs OPCUA {#opcua-values}

Associe chaque lecture à une commande d'écriture OPC UA via une table de correspondance **identifiant de point →
node ID**. La valeur est transmise telle quelle. Les lectures sans correspondance sont rejetées.

##### Paramètres {#settings-4}

| Paramètre            | Description                           |
| -------------------- | ------------------------------------- |
| **Table de mappage** | Liste de paires `{ pointId, nodeId }` |

##### Exemple {#example-4}

Table de mappage : `plant/temp1 → ns=1;s=Temperature`, `plant/valve1 → ns=1;s=Valve1`

**Entrée**

```json
[
  { "pointId": "plant/temp1", "timestamp": "2024-01-15T10:00:00.000Z", "data": { "value": "23.5" } },
  { "pointId": "plant/valve1", "timestamp": "2024-01-15T10:00:00.000Z", "data": { "value": "true" } }
]
```

**Sortie**

```json
[
  { "nodeId": "ns=1;s=Temperature", "value": "23.5" },
  { "nodeId": "ns=1;s=Valve1", "value": "true" }
]
```

---

### Pour les connecteurs South fichier et basés sur des requêtes {#for-file-and-query-based-south-connectors}

Ces transformateurs traitent des fichiers ou des charges utiles JSON produits par des connecteurs tels que REST, SFTP,
FTP, Folder Scanner, ODBC et OLEDB, ainsi que des données injectées via l'**API OIBus**.

---

#### Valeurs temporelles (depuis CSV) {#time-values-from-csv}

Analyse un fichier CSV et associe chaque ligne à un objet time-value OIBus. Le transformateur convertit la chaîne
d'horodatage brute en ISO-8601 selon le format configuré.

##### Paramètres {#settings-5}

| Paramètre                | Description                                                                                           |
| ------------------------ | ----------------------------------------------------------------------------------------------------- |
| **Comporte un en-tête**  | Indique si la première ligne est une ligne d'en-tête                                                  |
| **Délimiteur CSV**       | Séparateur de colonnes (`COMMA`, `SEMI_COLON`, `TAB`, etc.)                                           |
| **Colonne ID du point**  | Nom de colonne (mode en-tête) ou index (à partir de zéro) contenant l'identifiant de point            |
| **Colonne d'horodatage** | Nom ou index de la colonne contenant l'horodatage                                                     |
| **Colonne de valeur**    | Nom ou index de la colonne contenant la valeur                                                        |
| **Type d'horodatage**    | Format de l'horodatage brut (`iso-string`, `unix-epoch`, `unix-epoch-ms`, `string`)                   |
| **Fuseau horaire**       | Fuseau horaire utilisé pour l'analyse (uniquement lorsque le type est `string`)                       |
| **Format**               | Motif de date/heure personnalisé (uniquement lorsque le type est `string`, ex. `yyyy-MM-dd HH:mm:ss`) |

##### Exemple {#example-5}

Ce transformateur est utile lorsqu'un connecteur South REST récupère des exports CSV depuis une API, ou lorsqu'un
connecteur South Folder Scanner récupère des fichiers CSV déposés par un autre système.

**CSV en entrée** (récupéré par un élément REST)

```csv
SensorID,Timestamp,Reading
tag/temp1,2024-01-15T10:00:00.000Z,23.5
tag/temp1,2024-01-15T10:01:00.000Z,23.8
tag/pressure1,2024-01-15T10:00:00.000Z,102.1
```

**Sortie (JSON time-values)**

```json
[
  { "pointId": "tag/temp1", "timestamp": "2024-01-15T10:00:00.000Z", "data": { "value": 23.5 } },
  { "pointId": "tag/temp1", "timestamp": "2024-01-15T10:01:00.000Z", "data": { "value": 23.8 } },
  { "pointId": "tag/pressure1", "timestamp": "2024-01-15T10:00:00.000Z", "data": { "value": 102.1 } }
]
```

Ces time-values peuvent ensuite être transmises à tout connecteur North acceptant des lectures structurées
(OIAnalytics, MQTT, OPC UA…).

---

#### Charges utiles MQTT (depuis CSV) {#mqtt-payloads-from-csv}

Analyse un fichier CSV et convertit chaque ligne en un message MQTT avec un topic et une charge utile. Deux modes de
charge utile sont pris en charge :

- **Simple** — une seule colonne devient la charge utile, convertie vers le type configuré.
- **Objet** — plusieurs colonnes sont assemblées en une charge utile objet JSON.

##### Paramètres {#settings-6}

| Paramètre                    | Description                                                                                                    |
| ---------------------------- | -------------------------------------------------------------------------------------------------------------- |
| **Comporte un en-tête**      | Indique si la première ligne est une ligne d'en-tête                                                           |
| **Délimiteur CSV**           | Séparateur de colonnes                                                                                         |
| **Colonne du sujet**         | Nom ou index de la colonne contenant le topic MQTT                                                             |
| **Type de charge utile**     | `string`, `number`, `boolean`, `datetime` ou `object`                                                          |
| **Colonne de valeur**        | Colonne de la valeur (types de charge utile simples uniquement)                                                |
| **Champs objet**             | Liste de correspondances `{ key, column, dataType }` (charge utile objet uniquement)                           |
| **Paramètres de date/heure** | Conversion date/heure en entrée/sortie (s'applique lorsque le type de charge utile ou un champ est `datetime`) |

##### Exemple — Charge utile simple {#example--simple-payload}

**CSV en entrée**

```csv
topic,value
plant/pump1/speed,1450
plant/pump1/running,true
```

**Sortie (messages MQTT)**

```json
[
  { "topic": "plant/pump1/speed", "payload": "1450" },
  { "topic": "plant/pump1/running", "payload": "true" }
]
```

##### Exemple — Charge utile objet {#example--object-payload}

**CSV en entrée**

```csv
topic,value,quality,timestamp
plant/sensor1,23.5,good,2024-01-15T10:00:00.000Z
plant/sensor2,48.0,good,2024-01-15T10:00:00.000Z
```

Champs objet : `value → number`, `quality → string`, `timestamp → datetime`

**Sortie (messages MQTT)**

```json
[
  { "topic": "plant/sensor1", "payload": "{\"value\":23.5,\"quality\":\"good\",\"timestamp\":\"2024-01-15T10:00:00.000Z\"}" },
  { "topic": "plant/sensor2", "payload": "{\"value\":48.0,\"quality\":\"good\",\"timestamp\":\"2024-01-15T10:00:00.000Z\"}" }
]
```

#### CSV (depuis JSON) {#csv-from-json}

Analyse une structure JSON et écrit un fichier CSV. Un **chemin d'itération des lignes** (expression JSONPath)
identifie le tableau d'objets qui deviennent des lignes, et chaque **champ** configuré associe un chemin au sein de
chaque ligne à une colonne CSV. Les champs prennent en charge la conversion date/heure, la conversion de type et des
expressions JavaScript de post-traitement facultatives par champ.

##### Paramètres {#settings-7}

| Paramètre                            | Description                                                                                                                                                                                                                          |
| ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Nom du fichier de sortie**         | Nom du fichier de sortie ; prend en charge `@CurrentDate` (horodatage UTC courant), et, pour un contenu provenant d'une requête d'historique South, `@QueryStartTime`/`@QueryEndTime` (la fenêtre temporelle interrogée, vide sinon) |
| **Encodage**                         | `UTF_8`, `UTF_8_BOM`, `LATIN_1` ou `UTF_16_LE`                                                                                                                                                                                       |
| **Première ligne comme en-tête**     | Inclure ou non la ligne d'en-tête des colonnes                                                                                                                                                                                       |
| **Délimiteur CSV**                   | Séparateur de colonnes                                                                                                                                                                                                               |
| **Délimiteur de ligne**              | Fin de ligne (`LF`, `CRLF`, `CR`)                                                                                                                                                                                                    |
| **Caractère de citation**            | `DOUBLE_QUOTE`, `SINGLE_QUOTE` ou `NONE`                                                                                                                                                                                             |
| **Caractère d'échappement**          | `DOUBLE_QUOTE` ou `BACKSLASH`                                                                                                                                                                                                        |
| **Valeur nulle**                     | Chaîne écrite lorsqu'un champ est manquant ou null (chaîne vide par défaut)                                                                                                                                                          |
| **JSONPath de l'itérateur de ligne** | JSONPath pointant vers le tableau de lignes (ex. `$.data[*]`)                                                                                                                                                                        |
| **Mappage des champs**               | Une entrée par colonne CSV (voir ci-dessous)                                                                                                                                                                                         |

Chaque entrée de **champ** :

| Paramètre                    | Description                                                                                 |
| ---------------------------- | ------------------------------------------------------------------------------------------- |
| **Nom de colonne**           | Libellé d'en-tête dans le CSV                                                               |
| **JSONPath**                 | JSONPath vers la valeur au sein de la ligne courante (ex. `$.timestamp`)                    |
| **Type de données**          | `string`, `number`, `boolean`, `datetime`, `array` ou `object`                              |
| **Paramètres de date/heure** | Format/fuseau horaire/type en entrée et en sortie lorsque le type de données est `datetime` |
| **Traitement du champ**      | Expression JS facultative pour post-traiter la valeur extraite (ex. `value.toUpperCase()`)  |

##### Exemple {#example-6}

Un connecteur South REST récupère un rapport JSON depuis une API. Le transformateur **CSV (depuis JSON)** extrait les
champs pertinents et les reformate pour un connecteur North File Writer.

**JSON en entrée** (retourné par l'élément REST)

```json
{
  "data": [
    { "ts": "2024-01-15T10:00:00.000Z", "tag": "temp1", "val": 23.5, "ok": true },
    { "ts": "2024-01-15T10:01:00.000Z", "tag": "temp1", "val": 23.8, "ok": true },
    { "ts": "2024-01-15T10:00:00.000Z", "tag": "pressure1", "val": 102.1, "ok": false }
  ]
}
```

Configuration :

- JSONPath de l'itérateur de ligne : `$.data[*]`
- Champs : `Timestamp` (`$.ts`, datetime), `Tag` (`$.tag`, string), `Value` (`$.val`, number), `OK` (`$.ok`, boolean)

**CSV en sortie**

```csv
Timestamp,Tag,Value,OK
2024-01-15T10:00:00.000Z,temp1,23.5,true
2024-01-15T10:01:00.000Z,temp1,23.8,true
2024-01-15T10:00:00.000Z,pressure1,102.1,false
```

:::info Chaînes JSON imbriquées
Les transformateurs **CSV (depuis JSON)** et **OIAnalytics (depuis JSON)** (ci-dessous) peuvent tous deux analyser
automatiquement des nœuds intermédiaires sérialisés en JSON — par exemple un connecteur South MQTT dont les messages
transportent une charge utile JSON sous forme de chaîne brute. Si un segment de chemin résout vers une chaîne
contenant elle-même du JSON, le reste du chemin est résolu par rapport à la valeur analysée. Cela s'applique
également au **chemin d'itération des lignes** lui-même : il peut traverser cette frontière de chaîne et produire
quand même une ligne par correspondance imbriquée, de sorte qu'un seul message contenant plusieurs lectures se divise
en plusieurs lignes. Voir l'exemple [OIAnalytics (depuis JSON)](#oianalytics-from-json) ci-dessous pour un cas
détaillé.
:::

---

#### OIAnalytics (depuis JSON) {#oianalytics-from-json}

Extrait l'identifiant de point, la valeur et l'horodatage d'une structure JSON arbitraire via des expressions
JSONPath et produit des time-values au format compact d'OIAnalytics (tableaux parallèles `timestamps`, `values` et
`references`) — la même sortie que le transformateur
[OIAnalytics (sélectionner la précision temporelle)](#oianalytics-select-time-precision). Un **chemin d'itération des
lignes** identifie quelle partie de la charge utile devient une ligne (une time-value) par correspondance ; les
chemins d'identifiant de point, de valeur et d'horodatage sont ensuite résolus par rapport à cette ligne.

C'est le transformateur à privilégier lorsqu'un connecteur South (typiquement MQTT, REST ou Folder Scanner) fournit du
JSON brut qui ne correspond pas déjà à la forme interne time-values d'OIBus, et que vous souhaitez l'envoyer
directement à un connecteur North OIAnalytics sans écrire de transformateur personnalisé.

##### Paramètres {#settings-8}

| Paramètre                            | Description                                                                                                                                                                                                                                                                                                                                                  |
| ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **JSONPath de l'itérateur de ligne** | JSONPath vers le tableau de lignes qui deviennent des time-values (ex. `$[*]`). Analyse automatiquement un nœud intermédiaire sérialisé en JSON lorsque la traversée directe échoue, de sorte que le chemin peut entrer dans un champ contenant du texte JSON brut (ex. une charge utile MQTT) et produire quand même une ligne par correspondance imbriquée |
| **JSONPath de l'ID du point**        | JSONPath vers l'identifiant de point au sein de la ligne courante (ex. `$[*].id`) ; les jokers (`[*]`) sont résolus selon les indices de la ligne courante                                                                                                                                                                                                   |
| **JSONPath de la valeur**            | JSONPath vers la valeur au sein de la ligne courante                                                                                                                                                                                                                                                                                                         |
| **JSONPath de l'horodatage**         | JSONPath vers l'horodatage brut au sein de la ligne courante. Se rabat sur l'heure courante s'il ne peut pas être résolu                                                                                                                                                                                                                                     |
| **Traitement de la référence**       | Expression JavaScript facultative appliquée à chaque identifiant de point résolu pour construire la référence OIAnalytics, `value` étant l'identifiant de point (ex. `value.replace('plant/', '').toUpperCase()`)                                                                                                                                            |
| **Type d'entrée de l'horodatage**    | Format de l'horodatage brut : `Chaîne`, `Chaîne ISO`, `Époque Unix (s)` ou `Époque Unix (ms)`                                                                                                                                                                                                                                                                |
| **Fuseau horaire**                   | Fuseau horaire utilisé pour l'analyse (uniquement lorsque le type d'entrée est `Chaîne`)                                                                                                                                                                                                                                                                     |
| **Format**                           | Motif de date/heure personnalisé (uniquement lorsque le type d'entrée est `Chaîne`, ex. `yyyy-MM-dd HH:mm:ss`)                                                                                                                                                                                                                                               |
| **Paramètres régionaux**             | Paramètres régionaux utilisés pour analyser les noms de mois/jours (uniquement lorsque le type d'entrée est `Chaîne`)                                                                                                                                                                                                                                        |
| **Précision de l'horodatage**        | Précision à laquelle l'horodatage ISO résultant est tronqué : `Milliseconde`, `Seconde`, `Minute` ou `Heure`                                                                                                                                                                                                                                                 |

##### Exemple — Messages MQTT avec une charge utile sérialisée en JSON {#example--mqtt-messages-with-a-json-stringified-payload}

Un connecteur South MQTT fournit chaque message sous la forme `{ message, timestamp, item }`, où `message` est la
**chaîne de charge utile MQTT brute**. Un seul message peut transporter plusieurs métriques ; le chemin d'itération
des lignes utilise donc **deux** jokers — l'un pour le tableau externe de messages, l'autre pour les métriques à
l'intérieur de la charge utile (sérialisée en JSON) de chaque message — et produit une ligne par métrique, qu'un
message donné contienne une seule lecture ou plusieurs.

**Entrée** — le premier message transporte deux métriques, le second en transporte une

```json
[
  {
    "message": "{\"metrics\":[{\"name\":\"PLANT.UNIT1.TANK3.LEVEL\",\"value\":52.2936,\"timestamp\":\"2026-07-16T08:50:18.808Z\"},{\"name\":\"PLANT.UNIT1.TANK3.TEMP\",\"value\":18.4,\"timestamp\":\"2026-07-16T08:50:19.001Z\"}]}"
  },
  { "message": "{\"metrics\":[{\"name\":\"PLANT.UNIT2.PUMP1.SPEED\",\"value\":1450,\"timestamp\":\"2026-07-16T08:50:20.500Z\"}]}" }
]
```

Configuration :

- JSONPath de l'itérateur de ligne : `$[*].message.metrics[*]`
- JSONPath de l'ID du point : `$[*].message.metrics[*].name`
- JSONPath de la valeur : `$[*].message.metrics[*].value`
- JSONPath de l'horodatage : `$[*].message.metrics[*].timestamp`
- Type d'entrée de l'horodatage : `Chaîne ISO`, Précision de l'horodatage : `Milliseconde`

Le premier `[*]` parcourt le tableau externe de messages ; le second traverse la frontière de la chaîne `message`
(analysée automatiquement) pour parcourir les métriques qu'elle contient. Les deux sont résolus ensemble pour chaque
ligne, de sorte que la même configuration gère aussi bien un message à métrique unique qu'un message à métriques
multiples.

**Sortie** — trois lignes : deux issues du premier message, une du second

```json
{
  "timestamps": ["2026-07-16T08:50:18.808Z", "2026-07-16T08:50:19.001Z", "2026-07-16T08:50:20.500Z"],
  "values": [52.2936, 18.4, 1450],
  "references": ["PLANT.UNIT1.TANK3.LEVEL", "PLANT.UNIT1.TANK3.TEMP", "PLANT.UNIT2.PUMP1.SPEED"]
}
```

### Pour les connecteurs South de base de données SQL et MongoDB {#for-sql-database-and-mongodb-south-connectors}

Les connecteurs South MySQL, PostgreSQL, MSSQL, Oracle, SQLite et MongoDB ne sérialisent pas eux-mêmes le résultat
de leurs requêtes — chaque ligne (ou document) est envoyée en aval exactement telle que la base de données l'a
retournée, sous forme de contenu **record-list** (un tableau d'objets de ligne plats). Le rendu de ces données dans
toute autre forme, y compris le CSV, est le rôle du transformateur.

---

#### CSV (depuis liste d'enregistrements) {#csv-from-record-list}

Convertit un tableau de lignes en fichier CSV. Chaque clé présente dans une ligne devient automatiquement une
colonne — il n'est pas nécessaire de déclarer un champ simplement pour qu'il apparaisse dans la sortie. Déclarer un
champ (via **Mappage des champs**, en utilisant le même modèle de correspondance par champ que
[CSV (depuis JSON)](#csv-from-json)) n'est nécessaire que lorsqu'une colonne doit être renommée, convertie vers un
type spécifique, reformatée (dates) ou passée par une expression JavaScript. Toute colonne non couverte par une
configuration de champ est écrite telle quelle.

##### Paramètres {#settings-9}

| Paramètre                        | Description                                                                                                  |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| **Nom du fichier**               | Motif du nom de fichier de sortie (prend en charge `@CurrentDate`, `@QueryStartTime`, `@QueryEndTime`)       |
| **Encodage**                     | Encodage des caractères en sortie (`UTF_8`, `UTF_8_BOM`, `LATIN_1`, `UTF_16_LE`)                             |
| **Première ligne comme en-tête** | Écrire ou non une ligne d'en-tête avec les noms de colonnes                                                  |
| **Compresser le fichier**        | Compresser le fichier de sortie en Gzip                                                                      |
| **Délimiteur**                   | Séparateur de colonnes (`COMMA`, `SEMI_COLON`, `TAB`, etc.)                                                  |
| **Saut de ligne**                | Séparateur de lignes (`CRLF`, `LF`, `CR`)                                                                    |
| **Caractère de citation**        | Caractère utilisé pour encadrer les champs (`DOUBLE_QUOTE`, `SINGLE_QUOTE`, `NONE`)                          |
| **Caractère d'échappement**      | Caractère utilisé pour échapper un caractère de citation dans un champ encadré (`BACKSLASH`, `DOUBLE_QUOTE`) |
| **Valeur nulle**                 | Valeur écrite lorsqu'un champ configuré vaut `null` ou est absent de la ligne                                |
| **Mappage des champs**           | Une liste de surcharges par colonne (renommage, conversion, reformatage ou traitement) — voir ci-dessous     |

Chaque entrée de **Mappage des champs** cible une colonne, par son nom dans les lignes source :

| Paramètre                    | Description                                                                                                                                           |
| ---------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Nom du champ**             | Nom de la colonne à configurer, correspondant à une clé dans les lignes source                                                                        |
| **Nom de colonne**           | En-tête de cette colonne dans le CSV de sortie. Laisser vide pour conserver le nom de champ d'origine.                                                |
| **Type de données**          | Conversion à appliquer à la valeur : `string`, `number`, `boolean`, `datetime`, `array` ou `object`                                                   |
| **Traitement du champ**      | Expression JavaScript facultative appliquée après la conversion (ex. `value.toUpperCase()`)                                                           |
| **Paramètres de date/heure** | Affiché uniquement lorsque le type de données est `datetime` — type d'entrée/sortie, fuseau horaire, format et paramètres régionaux (voir ci-dessous) |

Lorsque le **Type de données** est `datetime`, les **Paramètres de date/heure** décrivent comment analyser la valeur
brute et comment la restituer :

| Paramètre                                                   | Description                                                                              |
| ----------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| **Type d'entrée de l'horodatage**                           | Comment analyser la valeur brute (`string`, `iso-string`, `unix-epoch`, `unix-epoch-ms`) |
| **Fuseau horaire / Format / Paramètres régionaux (entrée)** | Utilisés pour analyser la valeur brute lorsque son type d'entrée est `string`            |
| **Type de sortie de l'horodatage**                          | Comment restituer la valeur (`string`, `iso-string`, `unix-epoch`, `unix-epoch-ms`)      |
| **Fuseau horaire / Format / Paramètres régionaux (sortie)** | Utilisés pour restituer la valeur lorsque son type de sortie est `string`                |

##### Exemple {#example-7}

**Entrée** (contenu record-list provenant d'un élément MySQL)

```json
[
  { "deviceId": "sensor-1", "readingTime": "2024-01-15T10:00:00.000Z", "value": 23.5 },
  { "deviceId": "sensor-1", "readingTime": "2024-01-15T10:01:00.000Z", "value": 23.8 }
]
```

Avec un seul champ configuré (`readingTime`, type de données `datetime`, type d'entrée `iso-string`, type de sortie
`string` avec le format `yyyy-MM-dd HH:mm:ss` et le fuseau horaire `Europe/Paris`) — `deviceId` et `value` ne sont
pas configurés, ils passent donc inchangés :

**CSV en sortie**

```csv
deviceId,value,readingTime
sensor-1,23.5,2024-01-15 11:00:00
sensor-1,23.8,2024-01-15 11:01:00
```

### Pour les consignes OIAnalytics {#for-oianalytics-setpoints}

Ces transformateurs convertissent les commandes d'écriture (write-back) envoyées par OIAnalytics dans le format

Chaque commande de consigne a cette forme :

```json
{ "reference": "pump1/setSpeed", "value": 1200 }
```

#### Charges utiles MQTT {#mqtt-payloads-1}

Convertit les commandes de consigne en messages MQTT via une table de correspondance **référence → topic**. Les
commandes sans entrée correspondante sont rejetées. La charge utile est la valeur sérialisée en chaîne ; les valeurs
objet sont sérialisées en JSON.

##### Paramètres {#settings-10}

| Paramètre            | Description                            |
| -------------------- | -------------------------------------- |
| **Table de mappage** | Liste de paires `{ reference, topic }` |

##### Exemple {#example-8}

Table de mappage : `pump1/setSpeed → control/pump1/speed`

**Entrée (consignes)**

```json
[
  { "reference": "pump1/setSpeed", "value": 1200 },
  { "reference": "valve2/open", "value": true }
]
```

`valve2/open` est rejeté (pas de correspondance).

**Sortie (messages MQTT)**

```json
[{ "topic": "control/pump1/speed", "payload": "1200" }]
```

#### Valeurs Modbus {#modbus-values-1}

Convertit les commandes de consigne en commandes d'écriture Modbus. Les valeurs booléennes sont écrites dans des
bobines (coils) ; les valeurs numériques sont analysées comme des entiers et écrites dans des registres de maintien.

##### Paramètres {#settings-11}

| Paramètre            | Description                                                                                  |
| -------------------- | -------------------------------------------------------------------------------------------- |
| **Table de mappage** | Liste de triplets `{ reference, address, modbusType }` (`modbusType` : `coil` ou `register`) |

##### Exemple {#example-9}

Table de mappage : `valve1/open → 0x0010 (coil)`, `pump1/speed → 0x0020 (register)`

**Entrée (consignes)**

```json
[
  { "reference": "valve1/open", "value": true },
  { "reference": "pump1/speed", "value": 1450 }
]
```

**Sortie (commandes d'écriture Modbus)**

```json
[
  { "address": "0x0010", "value": true, "modbusType": "coil" },
  { "address": "0x0020", "value": 1450, "modbusType": "register" }
]
```

#### Valeurs OPCUA {#opcua-values-1}

Convertit les commandes de consigne en commandes d'écriture OPC UA via une table de correspondance **référence →
node ID**.

##### Paramètres {#settings-12}

| Paramètre            | Description                             |
| -------------------- | --------------------------------------- |
| **Table de mappage** | Liste de paires `{ reference, nodeId }` |

##### Exemple {#example-10}

Table de mappage : `pump1/speed → ns=1;s=PumpSpeed`

**Entrée (consignes)**

```json

```

**Sortie (commandes d'écriture OPC UA)**

```json
[{ "nodeId": "ns=1;s=PumpSpeed", "value": 1200 }]
```

## Transformateurs personnalisés {#custom-transformers}

Lorsqu'aucun transformateur standard ne convient à votre cas d'usage, vous pouvez écrire un **transformateur
personnalisé** en JavaScript ou TypeScript. Le code personnalisé s'exécute dans un bac à sable (sandbox) isolé et
sécurisé, sans accès au système de fichiers de l'hôte, aux modules Node.js, ni au réseau.

Les transformateurs personnalisés sont créés dans la page **Moteur → Transformateurs personnalisés** et sont ensuite
disponibles dans la liste de sélection des transformateurs de tout connecteur North.

### Fonction Transform {#transform-function}

Votre code doit exporter une fonction `transform` (ou un export par défaut). Elle reçoit quatre arguments et doit
retourner un objet résultat.

```typescript
/**
 * @param content  - The raw input data as a UTF-8 string (JSON, CSV, XML…)
 * @param source   - Metadata about the data source ({ type, dataSourceId, … })
 * @param filename - The original filename (or a generated ID if no file was involved)
 * @param options  - The transformer options as configured in the UI
 */
export function transform(
  content: string,
  source: object,
  filename: string,
  options: object
): { data: unknown; filename: string; numberOfElement?: number } {
  // …
}
```

| Champ de retour   | Description                                                                                                     |
| ----------------- | --------------------------------------------------------------------------------------------------------------- |
| `data`            | Le contenu écrit dans le fichier de cache (voir ci-dessous) : une chaîne, du binaire brut ou toute autre valeur |
| `filename`        | Le nom de fichier utilisé lorsque la sortie est stockée dans le cache du North                                  |
| `numberOfElement` | Nombre facultatif d'enregistrements traités, affiché dans les journaux et les métriques                         |

La sortie du transformateur est **écrite telle quelle dans le fichier de cache**, puis relue par le North selon son
type de contenu. `data` est traité selon sa nature :

| `data` retourné                                  | Stocké sous forme de            | À utiliser avec                                                  |
| ------------------------------------------------ | ------------------------------- | ---------------------------------------------------------------- |
| une **chaîne**                                   | la chaîne telle quelle (UTF-8)  | tout type de sortie — vous contrôlez le texte exact              |
| un **`Uint8Array` / `ArrayBuffer`** (binaire)    | les octets bruts, à l'identique | le type de sortie **`any`** uniquement (North fichier)           |
| toute **autre valeur** (objet, tableau, nombre…) | `JSON.stringify(data)`          | les sorties typées (`time-values`, `mqtt`, …) qui lisent du JSON |

:::caution Faire correspondre `data` au type de sortie ; garder `filename` sous forme de chaîne

- Pour les types de sortie **typés** (`time-values`, `mqtt`, `oianalytics`, `modbus`, `opcua`), le North lit le
  fichier de cache comme du **JSON** — retournez une chaîne ou un objet/tableau (qu'OIBus sérialise en JSON). Un
  retour binaire ne pourra pas être analysé.
- La sortie **binaire** (`Uint8Array`/`ArrayBuffer`) est destinée au type de sortie **`any`**, où les North fichier
  (File Writer, S3, Azure, envoi de fichiers OIAnalytics) écrivent/téléversent les octets sans modification.
- Une valeur ni chaîne ni binaire que `JSON.stringify` rejette (une structure circulaire, un `BigInt`) ou ignore (une
  fonction) fait échouer la transformation avec une erreur explicite au lieu d'être mise en cache.

`filename` **doit être une chaîne** — il devient le nom du fichier de cache et est enregistré dans les métriques du
connecteur ; retourner un objet ou un tableau à cet endroit peut donc casser la persistance des métriques. Lorsque
vous le dérivez des données d'entrée (un topic MQTT, un champ de la charge utile…), convertissez-le en chaîne et
retirez les séparateurs de chemin, ex. `` `mqtt_${String(topic).replace(/[\\/]/g, '_')}.json` ``.
:::

### Bibliothèques disponibles {#available-libraries}

Les bibliothèques suivantes sont préchargées dans le bac à sable et disponibles via `require` :

### Exemples {#examples}

#### Exemple 1 — Reformater un tableau JSON en CSV (JavaScript) {#example-1--reformat-a-json-array-to-csv-javascript}

Un connecteur South REST retourne un tableau JSON. Ce transformateur le convertit en fichier CSV délimité par des
points-virgules pour un connecteur North File Writer.

**Entrée (`content`)**

```json
[
  { "ts": "2024-01-15T10:00:00.000Z", "id": "temp1", "val": 23.5 },
  { "ts": "2024-01-15T10:01:00.000Z", "id": "temp1", "val": 23.8 },
  { "ts": "2024-01-15T10:00:00.000Z", "id": "pressure1", "val": 102.1 }
]
```

**Sortie**

```csv
Timestamp;Tag;Value
2024-01-15T10:00:00.000Z;temp1;23.5
2024-01-15T10:01:00.000Z;temp1;23.8
2024-01-15T10:00:00.000Z;pressure1;102.1
```

**Code**

```javascript
export function transform(content, source, filename, options) {
  const Papa = require('papaparse');
  const rows = JSON.parse(content);

  const csv = Papa.unparse(
    rows.map(r => ({
      Timestamp: r.ts,
      Tag: r.id,
      Value: r.val
    })),
    { delimiter: ';', header: true }
  );

  return {
    data: csv,
    filename: `export_${filename.replace('.json', '.csv')}`,
    numberOfElement: rows.length
  };
}
```

#### Exemple 2 — Filtrer et enrichir des time-values (TypeScript) {#example-2--filter-and-enrich-time-values-typescript}

Ne conserver que les lectures au-dessus d'un seuil configuré, et annoter chacune avec un champ `status` dérivé.

**Entrée (`content`)** — tableau time-values standard, `options.threshold = 20`

```json
[
  { "pointId": "plant/temp1", "timestamp": "2024-01-15T10:00:00.000Z", "data": { "value": "23.5" } },
  { "pointId": "plant/temp2", "timestamp": "2024-01-15T10:00:00.000Z", "data": { "value": "18.0" } },
  { "pointId": "plant/pressure1", "timestamp": "2024-01-15T10:00:00.000Z", "data": { "value": "102.1" } }
]
```

**Sortie** — `temp2` est rejeté (18.0 ≤ 20), les autres sont annotées

```json
[
  { "pointId": "plant/temp1", "timestamp": "2024-01-15T10:00:00.000Z", "data": { "value": "23.5", "status": "NORMAL" } },
  { "pointId": "plant/pressure1", "timestamp": "2024-01-15T10:00:00.000Z", "data": { "value": "102.1", "status": "HIGH" } }
]
```

**Code**

```typescript
type TimeValue = { pointId: string; timestamp: string; data: { value: string } };

export function transform(
  content: string,
  _source: object,
  _filename: string,
  options: { threshold: number }
): { data: string; filename: string; numberOfElement: number } {
  const values: Array<TimeValue> = JSON.parse(content);
  const threshold = options.threshold ?? 0;

  const filtered = values
    .filter(v => parseFloat(v.data.value) > threshold)
    .map(v => ({
      ...v,
      data: {
        ...v.data,
        status: parseFloat(v.data.value) > threshold * 2 ? 'HIGH' : 'NORMAL'
      }
    }));

  console.info(`Kept ${filtered.length} / ${values.length} values above threshold ${threshold}`);

  return {
    data: JSON.stringify(filtered),
    filename: `filtered_${Date.now()}.json`,
    numberOfElement: filtered.length
  };
}
```

#### Exemple 3 — Extraire des champs d'un JSON imbriqué avec JSONPath (JavaScript) {#example-3--extract-fields-from-a-nested-json-with-jsonpath-javascript}

**Entrée (`content`)**

```json
{
  "records": [
    { "header": { "ts": "2024-01-15T10:00:00.000Z" }, "tag": "plant/temp1", "measurements": { "val": 23.5 } },
    { "header": { "ts": "2024-01-15T10:01:00.000Z" }, "tag": "plant/temp1", "measurements": { "val": 23.8 } },
    { "header": { "ts": "2024-01-15T10:00:00.000Z" }, "tag": "plant/pressure1", "measurements": { "val": 102.1 } }
  ]
}
```

**Sortie**

```json
[
  { "pointId": "plant/temp1", "timestamp": "2024-01-15T10:00:00.000Z", "data": { "value": "23.5" } },
  { "pointId": "plant/temp1", "timestamp": "2024-01-15T10:01:00.000Z", "data": { "value": "23.8" } },
  { "pointId": "plant/pressure1", "timestamp": "2024-01-15T10:00:00.000Z", "data": { "value": "102.1" } }
]
```

**Code**

```javascript
export function transform(content, _source, _filename, _options) {
  const { JSONPath } = require('jsonpath-plus');
  const data = JSON.parse(content);

  const timestamps = JSONPath({ path: '$.records[*].header.ts', json: data });
  const tags = JSONPath({ path: '$.records[*].tag', json: data });
  const values = JSONPath({ path: '$.records[*].measurements.val', json: data });

  const timeValues = timestamps.map((ts, i) => ({
    pointId: tags[i],
    timestamp: ts,
    data: { value: String(values[i]) }
  }));

  return {
    data: JSON.stringify(timeValues),
    filename: `extracted_${Date.now()}.json`,
    numberOfElement: timeValues.length
  };
}
```

#### Exemple 4 — Conversion d'horodatage avec Luxon (JavaScript) {#example-4--timestamp-conversion-with-luxon-javascript}

Analyser des horodatages Unix epoch en millisecondes provenant d'une réponse d'API REST et les convertir en ISO-8601

**Entrée (`content`)**

```javascript
export function transform(content, _source, _filename, _options) {
```

#### Exemple 5 — Normaliser des messages JSON MQTT en time-values (JavaScript) {#example-5--normalize-mqtt-json-messages-to-time-values-javascript}

Un connecteur **South MQTT** fournit chaque lot de messages reçus sous la forme d'une unique charge utile
`any-content` : un tableau JSON de `{ message, timestamp, item: { id, name, topic } }`, où `message` est la **chaîne
de charge utile MQTT brute**. Cette charge utile brute peut avoir n'importe quelle forme — un simple nombre, une
chaîne JSON, un objet plat ou un tableau de lectures (voir les [topics JSON](../../developer/local-test-stack.md#json-topics)
publiés par la pile de test locale). Ce transformateur normalise tous ces cas en un tableau time-values standard, en
utilisant le topic comme identifiant de point.

**Entrée (`content`)** — trois messages provenant de topics différents

```json
[
  {
    "message": "{\"value\":35.17,\"unit\":\"celsius\",\"timestamp\":\"2026-06-04T08:15:06.673+00:00\",\"quality\":\"good\"}",
    "timestamp": "2026-06-04T08:15:06.700Z",
    "item": { "id": "i1", "name": "flat", "topic": "workshop1/json/flat" }
  },
  {
    "message": "44.53",
    "timestamp": "2026-06-04T08:15:06.700Z",
    "item": { "id": "i2", "name": "number", "topic": "workshop2/json/number" }
  },
  {
    "message": "[{\"timestamp\":\"2026-06-04T08:15:06.673+00:00\",\"value\":34.95},{\"timestamp\":\"2026-06-04T08:15:08.673+00:00\",\"value\":35.48}]",
    "timestamp": "2026-06-04T08:15:06.700Z",
    "item": { "id": "i3", "name": "array", "topic": "workshop1/json/array" }
  }
]
```

**Sortie** — une time-value par lecture ; le message tableau en produit deux

```json
[
  { "pointId": "workshop1/json/flat", "timestamp": "2026-06-04T08:15:06.673+00:00", "data": { "value": "35.17" } },
  { "pointId": "workshop2/json/number", "timestamp": "2026-06-04T08:15:06.700Z", "data": { "value": "44.53" } },
  { "pointId": "workshop1/json/array", "timestamp": "2026-06-04T08:15:06.673+00:00", "data": { "value": "34.95" } },
  { "pointId": "workshop1/json/array", "timestamp": "2026-06-04T08:15:08.673+00:00", "data": { "value": "35.48" } }
]
```

**Code**

```javascript
export function transform(content, _source, _filename, _options) {
  const messages = JSON.parse(content); // [{ message, timestamp, item: { topic } }, …]
  const timeValues = [];

  // Extract a scalar value from one reading, whatever its shape.
  const toValue = reading => {
    if (reading !== null && typeof reading === 'object') {
      // Flat reading ({ value, … }); fall back to the whole object for nested shapes.
      return reading.value ?? JSON.stringify(reading);
    }
    return reading; // number, string or boolean
  };

  for (const { message, timestamp, item } of messages) {
    // The raw MQTT payload may be JSON (object/array/number/string) or plain text.
    let parsed;
    try {
      parsed = JSON.parse(message);
    } catch {
      parsed = message; // non-JSON payload: keep the raw string
    }

    const readings = Array.isArray(parsed) ? parsed : [parsed];
    for (const reading of readings) {
      timeValues.push({
        pointId: item.topic,
        timestamp: (reading && reading.timestamp) || timestamp,
        data: { value: String(toValue(reading)) }
      });
    }
  }

  return {
    data: JSON.stringify(timeValues),
    // Always a plain string filename — never a payload object (see the caution above).
    filename: `mqtt_${Date.now()}.json`,
    numberOfElement: timeValues.length
  };
}
```

(`flat`, `nested`, `array`, `mixed`, `string`, `number`), afin que vous puissiez y connecter un connecteur South MQTT
et éprouver un transformateur personnalisé sur chaque cas.
