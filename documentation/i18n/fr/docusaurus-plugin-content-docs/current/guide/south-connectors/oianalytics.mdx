# OIAnalytics®

Interroger des données de séries temporelles depuis l'application SaaS [OIAnalytics®](https://optimistik.com/oianalytics/).

## Paramètres de connexion {#connection-settings}

### Configuration principale {#main-configuration}

| Paramètre                             | Description                                                                                                                                     | Exemple de valeur |
| ------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- | ----------------- |
| Utiliser l'enregistrement OIAnalytics | Utiliser les paramètres de connexion préconfigurés depuis l'[enregistrement OIAnalytics](../installation/oianalytics.mdx). Par défaut : activé. | Activé/Désactivé  |
| Délai d'expiration                    | Durée en secondes avant qu'un échec de connexion soit signalé. Par défaut : `30`.                                                               | `30`              |

## Paramètres de groupe {#group-settings}

Les éléments peuvent être organisés en groupes. Chaque groupe définit un mode de scan de collecte partagé et des
paramètres de limitation par défaut. Les éléments d'un même groupe sont toujours récupérés **un à la fois** en
séquence — le groupe fournit simplement des valeurs par défaut communes que les éléments individuels peuvent
surcharger.

| Paramètre        | Description                                                                                                                                                                                                                                  | Exemple de valeur               |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------- |
| **Nom**          | Libellé unique du groupe au sein de ce connecteur.                                                                                                                                                                                           | `Group A`                       |
| **Mode de scan** | Mode de scan utilisé pour collecter tous les éléments du groupe.                                                                                                                                                                             | `Every 1 min`                   |
| **Limitation**   | Valeurs de limitation par défaut (Intervalle de lecture maximal, Délai de lecture, Décalage de l'heure de début, Décalage de l'heure de fin, Stratégie de récupération, Si aucune donnée n'est trouvée) héritées par les éléments du groupe. | `3600, 200, 0, 0, oldest, keep` |

## Paramètres d'élément {#item-settings}

Chaque élément peut être configuré individuellement. Les éléments héritent de leur mode de scan et de leurs valeurs
de limitation par défaut du groupe, mais chaque paramètre peut être remplacé au niveau de l'élément en désactivant
**Synchroniser avec le groupe**.

| Paramètre            | Description                                     | Exemple de valeur              |
| -------------------- | ----------------------------------------------- | ------------------------------ |
| Point de terminaison | Point de terminaison API pour les requêtes HTTP | `/api/oianalytics/data/values` |

### Paramètres de requête {#query-parameters}

**Variables de requête** :

- `@StartTime` : Heure d'exécution initiale, mise à jour avec l'horodatage le plus récent des résultats
- `@EndTime` : Heure actuelle (`now()`) ou fin de sous-intervalle lorsque les requêtes sont fractionnées

:::info Fractionnement des requêtes
Les grands intervalles de temps sont automatiquement divisés en plus petits blocs à l'aide de :

- **Intervalle de lecture maximal** (voir les [paramètres de limitation](#throttling-settings))
- Réduit la charge sur le serveur et le réseau
- Améliore la résilience du flux de données
  :::

:::tip Clés répétées
Ajouter plusieurs fois la même clé l'envoie sous forme de tableau de valeurs dans la requête, au lieu d'écraser la
valeur précédente. Ceci est utile pour les points de terminaison acceptant plusieurs valeurs pour un même paramètre,
comme `data-reference` ci-dessous.
:::

#### Exemple : interroger des valeurs de données {#example-querying-data-values}

Pour récupérer les valeurs brutes de plusieurs références de données sur une fenêtre temporelle, configurez l'élément
avec le point de terminaison `/api/oianalytics/data/values` et les paramètres de requête suivants :

| Clé            | Valeur                          |
| -------------- | ------------------------------- |
| from           | `@StartTime`                    |
| to             | `@EndTime`                      |
| aggregation    | `RAW_VALUES`                    |
| data-reference | `CIP_Line_1_Acid_Tank_Level`    |
| data-reference | `CIP_Line_1_Caustic_Tank_Level` |

Comme `data-reference` est répété, il est envoyé sous la forme `data-reference=CIP_Line_1_Acid_Tank_Level&data-reference=CIP_Line_1_Caustic_Tank_Level`,
ce qui permet au point de terminaison de renvoyer les valeurs des deux niveaux de réservoir en une seule requête.

## Données envoyées {#sent-data}

Chaque élément envoie les valeurs qu'il récupère sous forme d'**enregistrements de points**, avec leur unité :

```json
{ "pointId": "CIP_Line_1_Acid_Tank_Level", "timestamp": "2024-01-15T10:00:00.000Z", "value": 52.3, "unit": "%" }
```

Pour les écrire dans un fichier CSV (ou JSON), associez le transformateur [Fichier](../engine/transformers.mdx#file-from-records)
au connecteur North ou à la requête d'historique : ses paramètres choisissent les colonnes, le format et le fuseau horaire
de l'horodatage, le délimiteur, le nom du fichier et la compression.

Avant la 3.10, les éléments écrivaient eux-mêmes des fichiers CSV (nom du fichier, délimiteur, compression, format et
fuseau horaire de l'horodatage) : la mise à jour déplace ces paramètres dans un transformateur Fichier pour chaque élément
dont les fichiers étaient envoyés tels quels. Les autres transformateurs lisant ses fichiers sont supprimés, les données
étant des listes d'enregistrements.
