# OSIsoft PI System™

Lire les valeurs enregistrées d'un PI Data Archive. OIBus y accède via le PI AF Client installé sur la machine OIBus,
grâce à un petit processus auxiliaire Windows livré avec OIBus : aucun OIBus Agent n'est nécessaire.

:::caution Prérequis système

- OIBus **doit** s'exécuter sous Windows x64 pour utiliser ce connecteur.
- **PI AF Client** **doit** être installé sur la machine OIBus. Il installe l'AF SDK que charge OIBus, et contient la
  table des serveurs connus : les PI Data Archives auxquels OIBus peut se connecter, et celui par défaut. OIBus ne livre
  aucun logiciel AVEVA : installez PI AF Client depuis AVEVA, dans le cadre de votre propre contrat avec AVEVA.
- Le compte Windows qui exécute OIBus **doit** avoir un accès en lecture au PI Data Archive, via un
  [mapping ou une confiance](#pi-af-client-configuration).
- AVEVA exige une licence **PI System Access (PSA)** pour tout programme non AVEVA qui lit des données PI, OIBus compris.

:::

## Paramètres de connexion {#connection-settings}

| Paramètre                        | Description                                                                                                                    | Exemple de valeur |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ | ----------------- |
| PI Data Archive                  | Nom du PI Data Archive dans la table des serveurs connus de PI AF Client. Vide : le PI Data Archive par défaut de cette table. | `MYPISERVER`      |
| Intervalle de nouvelle tentative | Temps en millisecondes à attendre avant de retenter la connexion. Par défaut : `10000`.                                        | `10000`           |

:::note Connexion
OIBus se connecte au démarrage du connecteur, et réessaie toutes les **Intervalle de nouvelle tentative** millisecondes
jusqu'à y parvenir. Quand la connexion au PI Data Archive est perdue, la lecture en cours échoue et la suivante se
reconnecte.
:::

## Paramètres de groupe {#group-settings}

Les éléments sont organisés en **groupes**. Chaque groupe définit un mode de scan partagé ainsi que les
paramètres de limitation par défaut pour la récupération des données historiques.

| Paramètre        | Description                                                   | Exemple de valeur |
| ---------------- | ------------------------------------------------------------- | ----------------- |
| **Nom**          | Libellé unique du groupe au sein de ce connecteur.            | `Group A`         |
| **Mode de scan** | Mode de scan de collecte appliqué à chaque élément du groupe. | `Every 1 min`     |

<ThrottlingSettings />

:::tip Remplacer la limitation par élément
Chaque élément peut remplacer les paramètres de limitation par défaut du groupe en désactivant l'option **Synchroniser avec le groupe**
dans le formulaire d'édition de l'élément.
:::

## Configuration des éléments {#item-configuration}

### Méthodes d'accès aux points {#point-access-methods}

| Paramètre  | Description                                                                                                                                                                                                                                                                     | Exemple de valeur                |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------- |
| Type       | Méthode d'accès : `PI point` (point unique par nom) ou `PI query` (plusieurs points via une expression de requête)                                                                                                                                                              | `PI point` ou `PI query`         |
| Point PI   | Nom exact du point (sans le nom du serveur, insensible à la casse). Utilisé lorsque le Type est `PI point`.                                                                                                                                                                     | `SINUSOID`                       |
| Requête PI | Requête sélectionnant plusieurs points (voir [PI Point Query Syntax](https://docs.aveva.com/bundle/af-sdk/page/html/pipoint-query-syntax-overview.htm)). Une requête sans nom d'attribut, comme `sinus*`, cherche dans les noms des points. Par défaut : `*` (tous les points). | `tag:=SINUS* AND pointsource:=R` |

:::info Noms de référence

- Pour `PI point` : le nom de l'élément sert de référence dans les charges utiles JSON
- Pour `PI query` : le nom PI est utilisé comme référence
  :::

:::info Valeurs
OIBus lit les valeurs enregistrées entre le début et la fin de chaque intervalle, bornes incluses. Chaque
enregistrement contient le point (`pointId`), l'horodatage (chaîne ISO 8601 UTC) et la valeur : un nombre pour les
points numériques, le nom de l'état pour les états digitaux (états système compris, comme `I/O Timeout`), une chaîne
sinon. L'intervalle suivant commence juste après la dernière valeur lue. Un point introuvable ou une requête en échec
est journalisé en avertissement, et les autres éléments sont tout de même lus.
:::

## Configuration de PI AF Client {#pi-af-client-configuration}

### Table des serveurs connus {#known-servers-table}

Ajoutez le PI Data Archive à la table des serveurs connus de PI AF Client sur la machine OIBus (par exemple avec PI
System Explorer, **File** → **Connections**), et définissez-le comme serveur par défaut si le paramètre
**PI Data Archive** du connecteur est laissé vide.

### Configuration de l'utilisateur {#user-configuration}

OIBus se connecte avec le compte Windows qui l'exécute (son compte de service), jamais avec une invite de connexion :

1. Créer un compte utilisateur de domaine (accessible depuis les deux machines)

- Si le domaine n'existe pas, créer des utilisateurs locaux identiques avec le même mot de passe

2. Exécuter le service OIBus avec cet utilisateur

### Configuration de la confiance (Trust) {#trust-configuration}

1. Ouvrir PI System Management Tools
2. Naviguer vers `Mapping & Trusts` → onglet `Trusts`
3. Créer une nouvelle confiance avec :

- L'adresse IP et le masque de sous-réseau de la machine OIBus
- Le domaine (le cas échéant)
- L'identité PI à laquelle se connecter

### Configuration du mapping {#mapping-configuration}

1. Dans PI System Management Tools
2. Naviguer vers `Mapping & Trusts` → onglet `Mappings`
3. Créer un nouveau mapping avec :

- L'utilisateur du service OIBus
- L'identité PI issue de la configuration de la confiance

:::tip Accès aux journaux
Consultez les journaux système dans PI System Management Tools :
`Operation` → `Messages Logs`
:::

## Composants tiers {#third-party-components}

Le processus auxiliaire Windows est le paquet [`@oibus/pi`](https://github.com/OptimistikSAS/oibus-pi), sous licence
Apache 2.0. Il ne contient aucun logiciel AVEVA : il charge, à l'exécution, l'AF SDK du PI AF Client installé sur la
machine OIBus, qui reste régi par votre propre contrat avec AVEVA.

AVEVA, PI System, PI AF et PI Data Archive sont des marques d'AVEVA Group Limited ou de ses filiales. OIBus n'est ni
affilié à AVEVA, ni parrainé ou approuvé par AVEVA ; ces noms ne servent qu'à décrire ce à quoi OIBus se connecte.
