# MongoDB

Interrogez des bases de données de documents MongoDB avec OIBus.

:::info Notes de compatibilité

- Prend en charge MongoDB 4.4 et versions ultérieures

:::

## Paramètres spécifiques {#specific-settings}

| Paramètre           | Description                                                                                                        | Exemple de valeur                                                                        |
| ------------------- | -------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| Connection string    | Chaîne de connexion MongoDB, incluant les hôtes, la base de données et tout paramètre de requête (ex. `replicaSet`, `authSource`). | `mongodb://host1:27017,host2:27017,host3:27017/database?replicaSet=rs0&authSource=admin` |
| Connection timeout   | Temps maximal en millisecondes pour établir la connexion. Par défaut : `10000`.                                      | `10000`                                                                                    |
| Username              | Nom d'utilisateur d'authentification. Optionnel.                                                                     | `db_user`                                                                                  |
| Password              | Mot de passe d'authentification.                                                                                     | `••••••••`                                                                                 |

:::tip Bonnes pratiques de sécurité

- Les identifiants ne sont jamais intégrés dans la chaîne de connexion. Lorsqu'un nom d'utilisateur est défini, OIBus s'authentifie en utilisant
  l'option native `auth` du pilote, envoyant le nom d'utilisateur et le mot de passe (déchiffré) séparément de la chaîne de
  connexion.
- Utilisez un utilisateur/rôle MongoDB en lecture seule limité aux collections dont OIBus a besoin.

:::

:::note Paramètres de la chaîne de connexion
OIBus ne dérive ni n'ajoute d'options de connexion en votre nom. Si votre déploiement nécessite `authSource`,
`replicaSet`, ou d'autres paramètres, incluez-les directement dans le champ **Connection string**.
:::

## Paramètres des éléments {#item-settings}

Chaque élément interroge une seule collection MongoDB et est planifié indépendamment via son propre mode de scrutation.

| Paramètre           | Description                                                                     | Exemple de valeur      |
| -------------------- | ------------------------------------------------------------------------------- | ------------------------ |
| **Collection**       | Nom de la collection MongoDB à interroger.                                       | `sensor_readings`        |
| **Query type**       | `find` pour un document de filtre, ou `aggregation` pour un pipeline.            | `find`, `aggregation`    |
| **Query**            | Document JSON de filtre (`find`) ou tableau JSON d'étapes de pipeline (`aggregation`). | voir ci-dessous     |
| **Sort**             | Spécification de tri JSON, appliquée uniquement aux requêtes `find`.             | `{ "timestamp": 1 }`     |
| **Track instant**    | Active le suivi incrémental de curseur via une expression JSONPath (voir ci-dessous). | activé/désactivé   |

### Query {#query}

Le champ **Query** est du texte JSON, analysé différemment selon le **Query type** :

- **find** : un unique objet JSON utilisé comme document de filtre passé à
  [`collection.find()`](https://www.mongodb.com/docs/manual/reference/method/db.collection.find/).

```json
{
  "timestamp": { "$gt": "@StartTime", "$lte": "@EndTime" }
}
```

- **aggregation** : un tableau JSON d'étapes de pipeline passé à
  [`collection.aggregate()`](https://www.mongodb.com/docs/manual/reference/method/db.collection.aggregate/).

```json
[
  { "$match": { "timestamp": { "$gt": "@StartTime", "$lte": "@EndTime" } } },
  { "$group": { "_id": "$deviceId", "value": { "$avg": "$value" }, "timestamp": { "$max": "$timestamp" } } }
]
```

:::note Les pipelines d'agrégation ne sont pas triés automatiquement
En mode `aggregation`, OIBus n'ajoute **pas** d'étape `$sort` construite à partir du paramètre **Sort** — **Sort**
s'applique uniquement aux requêtes `find`. Un tri ajouté après coup pourrait référencer un champ qui n'existe plus une fois qu'une étape `$group`
(ou une restructuration similaire) a été exécutée ; incluez donc votre propre étape `$sort` dans le pipeline si les résultats de la requête doivent
être triés.
:::

#### Emplacements `@StartTime` / `@EndTime` {#starttime--endtime-placeholders}

`@StartTime` et `@EndTime` fonctionnent de la même manière que dans les connecteurs SQL d'OIBus, avec une exigence
spécifique à MongoDB : ils doivent apparaître comme des **littéraux de chaîne JSON entre guillemets** dans le texte de la requête, ex.
`"@StartTime"`. Avant l'exécution de la requête, OIBus substitue chaque emplacement et le convertit en `Date` BSON
native — le littéral de chaîne dans la source JSON devient une valeur `Date` dans la requête réellement envoyée à MongoDB, et non
une chaîne.

| Paramètre    | Description                                                                                | Exemple de valeur          |
| -------------- | ---------------------------------------------------------------------------------------------- | ---------------------------- |
| `@StartTime`   | Initialisé à la première heure d'exécution, puis mis à jour avec la valeur de champ suivie la plus récente | `2024-01-15T10:00:00.000Z` |
| `@EndTime`     | Défini à l'heure actuelle (`now()`) ou à la fin du sous-intervalle lorsque les requêtes sont divisées | `2024-01-15T11:00:00.000Z` |

### Sort {#sort}

Le champ **Sort** est un objet JSON dans la forme native des spécifications de tri de MongoDB (ex. `{ "timestamp": 1 }`), passé
directement à `.sort()` en mode `find`. Les tris composés (plusieurs clés) sont pris en charge. Il n'a aucun effet en mode
`aggregation` et n'est pas lié au suivi incrémental de curseur — voir **Tracking instant** ci-dessous.

### Tracking instant {#tracking-instant}

L'activation de **Track instant** permet à OIBus de faire avancer son curseur entre les requêtes planifiées, de sorte que la requête suivante ne récupère
que les documents plus récents que le dernier déjà collecté. Lorsqu'il est désactivé (par défaut), OIBus ne suit aucun champ de
curseur — configurez le **Query** de l'élément pour limiter chaque exécution d'une autre manière.

| Paramètre                     | Description                                                                                                                                                          | Exemple de valeur                                                        |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| **Track instant**                  | Active le suivi de curseur.                                                                                                                                           | activé/désactivé                                                              |
| **JSON path**                      | Une expression [JSONPath](https://github.com/JSONPath-Plus/JSONPath) évaluée sur le tableau brut de documents retourné par la requête — atteint les champs imbriqués. | `$[*].timestamp`, `$[*].metadata.recordedAt`                                 |
| **Date time input → Type**         | Comment la valeur brute extraite doit être interprétée avant comparaison.                                                                                             | `Timestamp`, `ISO String`, `UNIX epoch (s)`, `UNIX epoch (ms)`, `String`     |

`$[*]` correspond à chaque document du lot ; le chemin qui le suit pointe vers le champ à comparer. Après chaque requête,
OIBus évalue le JSONPath, convertit chaque valeur correspondante en instant selon **Type**, et conserve
le maximum comme prochain `@StartTime`.

**Type** doit correspondre à la forme réelle du champ tel que retourné par le pilote MongoDB — le plus souvent `Timestamp`
pour un champ `Date` BSON natif. Choisissez `ISO String`, `UNIX epoch (s)`, ou `UNIX epoch (ms)` pour les champs stockés en
texte ou en nombres ; `String` nécessite en plus un **Format**, un **Timezone** et une **Locale** pour analyser une représentation
textuelle personnalisée.

### Aplatissement des documents {#document-flattening}

Les documents sont envoyés en aval comme contenu de liste d'enregistrements, une entrée par document, aplatie sur leurs
**champs de premier niveau uniquement** :

| Valeur source                                        | Valeur envoyée                       |
| -------------------------------------------------------- | --------------------------------------- |
| `Date`                                                     | Chaîne ISO 8601 (`.toISOString()`)      |
| `ObjectId`                                                 | Chaîne hexadécimale (`.toHexString()`)  |
| Chaîne, nombre, booléen                                    | Envoyé tel quel                         |
| `null` / `undefined`                                       | `null`                                  |
| Objet imbriqué, tableau, `Decimal128`, `Binary`, etc.      | Converti en chaîne JSON                 |

Pour rendre ces données au format CSV (ou dans un autre format), attachez un transformateur compatible — ex. **record-list-to-csv** —
au connecteur North ou à la requête historique. Consultez [Transformateurs](../engine/transformers.mdx) pour plus de détails.

:::tip Bonnes pratiques

1. Choisissez un champ suivi avec des valeurs cohérentes et croissantes (ex. un horodatage d'insertion).
2. Ajoutez un index sur le champ suivi, et sur tout champ utilisé dans **Sort**, pour la performance des requêtes.
3. Préférez le mode `find` pour les requêtes de plage temporelle simples ; utilisez le mode `aggregation` uniquement pour
   restructurer ou agréger des documents côté serveur, et incluez une étape `$sort` explicite si l'ordre importe.

:::
