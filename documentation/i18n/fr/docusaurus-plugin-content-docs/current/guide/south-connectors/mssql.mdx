# Microsoft SQL Server™

Se connecter et interroger des bases de données Microsoft SQL Server™ (MSSQL) avec OIBus.

Ce connecteur est couramment utilisé pour extraire des données de process et d'historisation à partir de plateformes industrielles qui stockent leurs données dans SQL Server, telles que **AVEVA™ Historian** (anciennement Wonderware® InSQL) ou **Inductive Automation Ignition®**.

:::info Notes de compatibilité

- Prend en charge SQL Server 2012 et versions ultérieures
- Nécessite l'activation du protocole TCP/IP sur SQL Server

:::

## Paramètres spécifiques {#specific-settings}

| Paramètre                                | Description                                                                      | Exemple de valeur |
| ---------------------------------------- | -------------------------------------------------------------------------------- | ----------------- |
| Hôte                                     | Adresse IP ou nom d'hôte de l'instance SQL Server.                               | `192.168.1.10`    |
| Port                                     | Numéro de port SQL Server. Par défaut : `1433`.                                  | `1433`            |
| Délai de connexion                       | Temps maximal en millisecondes pour établir la connexion. Par défaut : `5000`.   | `5000`            |
| Base de données                          | Nom de la base de données à laquelle se connecter.                               | `production`      |
| Utiliser le chiffrement                  | Activer le chiffrement des données entre OIBus et la base de données.            | Activé/Désactivé  |
| Faire confiance au certificat du serveur | Accepter les certificats auto-signés ou expirés. À utiliser avec prudence.       | Activé/Désactivé  |
| Nom d'utilisateur                        | Nom d'utilisateur d'authentification.                                            | `sa`              |
| Mot de passe                             | Mot de passe d'authentification.                                                 | `••••••••`        |
| Domaine                                  | Domaine Active Directory pour l'authentification de domaine (optionnel).         | `CORP`            |
| Délai de requête                         | Temps d'exécution maximal en millisecondes pour chaque requête SQL individuelle. | `15000`           |

### Bonnes pratiques de sécurité {#security-best-practices}

- **Permissions utilisateur** : Toujours utiliser un utilisateur de base de données en lecture seule
- **Validation du certificat** : Ne faire confiance aux certificats du serveur qu'en environnement de développement/test
- **Chiffrement** : Activer pour les données sensibles, les réseaux non fiables ou les exigences de conformité

### Considérations de performance {#performance-considerations}

**Optimisation des requêtes** :

- Utiliser des colonnes indexées dans les clauses WHERE
- Limiter les jeux de résultats (éviter `SELECT *`)
- Privilégier les requêtes paramétrées

**Gestion des ressources** :

- Le chiffrement ajoute une charge CPU
- Augmenter les délais d'expiration pour les requêtes longues
- Mettre en œuvre la pagination pour les grands jeux de résultats
- Réutiliser les connexions autant que possible

## Explorer les tables {#exploring-tables}

Cliquez sur **Explorer** pour parcourir les tables de la base de données (avec leur nombre de colonnes et, lorsque la
base le fournit, un nombre approximatif de lignes) et les colonnes de chaque table, avec leur type et, lorsque
disponibles, leur nullabilité, leur clé primaire et leur valeur par défaut. Cochez des tables ou des colonnes et
cliquez sur **Ajouter comme points** pour créer un élément par table, dont la requête lit les colonnes cochées et est
suivie sur une colonne date/heure choisie automatiquement — voir
[Tables SQL comme éléments](./common-settings.md#sql-tables-as-items).

Une [synchronisation des points](./common-settings.md#items-synchronisation) sur ce connecteur exécute une requête de
métadonnées et envoie ses lignes à OIAnalytics ; elle ne crée jamais d'éléments.

:::note Types de champ date/heure MSSQL
Les valeurs de **Type** suivantes sont disponibles pour le champ date/heure de l'instant suivi dans Microsoft SQL Server :

| Type             | Description                                                         |
| ---------------- | ------------------------------------------------------------------- |
| Chaîne           | Représentation textuelle analysée avec un format personnalisé       |
| Date             | Colonne SQL `DATE` (date uniquement, sans heure)                    |
| DateTime         | Colonne SQL `DATETIME`                                              |
| DateTime2        | Colonne SQL `DATETIME2` (précision supérieure)                      |
| DateTime Offset  | Colonne SQL `DATETIMEOFFSET` (inclut le décalage de fuseau horaire) |
| Small DateTime   | Colonne SQL `SMALLDATETIME` (précision à la minute)                 |
| Chaîne ISO       | Chaîne ISO 8601 (par ex. `2024-01-15T10:30:00.000Z`)                |
| Époque UNIX (s)  | Horodatage Unix en secondes                                         |
| Époque UNIX (ms) | Horodatage Unix en millisecondes                                    |

:::
